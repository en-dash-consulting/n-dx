description: "Move sourcevision's pure language facts into packages/lang-kit/src and make sourcevision import them from `@n-dx/lang-kit`. This is a move, not a rewrite: keep each module's code, comments and behaviour; only paths and the detection seam change. Analysis output must stay byte-identical.\n\nWhat moves (from packages/sourcevision/src/language/ unless noted), with git mv so history follows:\n- Language ids and configs: registry.ts, go.ts, java.ts, python.ts, swift.ts, typescript.ts, terraform.ts.\n- Build files: build-model.ts, go-build.ts, java-modules.ts, java-maven-build.ts, java-gradle-build.ts, gradle-script.ts, gradle-catalog.ts.\n- Small parsers: toml-lite.ts, xml-lite.ts, and analyzers/yaml-subset.ts (its one user, analyzers/sdlc-profile.ts, imports it from @n-dx/lang-kit).\n- Detection: the pure part of detect.ts.\n\nDetection seam. detect.ts today reads the `.n-dx.json` override and inventory config through `resolveLayout` from @n-dx/llm-client, and walks the tree with util/project-walk.ts (which imports PROJECT_DIRS from llm-client) to find Terraform files. lang-kit must never import @n-dx/llm-client or read config. So:\n- lang-kit gets the marker logic, the config map, `getLanguageConfig`, `languageConfigsFromIds`, `VALID_LANGUAGE_IDS`, `mergeLanguageConfigs`, the source-count tiebreak and the Swift/Python/Java markers. Its `detectLanguage` / `detectLanguages` take the override and the Terraform search as arguments (for example an options object with `override?: string` and `hasTerraformFile(otherConfigs): Promise<boolean>`), so lang-kit holds no walk and no config read.\n- sourcevision's src/language/detect.ts stays as the thin layer that reads config (`readConfigOverride`, `loadInventoryConfig`, `InventoryConfigOverride`), builds the walk-backed Terraform search from util/project-walk.ts, and calls lang-kit. Its exported names and signatures (`detectLanguage(rootDir)`, `detectLanguages(rootDir)`, `loadInventoryConfig`, and anything else sourcevision code or tests import from it) do not change. Call order and results must be identical, including when the Terraform walk runs and with which skip set.\n\nImporters to update: analyzers/go-imports.ts, analyzers/sdlc-profile.ts, analyzers/inventory.ts, analyzers/imports.ts, cli/sourcevision-core.ts, and the files that stay in src/language/ (database-engines.ts, go-pack.ts, go-resolver.ts, java-pack.ts, pack.ts, sql-pack.ts, java-resolver.ts, runner.ts and the SQL modules). Everything that stays imports the moved names from `@n-dx/lang-kit`; lang-kit's src/index.ts barrel exports them. Two moved modules must not export clashing names through the barrel; resolve a clash by renaming at the barrel, not by changing behaviour.\n\nConstraints:\n- sourcevision's public exports (src/public.ts and its d.ts) are unchanged: compare `packages/sourcevision/dist/public.d.ts` before and after.\n- Nothing in lang-kit imports an @n-dx/* package or a language SDK.\n- No golden, fixture or expected-output file is edited.\n- Unit tests of moved modules move to packages/lang-kit/tests with them (detect tests that exercise the config read stay in sourcevision). If a moved test reads sourcevision fixtures, move fixtures used only by it; keep shared fixtures where they are and leave that test in sourcevision importing from @n-dx/lang-kit.\n- Scripts under packages/sourcevision/scripts (go-corpus-report.mjs imports dist/language/go.js; check java-, sql-, tf- and database-corpus-report.mjs too) read moved modules from lang-kit's dist (packages/lang-kit/dist/index.js) instead of sourcevision's dist.\n- Out of scope: resolvers, runner.ts, pack.ts, *-pack.ts, queries, grammars, the SQL modules and database-engines.ts stay in sourcevision. analyzers/infrastructure.ts and IAC_KINDS are the next task.\n\nVerify byte-identity: the Java and Go corpus reports (`node packages/sourcevision/scripts/java-corpus-report.mjs`, `node packages/sourcevision/scripts/go-corpus-report.mjs`) give PR 10's numbers: Java 99.93% clean parse overall; Go on gitea 98.69% clean (3090/3131), import parity 3130/3131, edge parity pack 13077 edges / 11537 external pairs. Append the numbers to this task's log."
