description: "Found by /ndx-adversarial-review on commit 623ae90b. Severity: low. Verdict: out-of-scope for that change -- pre-existing, and only surfaced because 623ae90b added a fourth kill path on top of the same untested foundation. Filed here rather than under the change that revealed it.\n\nFAILURE SCENARIO\nEvery kill path in packages/core/child-lifecycle.js -- terminateChildProcess, terminateProcessGroup, terminateWindowsTree, terminateTreeByPid, and now killLateArrival -- is covered exclusively by tests/unit/child-lifecycle.test.js, which drives them through FakeChildProcess (an EventEmitter whose kill() pushes the signal onto an array) and through injected killGroup / spawnCliImpl stubs. The tests assert WHICH STRATEGY RAN, never that a process died. Replace any of these implementations with a function that records the right signal and does nothing, and the entire unit file still passes.\n\nThe project already knows this. Two completed items say so in their own resolution text:\n- e6f25b4d-ee6a-4dfe-89b6-a6520f3fd0e4 ('Implement single terminateTree contract...') has an acceptance criterion that explicitly REPLACES liveness verification with strategy-ran verification: 'verified by asserting the chosen strategy actually RAN ... NOT by the existing e2e grandchild-liveness assertions'.\n- deb8d3f6-17c9-4157-b4aa-1689e8249e6b ('Fix POSIX group-kill escalation gated on the direct child...') records: 'Real process.kill(-pgid) still unexercised from a Windows host; covered by injection here and the e2e cleanup suites on Linux CI.'\n\nBoth were reasonable scope decisions at the time. The accumulated result is that the module responsible for not leaking processes has no test that proves it does not leak one. The 31 orphans found on 2026-09-12 (task 099a0f2d) are what that costs.\n\nREACHABILITY\nNot a user-facing defect -- it is a hole in what the suite can prove. Reached by every ndx invocation that spawns a child, i.e. all of them, which is why it is worth closing even at low severity.\n\nSOLUTION OPTIONS\nA (recommended). One integration test file spawning real short-lived node children: assert terminateTree kills a detached child AND its grandchild on POSIX, and that terminateTreeByPid kills by pid alone. Skip the Windows-strategy cases on POSIX rather than stubbing them. ~60 lines, no production change. Note the caveat already recorded in 134db348: on Windows the host Job Object may reap the tree independently, so a liveness assertion there proves less than it appears to -- assert on POSIX and keep the injected strategy assertions for Windows.\nB. Extend the existing e2e CLI cleanup suites to assert grandchild liveness. Rejected by e6f25b4d already, and those suites are slower and racier than a direct integration test.\nC. Accept the gap permanently and document it in the module header so the next reviewer does not re-derive it. Cheapest, and honest, but it leaves the module's core promise unverified.\n\nRecommend A. Prerequisite for treating any future change to this module as covered."
