description: "Found while fixing a CI failure this skill's own earlier commit caused, 2026-10-14. Verdict: should-fix. Severity: medium — nothing misbehaves, but the documentation steered a reader away from the correct command and into a manual edit.\n\n**The contradiction, inside one file.** packages/rex/src/cli/commands/migrate-slugs.ts documents itself twice and the two disagree:\n\n- Module header (lines 3-18), correct: 'The rule is title-only, with a -{id6} suffix added only where siblings collide on a normalised title. It replaced a rule that suffixed every slug unconditionally.' And: 'Because it round-trips rather than encoding a rule of its own, this command follows the serializer automatically. Idempotent: a second run finds every entry already canonical and changes nothing.'\n- JSDoc above cmdMigrateSlugs (line 44), stale: 'Rename every folder-tree entry to its id-qualified slug.'\n- Command summary in constants.ts line 47, stale: 'Rename the PRD tree to id-qualified slugs (one-shot, idempotent).'\n\nThe summary is what 'rex --help' prints, so the stale description is the one a reader meets first.\n\n**What it cost, concretely.** tests/e2e/prd-slug-conformance.test.js failed on one path whose title had been edited without renaming its file. Its message says 'a rex build using a different slug rule wrote this tree. Run rex migrate-slugs on the default branch.' Checking that command's help found 'Rename the PRD tree to id-qualified slugs', which reads as a whole-tree migration to a different rule — the opposite of what was wanted for a single drifted path. The command was rejected as the wrong tool and the file was renamed by hand instead, with the parent's Children row edited to match. The outcome happened to be identical, because the serializer produces exactly that path; the reasoning was wrong, and a less careful fix could have left the tree inconsistent.\n\n**Reachability.** Any contributor who hits the conformance test, follows its advice to the command, and reads the command's own help. The test is in the root suite, so this is on the common path, not a corner.\n\n**The second half: the test's message.** It is unconditional — every failure is reported as 'a rex build using a different slug rule wrote this tree', which is one cause among several and not the likeliest. A single drifted path almost always means a title was edited without the file being renamed, which is what happened here. The message should distinguish the two: a handful of paths is item drift, the whole tree is a rule change.\n\n**Options.** (a) Recommended: correct both stale strings to describe the title-only rule, say in --help that the command re-serialises at the current rule, and split the test's message by mismatch count. Cost: a few lines. Risk: none. (b) Correct the strings only, leaving the test's message. Cheaper and leaves the misleading diagnosis in place, which is the half that actually misdirects. (c) Derive the command summary from the module's own documentation so the two cannot drift. Better, and more than this defect needs on its own.\n\n**Why a test, not just a fix.** The strings drifted because nothing ties them to behaviour. Criterion 4 asks for that tie; without it this recurs the next time the rule moves."
