description: "**Severity:** medium — **Verdict:** should-fix (captured from /ndx-adversarial-review of branch `chore/pr-329-review-followups`, 2026-08-25)\n\n**Failure scenario.** Two resolvers now answer the same ambiguity — is a lone positional a config key or a directory? — and they disagree.\n\n- `packages/core/resolve-existing-dir.js:49` (`resolveExistingDir`, used by `main()` before dispatch) accepts any positional that names an existing directory.\n- `packages/core/config.js:1648` (`isConfigKey`, used by `config`'s own handler) says a *known key* beats a directory, because a key is an exact match against a closed set while a directory name is arbitrary.\n\nWhen a positional is *both* — a known config key and a real directory — the pre-dispatch layer takes the directory and the handler takes the key. Measured directly against both modules in a fixture project containing `.rex/`, `.hench/`, `.sourcevision/` and sibling directories named `hench/`, `rex.project/`, `llm/`:\n\n```\nndx config hench             -> pre-dispatch dir = \"hench\"        stale-check missing: [.sourcevision, .rex, .hench]\nndx config rex.project       -> pre-dispatch dir = \"rex.project\"  stale-check missing: [.sourcevision, .rex, .hench]\nndx config llm               -> pre-dispatch dir = \"llm\"          stale-check missing: [.sourcevision, .rex, .hench]\nndx config llm.vendor claude -> pre-dispatch dir = <cwd>          stale-check missing: []\n```\n\nTwo consequences, both quiet:\n1. `loadProjectConfig(\"hench\")` (`packages/core/cli.js:2766`) reads `.n-dx.json` from `./hench`, which does not exist, and `.catch(() => ({}))` swallows it. `resolveCommandTimeout` and `experimentalEnv` therefore see `{}` — command timeouts and BETA experimental flags silently stop applying.\n2. `checkProjectStaleness(\"hench\")` reports all three tool directories missing and prints \"Project setup incomplete\" for a fully initialized project.\n\n**Observed.** During a `tests/e2e/cli-config.test.js` run on this branch, the spawned CLI's stderr carried `Project setup incomplete — .sourcevision, .rex, .hench not found` for `ndx config rex.project`, in a fixture where all three directories exist at the root.\n\n**In scope, with a caveat worth stating.** The *symptom* predates this branch: the removed `resolveProjectDirForPreDispatch` used the identical `existsSync` tiebreaker and behaved the same way. What is new is the **disagreement**. Commit `1e231b25` on this branch introduced `isConfigKey` as the authoritative tiebreaker for exactly this ambiguity and did not propagate it, while `resolve-existing-dir.js`'s docblock presents the new module as the fix for this class of misfire — it fixes the case where the key is *not* a directory and leaves the case where it is.\n\n**Relation to prior work.** Task `fe7084dc` (\"resolveDir treats a tool subcommand as the project directory\") is **completed**, and its chosen fix is this module: \"main() now uses the new resolveExistingDir, which accepts a positional only when it names a real directory.\" Its own solution #2 anticipated the shape of the residue — \"changes behavior for a genuinely intended directory argument that does not yet exist\" — but not this one, where the argument is a real directory that was never meant to be one. Its acceptance criterion \"`.n-dx.json` command timeouts and experimental flags apply to tool-delegation commands invoked without an explicit directory\" holds for tool delegation and fails for `ndx config <key>`. Filed as a new task rather than an edit to completed work because the fix touches a different decision point; whether `fe7084dc` should move off `completed` is a separate call this review did not take.\n\n**Reachability.** `ndx config hench`, `ndx config rex`, `ndx config llm`, `ndx config web` — any bare-section form — in any project that happens to contain a directory of that name. A repo with a top-level `hench/` or `llm/` folder is not exotic.\n\n**Possible solutions.**\n1. *Recommended.* Teach the pre-dispatch path about config keys: when `command === \"config\"`, skip a positional that `isConfigKey` claims. Requires exporting `isConfigKey` from `config.js`, which `cli.js` already imports (it is the documented spawn-exempt module). Cost: roughly 10 lines. Risk: low — `./hench` and `../hench` stay unambiguous by the reasoning `isConfigKey` already documents (their first dot is at index 0, so the root segment is empty and never matches a section).\n2. Have `main()` skip the pre-dispatch resolve entirely for `config` and always use cwd. Removes the coupling between the two modules, but is wrong for the `ndx config <key> <value> <dir>` form where a trailing directory is real — it would need a carve-out for the 2- and 3-positional shapes.\n3. Accept it and document it. The blast radius is a silently-ignored timeout override plus a spurious notice — annoying rather than corrupting. Not recommended: the whole point of `isConfigKey` was that \"existence on disk alone is the wrong tiebreaker\", and leaving one layer using the wrong tiebreaker invites the next person to re-derive the same bug."
