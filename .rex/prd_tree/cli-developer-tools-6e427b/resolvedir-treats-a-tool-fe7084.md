description: "**Severity:** medium — **Verdict:** should-fix\n\n**Failure scenario.** `resolveDir` (`packages/core/cli.js:462-467`) scans the argument list **backwards** and returns the first token that does not start with `-`. For a tool-delegation invocation with no explicit directory and only flags after the subcommand — e.g. `ndx hench record --task=X --status=completed --title=\"…\" --summary=\"…\"`, or `ndx rex status --format=json` — every trailing argument is a flag, so the scan walks back to the **subcommand name** and returns `\"record\"` / `\"status\"` as the project directory.\n\nTwo consequences at `packages/core/cli.js:2700-2717`:\n\n1. `checkProjectStaleness(dir)` looks for `.sourcevision`, `.rex`, and `.hench` under `./record`, finds none, and prints `Project setup incomplete — .sourcevision, .rex, .hench not found — run ndx init to initialize` in a fully initialized project.\n2. `loadProjectConfig(dir)` reads `.n-dx.json` from the same bogus path and silently falls back to `{}` via its `.catch`. Command timeouts (`resolveCommandTimeout`) and BETA experimental flags (`experimentalEnv`, forwarded to children through `childEnv()`) therefore do not apply to tool-delegation commands invoked this way.\n\n**Observed.** `node packages/core/cli.js hench record --task=… --status=completed --title=… --summary=…` from the repo root printed the warning while writing the run correctly to `.hench/runs/`.\n\n**Why the delegated command still works.** Tool delegation passes `rest` verbatim to the sub-CLI (`packages/core/cli.js:2724`), which performs its own directory resolution. Only the orchestrator's own `dir` is wrong — which is why the symptom is a false warning and silently-dropped config rather than a failed command.\n\n**Relationship to `2037c955`.** That completed feature (\"Suppress Stale Project Setup Message When All Tool Directories Exist\") addressed the same user-visible symptom by replacing the trigger heuristic with a direct existence check. That fix is correct and remains in place; this is a distinct root cause — the directory handed to the check is wrong — which is why it is a new item rather than an edit to completed work.\n\n**Reachability.** Any `ndx rex|hench|sourcevision|sv <subcommand>` invocation with no trailing directory argument. Common in scripted and skill-driven use.\n\n**Possible solutions.**\n1. *Recommended.* Make `resolveDir` aware of tool delegation: when `command` is a tool name, skip the first positional in `rest` (the subcommand) before scanning. Narrow and targeted; risk is that tools with multi-word subcommands would need the same treatment.\n2. Only accept a positional as a directory when it resolves to an existing directory on disk, falling back to `process.cwd()` otherwise. Fixes every caller shape at once and is self-correcting, but changes behavior for a genuinely intended directory argument that does not yet exist.\n3. Suppress the stale check for tool-delegation commands via `STALE_CHECK_SKIP_COMMANDS`. Silences the warning only — leaves the `.n-dx.json` misread in place. Not recommended: it treats the symptom."
