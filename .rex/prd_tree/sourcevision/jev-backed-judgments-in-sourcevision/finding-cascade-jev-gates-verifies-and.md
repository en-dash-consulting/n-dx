description: "Invert the enrichment default from \"generate everything, then filter with regexes\" to \"compute facts, let Jev judge, generate only where the judgment is uncertain, then verify what was generated.\" Evidence from the 2026-09-21 live runs on this repository: 27 of 30 generated findings were `structural` paraphrases of cohesion/coupling numbers pass 0 already emits; the four Claude enrichment batches were 27k of a 29.6k-token phase and all of its wall-clock, while the Jev judgment step over the same findings and 26 zones took three requests and seconds.\n\n**Shipped (2026-09-22, branch feat/sourcevision-jev-enrich-hench):**\n\n- **Run record.** `manifest.lastAnalysis` and `.sourcevision/.cache/analyses.jsonl`: mode (`fast` · `generative` · `narrate` · `cascade`), wall-clock per phase, calls/tokens/time per LLM task class, cache hits/misses; the CLI prints one line per class. Both LLM clients record into `analyzers/run-ledger.ts`.\n- **Verify and anchor** (`enrich-judge.ts`, evidence mode). Per finding, in the same request as severity/category: support Noul over the scope zone's files, leading doc comments and imports (< 0.3 dropped, 0.3–0.7 kept with the support probability as confidence, replaces `isSpeculativeFinding` when judged); restates-metric Noul against the pass 0 findings for the scope (≥ 0.7 dropped); anchor Choice over the zone's files → `Finding.anchors`; type Choice (≥ 0.5) and scope Choice (≥ 0.8, evidence zones only). Judged prompts stop asking the text model for severity, category, type, scope and the finding-types hint. A failing batch is split in half and retried. Hook lives in `zones.ts` just before `assembleFindings`, for every enrichment mode.\n- **Judgment cache** (`judgment-cache.ts`). Per-question key = sha256(model + question + the state slices its backticked paths reference); consulted inside `askJev`, only misses are sent, answers stored atomically in `.sourcevision/.cache/judgments.json` (≤ 20k entries).\n- **Naming as selection** (`zone-naming.ts`). Candidates from package.json, dominant directory, top-two directories, dominant archetype; Choice + `none`; pair Nouls over graph-prefiltered pairs (merge ≥ 0.8, observation 0.4–0.6); `none` or confidence < 0.5 → three generated names → Choice + describes-Noul (≥ 0.6) → algorithmic fallback. Zones continuing a previous zone with a chosen name keep it and are not re-selected; names are deduplicated (largest keeps, others algorithmic).\n- **Cascade** (`enrich-cascade.ts`), the default whenever a `zone.judge` route resolves and `--narrate` is off: structural zones templated; names by selection; descriptions templated from facts (count, dominant archetypes, entry points, import partners); fragility judged once — ≥ 0.7 finding, 0.3–0.7 escalated to the per-zone generative prompt as a pass-2 call (names preserved; previous structure hashes carried so unchanged escalated zones are skipped); narrated findings then verified. Judgment-made findings bypass the support judgment. Templated descriptions and selected names survive identity preservation (`reapplyCascadeLabels`; a name chosen in an earlier run still wins). `PRIMER.md` is not regenerated in cascade mode. `--narrate` (passed through the sourcevision CLI, listed in help) forces the full generative pass.\n- **Classification escalation.** A Jev answer below 0.4 that is not a confident `none` (≥ 0.6) goes to the text classifier with the file's leading doc comment; `enrichClassificationsWithLLM` takes `projectDir`.\n\n**Not shipped, captured as follow-ups:** the per-heuristic-finding *real problem or artifact?* Noul and the per-file *which zone should this live in?* Choice feeding `move-recommendations.ts`; removal of the per-zone content-hash skip in `enrich.ts` (it still serves `--narrate`); `PASS_CONFIGS`/meta-pass deletion (they remain on the narrate path). CONTEXT.md was already deterministic — the generative artifact is `PRIMER.md`, now gated to generative modes.\n\n**Measurement (this repository, 2026-09-22):** see the execution log entry for the cascade-vs-narrate numbers. `pnpm gauntlet:evals` (fixture partition and archetypes, `--fast`) passes unchanged — it does not score findings, so retention was measured on this repository directly.\n\n**Out of scope, capture separately:** the rex `analyze` pre-filter (Noul *actionable as a task?* + Choice over existing epics); tightening the `utility` archetype criteria in `archetypes.ts`; `--per-zone` is not on the sourcevision CLI's passthrough allow-list either (pre-existing).\n\nThresholds live in code, not config."
