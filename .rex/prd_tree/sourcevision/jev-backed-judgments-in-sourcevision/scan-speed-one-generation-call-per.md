description: "Measured on caos (829 files, 33 zones, 2026-09-22): every phase except zone enrichment completes in ≈ 0 s; the 20 Jev judgments take 6 s total (0.3–0.5 s each); the 276 s of phase 4 is 19 text-model calls — 13 generated-name fallbacks at 15 s and 6 per-zone narrations at 22 s. A trivial prompt through the `claude` CLI costs 3.0 s on any model (spawn, auth, project discovery), so 19 calls pay 57 s before a token is read. The scan is already fast everywhere except that it still generates one prompt per zone, one spawn per prompt, on the critical path.\n\n**1. One name-proposal call.** `proposeZoneNames` becomes `proposeZoneNamesFor(zones[])`: one prompt listing every zone that needs generated names (id, file sample, entry points; up to 20 zones per prompt), answering `{ \"<zone id>\": [\"Name\",\"Name\",\"Name\"] }`. Verification stays per zone but merges into one Jev request (`pick-<id>` Choice + `fits-<id>-<k>` Nouls for all zones). caos: 13 calls → 1.\n\n**2. One narration call.** New `enrich-multiplex.ts`: `narrateZones(zones, …)` builds a single prompt for all escalated zones (the cap is 6) — per-zone blocks with files, headers, known insights and crossings, one output contract (`{ zones: [{ id, newInsights, findings: [{ text }] }] }`, judged form: text-only findings), task class `zone.enrich-deep`, one retry at a smaller file sample on a parse failure. Per-zone `extractFindings` and `computeZoneStructureHash` on the result so the carry-forward rule keeps working. The cascade uses it; `enrichZonesPerZone` remains for `--narrate --per-zone`. caos: 6 calls → 1, and the model sees the escalated zones together.\n\n**3. Narration off the critical path.** After the judged layer (names, descriptions, fragility, moves, heuristics, verified findings) `analyze` writes `zones.json` and the output files and returns; if zones were escalated it spawns a detached `sv narrate <dir>` child (stdio to `.sourcevision/.cache/narration.log`), records `manifest.narration = { status: \"pending\", pid, zones, startedAt }`, and prints where the log is. `--wait` keeps today's blocking behaviour (CI, `ndx ci`). The `narrate` command runs the multiplexed narration for the pending zones, judges the findings (support/anchors/severity — the same `judgeFindings` evidence path), merges insights and findings into `zones.json`, regenerates `llms.txt`/`CONTEXT.md`, sets `manifest.narration.status = \"done\"` (or `\"failed\"` with the reason), and appends a `mode: \"narration\"` record to `analyses.jsonl`. Staleness guard: the child re-reads `zones.json` before writing and drops its result if `analyzedAt` moved since it started. The dashboard's manifest reader can show a \"narration pending\" badge from the field; wiring that badge is out of scope.\n\n**Target (caos, keyed, fresh):** results on disk in under 10 s, prose in under 60 s, zero behaviour change without a key."
