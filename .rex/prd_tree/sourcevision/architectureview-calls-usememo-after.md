Verdict: should-fix (real, reachable, cheap fix, same defect class the branch declares fixed).\n\n## The defect\n\n`ArchitectureView` is the third pass-gated SourceVision view and has the exact shape that cbcc2814 (\"Fix conditional hook order in the Problems and Suggestions views\") fixed in the other two — but it was left unfixed, and the structural guard added alongside that fix does not cover it.\n\n- `packages/web/src/viewer/views/architecture.ts:20` — `return h(EnrichmentGate, ...)` when `enrichmentPass < ENRICHMENT_THRESHOLDS.architecture` (2)\n- `packages/web/src/viewer/views/architecture.ts:42` — `const zoneHealthData = useMemo(...)`, below that return\n- `packages/web/tests/unit/viewer/enrichment-gate-hook-order.test.ts:43` — `GATED_VIEWS` is hardcoded to `problems.ts` and `suggestions.ts`\n\n`ENRICHMENT_THRESHOLDS` has exactly three keys; architecture is the omitted one of three.\n\n## Failure scenario\n\n`sidebar.ts:376` keeps locked views navigable. Open Architecture while `zones.enrichmentPass` is 0: the gate renders and `useMemo` is never called, so the component's hook list is empty. An analysis finishes with the dashboard still open, `enrichmentPass` becomes 2, and the same mounted component calls `useMemo` for the first time.\n\nToday nothing is misread, because the hook list grew from zero — this is latent, exactly as the changeset for the sibling fix describes (\"the exposure is to the next edit\"). Slot 0 then means the newly added hook on a gated render and `zoneHealthData` on an ungated one. Preact matches hooks positionally and, unlike React, emits no warning: the slots silently shift under whatever state is already there.\n\nNote this is precisely how the sibling defect was introduced — cbcc2814's own description records that adding `useFeatureToggle` for the Explain action is what surfaced it.\n\n## Reachability (Pass 2)\n\nReachable through a real entry point: the Architecture tab in the dashboard sidebar, on any project whose analysis has not yet reached enrichment pass 2. Full build, typecheck, and all package + root test suites are green with the defect present.\n\n## Solution options\n\n1. **Move the memo above the gate and extend the guard list (recommended).** Hoist the `zoneHealthData` useMemo above the early return, mirroring the two fixed views, and add `{ name: \"architecture.ts\", component: \"ArchitectureView\" }` to `GATED_VIEWS`. ~4 lines. Cost: near zero. Risk: none — `zoneHealthData` already guards `if (!zones) return []`, so computing it on a gated render is safe and cheap. Add the guard entry FIRST so the test fails before the fix and passes after, proving it has teeth.\n\n2. **Derive `GATED_VIEWS` by scanning the views directory for `EnrichmentGate` instead of hardcoding it.** Closes the whole class rather than this instance, so a fourth gated view cannot be added unguarded. Cost: moderate — the test's `componentBody` helper is deliberately crude and assumes one exported component per file, which holds for the three views today but would need care. Risk: a scanner that silently matches nothing is worse than a list. Worth doing as a follow-up on top of option 1, not instead of it.\n"
