description: "Found reviewing the 5.5 model-list hotfix (2026-10-02). Severity: medium. Two problems in one seam.\n\nPROBLEM 1: llm.effort is dead config\n`llm.effort.<taskClass>` is parsed (packages/llm-client/src/llm-config.ts:259) and resolveTaskModel returns it as `effort` (packages/llm-client/src/config.ts, TaskModelResolution). No request ever sends it, so an operator who sets `llm.effort` gets no effect and no warning.\n\nPROBLEM 2: Opus 5.5 silently thinks less on the API path\nThe heavy tier and review model moved from claude-opus-5 to claude-opus-5-5. On the Messages API, Opus 5's default effort was `high`, but Opus 5.5's default is `medium`. n-dx sends no effort, so every heavy-tier Claude API call now gets less reasoning than before, with nothing to signal it.\n\nSOLUTION: Claude Messages API call paths only\n1. Carry the resolved effort to the request. Add an optional `effort` to CompletionRequest (llm-client). Have the Claude API provider (packages/llm-client/src/api-provider.ts, complete()) send `output_config: { effort }` when it is set. Do the same for hench's Claude API agent loop (packages/hench/src/agent/lifecycle/loop.ts, the params handed to callWithRetry). Thread `effort` from resolveTaskModel at each call site that already resolves a task model and reaches one of these two requests. Cross-package imports go through the existing gateways (packages/hench/src/prd/llm-gateway.ts).\n2. Default for Opus 5.5. When no `llm.effort` rule matches and the resolved model is claude-opus-5-5, send effort \"high\", the effective default under Opus 5, so the 5.5 bump does not lower reasoning depth. When no rule matches for any other model, send nothing, which keeps today's behaviour.\n3. Guard unsupported models. Claude Haiku 4.5 (and Sonnet 4.5 and older) return a 400 when sent `effort`. Keep an explicit allowlist of effort-capable Claude ids: claude-fable-5-1, claude-fable-5, claude-opus-5-5, claude-opus-5, claude-opus-4-8, claude-opus-4-7, claude-opus-4-6, claude-sonnet-5-5, claude-sonnet-5, claude-sonnet-4-6. Match dated -YYYYMMDD snapshots too. For a model outside the list, drop the effort and log one warning naming the task class and model. Never send it.\n4. Valid values are low, medium, high, xhigh and max. If `llm.effort` holds any other value, drop it and warn; do not send it.\n5. SDK check. Confirm that @anthropic-ai/sdk in packages/llm-client (and hench, if it has its own) types `output_config.effort` on MessageCreateParams. If it does not, STOP and report it. Do not bump the SDK in this task, and do not cast around the type.\n\nOUT OF SCOPE (record as follow-ups if you find them; do not implement): Claude Code CLI runs, both llm-client cli-provider.ts and hench's cli-loop spawn. Claude Code has an `--effort` flag and picks its own default, so passing llm.effort there is separate work. Also out of scope: Codex, Google and local providers, and thinking-parameter changes (n-dx never disables thinking).\n\nACCEPTANCE CRITERIA\n- With `llm.effort` set to { \"prd.*\": \"low\" }, a Claude API completion for a prd.* task class on an effort-capable model sends output_config.effort = \"low\". A unit test asserts on the request body sent to a mocked SDK client.\n- With no llm.effort configured, a Claude API call on claude-opus-5-5 sends effort \"high\", and a call on claude-sonnet-5-5 sends no output_config. Both are unit-tested.\n- A call that resolves to claude-haiku-4-5 never sends output_config, even when llm.effort matches. Its warning is unit-tested.\n- An invalid llm.effort value is not sent and produces a warning.\n- hench's Claude API agent loop sends the same effort as the llm-client provider for the same model and config, covered by a test.\n- A changeset bumps the touched packages at patch and names the new Opus 5.5 default.\n- pnpm build and pnpm test pass from the repo root."
