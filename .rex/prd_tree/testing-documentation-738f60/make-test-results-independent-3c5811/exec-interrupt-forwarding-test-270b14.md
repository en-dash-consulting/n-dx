description: "**Severity:** low — **Verdict:** should-fix (captured from /ndx-adversarial-review of branch `chore/pr-329-review-followups`, 2026-08-25)\n\n**Failure scenario.** This is a documentation-accuracy defect with a small coverage tail, not a runtime bug. Two claims in one docblock are wrong, and both were written on this branch.\n\n**Claim 1 — where CI runs tests.** `tests/integration/exec-interrupt-forwarding.test.js:13-17` justifies putting the test in the root suite with:\n\n> \"`smoke-macos` and `smoke-windows` both run `tests/**`, while the per-package suites run on Windows only (the ubuntu `validate` job builds and runs `pr-check`, which is build + rex validate — no tests). A POSIX-gated case under `packages/llm-client/tests/` would therefore never execute anywhere.\"\n\n`.github/workflows/ci.yml` shows the `validate` job on `ubuntu-latest` running `pnpm pr-check`, then **`node scripts/run-all-tests.mjs packages`**, then **`node scripts/run-vitest-bind-aware.mjs root`**. So a POSIX-gated per-package test would run on ubuntu, and the stated reason for the file's location does not hold. The contradiction is internal to this branch: the CI comment added in the same diff says the opposite — \"the ubuntu `validate` job already runs BOTH suites — per-package unit tests and the root e2e / integration suite — so POSIX coverage does not depend on this job.\"\n\n**Claim 2 — which assertions run where.** `:139-142` says of the first case: \"The registration is observable without raising anything, and this is the assertion that differs by platform — so it runs on every host.\" It does not. The suite is wrapped in `describeNeedsPosixShell`, so on a Windows machine with no `sh` on PATH the whole file skips, including the Windows branch at `:149-152` that asserts `exec` installs **no** SIGINT listener. And the case genuinely needs `sh` as written — its Windows branch still calls `waitForGrandchild()`, which throws after 10s when the shell never launched. Observed locally: all 3 cases skipped from PowerShell; the full root suite reported 5 skips.\n\n**Necessity — why this is low and not medium.** The Windows invariant is still covered at unit level: `forwardsInterrupts({})` returning false is asserted in `packages/llm-client/tests/unit/interrupt-forwarding.test.ts` (15 cases, verified green). So no invariant is unguarded; what is lost is the integration-level confirmation and, more importantly, the accuracy of the reasoning a future contributor will inherit. A false statement about which CI job runs which suite will be used to justify the next test's placement.\n\n**Reachability.** Not a user-facing failure. It misleads contributors deciding where to put a platform-gated test, and it silently narrows this file's Windows coverage on developer machines.\n\n**Possible solutions.**\n1. *Recommended.* Correct the docblock to match `ci.yml`, and lift the Windows branch of the first case out of the `sh`-gated suite — it needs only a listener count around any spawned command, not a shell-launched grandchild, so it can run on every host as the comment claims. Cost: a small test restructure plus a prose fix. Risk: none.\n2. Correct the docblock only, and drop the \"runs on every host\" sentence. Cost: minutes. Leaves the Windows integration assertion skipped wherever `sh` is missing, which is acceptable given the unit coverage, but keeps the coverage narrower than the file implies.\n3. Move the file to `packages/llm-client/tests/integration/` now that the location rationale is known to be false. Larger change; only worth it if the per-package suite is the better home on other grounds, since `smoke-macos` runs the root suite and not the per-package one — so the move would trade macOS coverage for ubuntu coverage rather than adding any."
