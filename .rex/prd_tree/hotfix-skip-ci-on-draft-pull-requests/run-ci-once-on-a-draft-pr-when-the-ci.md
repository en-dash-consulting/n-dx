description: "Drafts skip CI (the sibling tasks). Give them a manual, one-shot way in: adding the label `ci:run` to a draft PR runs the full ci.yml once, on the PR's merge commit like any PR run. Later pushes to the draft skip again; to run again, remove the label and add it back. Scope is ci.yml only. CodeQL and Dependency Review stay skip-on-draft and run when the PR is marked ready.\n\nWhy a label and not workflow_dispatch: GitHub only offers workflow_dispatch when the default branch's copy of the workflow declares it, and this branch is stacked eight PRs above main. A pull_request run reads the workflow from the PR branch, so the label works as soon as a branch carries this change.\n\nEdits, .github/workflows/ci.yml:\n1. Add `labeled` to the `pull_request:` `types:` list. Do NOT add `unlabeled`.\n2. Replace the draft gate on `build` and `smoke-parity` with one that also admits the label event:\n   if: >-\n     github.event_name != 'pull_request'\n     || (github.event.action != 'labeled' && github.event.pull_request.draft == false)\n     || (github.event.action == 'labeled' && github.event.label.name == 'ci:run' && github.event.pull_request.draft == true)\n   Consequences, each intended: any other label skips everything; `ci:run` on a ready PR skips (it already ran on its own); a push to a draft that still carries the label skips (one-shot).\n3. THE CONCURRENCY TRAP. The workflow-level `concurrency: ci-${{ github.ref }}` with cancel-in-progress applies to a run before any job `if:` is evaluated. With `labeled` in the types, adding ANY label to a ready PR would start a run whose jobs all skip, and that run would cancel the PR's real in-flight CI run. Give every labeled event that will not run CI a group of its own, so it cancels nothing:\n   concurrency:\n     group: ci-${{ github.ref }}${{ github.event.action == 'labeled' && !(github.event.label.name == 'ci:run' && github.event.pull_request.draft) && format('-noop-{0}', github.run_id) || '' }}\n     cancel-in-progress: true\n   Keep `converted_to_draft` in the shared group: cancelling the in-flight run when a PR goes back to draft is the point of that trigger. Verify the expression type-checks (a `&&`/`||` ternary whose middle value is a non-empty string) and say in a comment why it exists.\n4. Short comments in the existing style above `types:`, the gate and the concurrency block.\n\nDocs: add a short \"Draft pull requests\" paragraph to CONTRIBUTING.md (where it discusses PRs and CI; create a small section if there is none): drafts do not run CI; add `ci:run` to run CI once; marking the PR ready runs everything, CodeQL and Dependency Review included.\n\nTest: extend tests/e2e/ci-draft-pr-gate.test.js (text-only, same style):\n- ci.yml `pull_request` types include `labeled` and do not include `unlabeled`.\n- the build and smoke-parity `if:` both reference `github.event.label.name == 'ci:run'` and still carry the `github.event_name != 'pull_request'` guard.\n- the concurrency `group:` references `github.run_id` for labeled events (the guard against a label cancelling a real run). Comment why.\n- codeql.yml and dependency-review.yml do NOT list `labeled` (a label must not start those).\n\nNot in scope: creating the `ci:run` label in the GitHub repo. That is a repository setting the operator does by hand (`gh label create ci:run`).\n\nThen run the commands listed in the epic's conventions."
