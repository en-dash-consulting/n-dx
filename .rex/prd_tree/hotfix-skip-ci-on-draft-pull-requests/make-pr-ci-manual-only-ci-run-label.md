CodeQL and Dependency Review are NOT changed by this task (they keep skipping drafts and running on ready-PR pushes).\n\nWhy this is safe: main's ruleset requires \"Build & Validate\", \"CLI Smoke (macOS)\", \"CLI Smoke (Windows)\" and \"CLI Smoke Parity\" with strict up-to-date. A required check counts only for the commit it ran on, so a PR cannot merge until CI has been run on its latest commit. The nine \"Tests (…)\" jobs are not required today; making them required is a ruleset change the operator makes by hand, outside this task.\n\nBranch: hotfix/manual-pr-ci (this worktree), stacked on hotfix/draft-pr-ci-gate-test-jobs (#712), which gated the `test` job and made tests/e2e/ci-draft-pr-gate.test.js discover every job.\n\nEdits, .github/workflows/ci.yml:\n1. `pull_request:` types become `[labeled]` only. Drop opened, synchronize, reopened, ready_for_review and converted_to_draft. Keep `push` (main), `merge_group` and `workflow_dispatch` and their comments. Rewrite the `types:` comment: PR CI is manual; why each dropped type is gone.\n2. Gate for `build`, `test` and `smoke-parity` (same block on all three; `test` and `smoke-parity` keep their one-line pointer to `build`'s comment):\n   if: github.event_name != 'pull_request' || (github.event.action == 'labeled' && github.event.label.name == 'ci:run')\n   Draft state no longer matters: `ci:run` runs on a draft or a ready PR. New job `consume-label`, name \"Consume ci:run label\", that removes `ci:run` from the PR as soon as the run starts so it can be added again for the next run:\n   - `if: github.event_name == 'pull_request' && github.event.action == 'labeled' && github.event.label.name == 'ci:run'`\n   - job-level `permissions: pull-requests: write` (override the file's `contents: read` for this job only; it checks out nothing and runs no PR code, so say so in a comment).\n   - one step: `gh pr edit \"$PR\" --repo \"$REPO\" --remove-label ci:run` with GH_TOKEN=${{ github.token }}, PR=${{ github.event.pull_request.number }}, REPO=${{ github.repository }} passed through `env:` (never interpolate event fields into `run:`).\n   - `continue-on-error: true`: on a fork PR the token is read-only and the removal fails; CI itself must not go red over it.
