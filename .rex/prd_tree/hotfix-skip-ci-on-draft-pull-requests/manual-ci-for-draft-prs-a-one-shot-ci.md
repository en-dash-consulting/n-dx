description: "Drafts skip CI (the sibling tasks). Give them two manual ways in. Scope is ci.yml only. CodeQL and Dependency Review stay skip-on-draft and run when the PR is marked ready.\n\nA. The `ci:run` label (one-shot). Adding the label `ci:run` to a draft PR runs the full ci.yml once, on the PR's merge commit like any PR run. Later pushes to the draft skip again; to run again, remove the label and add it back. A pull_request run reads the workflow from the PR branch, so this works as soon as a branch carries the change. The label already exists in en-dash-consulting/n-dx; do not create it.\n\nB. The Run workflow button (`workflow_dispatch`). GitHub only shows the button (and accepts `gh workflow run`) once the default branch's copy of ci.yml declares the trigger, so it goes live when this stack reaches main. It runs against the chosen branch's head, not the PR's merge commit with its base. Its results appear in the Actions tab, not as a PR event.\n\nEdits, .github/workflows/ci.yml:\n1. Add `labeled` to the `pull_request:` `types:` list. Do NOT add `unlabeled`.\n2. Add a bare `workflow_dispatch:` trigger (no inputs) to `on:`. Keep `push`, `pull_request` and `merge_group` and their comments.\n3. Replace the draft gate on `build` and `smoke-parity` with one that also admits the label event:\n   if: >-\n     github.event_name != 'pull_request'\n     || (github.event.action != 'labeled' && github.event.pull_request.draft == false)\n     || (github.event.action == 'labeled' && github.event.label.name == 'ci:run' && github.event.pull_request.draft == true)\n   workflow_dispatch passes through the first clause, so the button always runs. Consequences, each intended: any other label skips everything; `ci:run` on a ready PR skips (it already ran on its own); a push to a draft that still carries the label skips (one-shot).\n4. Steps that read pull_request-only context stay gated on `github.event_name == 'pull_request'` (e.g. \"Require changeset\"); check no step newly breaks under workflow_dispatch, where `github.head_ref` is empty and there is no PR payload.\n5. CONCURRENCY. Two traps in the workflow-level `concurrency: ci-${{ github.ref }}` (cancel-in-progress), which applies to a run before any job `if:` is evaluated:\n   (a) With `labeled` in the types, adding ANY label to a ready PR would start a run whose jobs all skip, and that run would cancel the PR's real in-flight CI run. Give every labeled event that will not run CI a group of its own.\n   (b) A workflow_dispatch run has `github.ref` = refs/heads/<branch>, the same group as a push to that branch. A button press on main would cancel main's push run, and the next push would cancel the button's run. Give dispatch runs their own group prefix.\n   Shape:\n   concurrency:\n     group: ci-${{ github.event_name == 'workflow_dispatch' && 'dispatch-' || '' }}${{ github.ref }}${{ github.event.action == 'labeled' && !(github.event.label.name == 'ci:run' && github.event.pull_request.draft) && format('-noop-{0}', github.run_id) || '' }}\n     cancel-in-progress: true\n   Keep `converted_to_draft` in the shared PR group: cancelling the in-flight run when a PR goes back to draft is the point of that trigger. Verify each `&&`/`||` ternary has a non-empty string in the middle, and say in a comment why each part exists.\n6. Short comments in the existing style above `types:`, `workflow_dispatch:`, the gate and the concurrency block.\n\nDocs: add a short \"Draft pull requests\" section to CONTRIBUTING.md (where it discusses PRs and CI; create one if there is none): drafts do not run CI; add `ci:run` to run CI once, remove and re-add it to run again; or use Run workflow on the CI workflow in the Actions tab (branch head, not merged with its base; available once the trigger is on main); marking the PR ready runs everything, CodeQL and Dependency Review included.\n\nTest: extend tests/e2e/ci-draft-pr-gate.test.js (text-only, same style):\n- ci.yml `on:` block has `workflow_dispatch:`; `pull_request` types include `labeled` and do not include `unlabeled`.\n- the build and smoke-parity `if:` both reference `github.event.label.name == 'ci:run'` and still carry the `github.event_name != 'pull_request'` guard.\n- the concurrency `group:` references `github.run_id` for labeled events and separates `workflow_dispatch` (the guards against a label or a button press cancelling a real run). Comment why.\n- codeql.yml and dependency-review.yml do NOT list `labeled` (a label must not start those).\n- tests/e2e/ci-merge-queue-trigger.test.js's check that `on:` carries push, pull_request and merge_group still passes.\n\nThen run the commands listed in the epic's conventions."
