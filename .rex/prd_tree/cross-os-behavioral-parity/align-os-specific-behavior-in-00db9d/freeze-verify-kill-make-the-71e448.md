description: "Replace inference with containment on the POSIX timeout path. Today's sweep reads the process table and infers parentage, which is best-effort by construction; this makes it provable.\n\nTHE ALGORITHM\n1. SIGSTOP the root.\n2. Enumerate descendants; SIGSTOP each newly discovered one.\n3. Repeat until a full pass discovers nothing AND every member reads as stopped.\n4. SIGKILL, leaves before parents.\n\nWHY IT CONVERGES: a stopped process cannot execute, so it cannot fork. New arrivals can only come from processes that were still running at enumeration time, and that set shrinks monotonically. SIGSTOP cannot be caught, blocked, or ignored, so step 1 cannot be refused.\n\nWHY IT IS BETTER THAN THE CURRENT SWEEP: reparenting only happens when a parent exits. The existing code collects descendants BEFORE signalling precisely because killing dissolves the pid->ppid links it depends on. Freezing the tree and killing nothing until enumeration is closed means those links cannot dissolve underneath us — it removes the hole rather than working around it.\n\nTWO CONSTRAINTS THAT SHAPE THE SCOPE\n\n1. SIGTERM PENDS WHILE STOPPED. A stopped process does not act on SIGTERM until SIGCONT; the signal just queues. So freezing commits us to SIGKILL, which IS delivered to stopped processes without resuming them. Restoring a graceful phase would mean SIGCONT per process, which reopens the fork window and forfeits the guarantee. Freezing and graceful shutdown are mutually exclusive.\n\n   Therefore SCOPE THIS TO THE TIMEOUT / RUNAWAY PATH ONLY. Leave the graceful shutdown path (SIGTERM then grace then SIGKILL, used by Ctrl-C on `ndx start` via core's tracker) exactly as it is. Freezing a child mid-write while it holds locks and then hard-killing it is strictly worse for shutdown, where we want the flush.\n\n2. NO PAUSE ON WINDOWS IN PURE JS. There is no SIGSTOP; libuv maps the signals it supports onto TerminateProcess. The real equivalents all need native code — NtSuspendProcess, per-thread SuspendThread, debugger attach, or a Job Object with JOB_OBJECT_LIMIT_ACTIVE_PROCESS = 1 (containment by denying creation rather than pausing). Job Objects remain rejected for the reason already recorded in packages/core/child-lifecycle.js: a compiled dependency in a pure-JS package.\n\n   So this buys POSIX definitiveness, not cross-OS definitiveness — which is fine, because POSIX is where the story is weakest. Windows keeps `taskkill /T`. Worth documenting there that Windows never reparents, so its tree links survive a parent's death; its failure mode is the mirror image, a PPID dangling onto a RECYCLED pid.\n\nVERIFICATION IS REAL, NOT ASSUMED: a stopped process is observably stopped. Linux exposes state in /proc/<pid>/stat field 3 ('T'); `ps -o state=` gives the same on Linux and macOS. The fixpoint check is therefore an assertion, not a hope, and should be written as one.\n\nONCE 58161d5e LANDS, THE FAST PATH NEEDS NO ENUMERATION AT ALL:\n    kill(-pgid, SIGSTOP)   // atomic freeze of the whole group\n    kill(-pgid, SIGKILL)   // atomic kill\nbecause group membership is inherited rather than listed. The stop-then-enumerate loop becomes the fallback for children with no group of their own, and that is exactly where it earns its keep.\n\nCOST: one `ps` per pass, typically converging in two. On Linux a /proc read avoids the spawn entirely and is worth preferring there.\n\nREMAINING LIMIT, worth stating in the code rather than discovering later: a deliberate double-fork daemon is DESIGNED to escape parentage entirely. No enumeration finds it. That is a policy question (should agent-run commands be allowed to daemonize?) rather than a detection one."
