description: "Verdict: should-fix. Severity: medium (test quality — the guard does not protect the behaviour it names).\n\nFAILURE SCENARIO\ntests/e2e/skill-termination.test.js:62-71 (\"names what it does not do\") asserts:\n\n  /\\bnot\\b|\\bnever\\b|\\bseparate run\\b|\\bdoes not\\b/i.test(section)\n\nover everything following \"## Done when\". A bare \"not\" anywhere in that trailing section satisfies it. A skill whose ending reads\n\n  \"## Done when\n   The report is delivered, whether or not the user acts on it.\"\n\npasses while stating no scope boundary at all — which is the precise failure the suite exists to prevent (a skill that overruns into adjacent work because its ending never said what is out of scope).\n\nThe file's own docstring claims more than the code does: \"The assertion therefore looks for an explicit statement of the final action and of what is deliberately *not* done\". It looks for a negation word.\n\nCURRENT STATE — the suite is honest today\nI checked all 13 skills. Every match is a genuine scope statement, so nothing is currently passing on a technicality:\n  ndx-adversarial-review  \"This skill does not fix anything\"\n  ndx-capture             \"do not start implementing what was captured\"\n  ndx-config              \"Do not change settings that were not asked for\"\n  ndx-feedback            \"does not fix what the feedback describes\"\n  ndx-plan                \"do not begin implementing any of them\"\n  ndx-reshape             \"it does not implement them\"\n  ndx-status              \"is a separate run\"\n  ndx-work                \"Do not pick up the next task\"\n  ndx-zone                \"It does not refactor the zone\"\n  no-plan-mode            \"produces no output, writes no file, and requires no record\"\n  dev-link                \"Do not build, test, or run n-dx commands beyond the one check\"\n  iso-map                 \"it does not change the code it renders\"\n  triage                  \"does not fix the issues it triages\"\nThe defect is that it would not stop the NEXT skill, not that it is passing something bad now.\n\nVERIFIED CAVEAT — do not tighten blind\nThe obvious fix (drop the bare \\bnot\\b alternative, keep do not|does not|never|is a separate run|stop there) FAILS no-plan-mode, whose boundary is legitimately phrased with \"no <noun>\" forms rather than a negated verb:\n  \"There is no run to finish: this skill is a standing rule, not a procedure. ... It produces no output, writes no file, and requires no record.\"\nI ran that tighter regex against all 13 bodies: 1 would fail. So the phrase list has to admit \"no output / writes no file / requires no record\", or the assertion has to require two independent negation constructions rather than one.\n\nSOLUTION OPTIONS\n(a) RECOMMENDED — replace the bare \\bnot\\b alternative with an explicit phrase list that includes both shapes: negated verbs (do not, does not, never, is a separate run, stop there) AND \"no <noun>\" forms (produces no, writes no, requires no, no PRD item). Run it against all 13 fixtures before landing; the suite already has the bodies loaded, so this is cheap to verify.\n(b) Require two or more distinct negation constructions in the section, on the theory that an incidental \"not\" rarely co-occurs with a second one. Less brittle than a phrase list but harder to explain in a failure message.\n(c) Assert structurally instead of lexically: require the \"## Done when\" section to contain a sentence whose subject is the skill (\"This skill ...\", \"<name> does ...\") and a negation. Closest to what the docstring promises; most work.\n(d) Keep the loose check and correct the docstring to say it only detects a negation word. Cheapest, but gives up the guard.\n\nRecommend (a), with the fixture run as part of the change.\n\nRelated sibling task in this epic: \"workflow-skill-wording-termination\" — the item that introduced this guard.\n\nFound by /ndx-adversarial-review on branch fix/coding-prompts-and-workflows (d0d7aeb8)."
