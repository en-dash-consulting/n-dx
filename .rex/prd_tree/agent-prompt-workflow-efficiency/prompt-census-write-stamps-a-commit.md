description: "Verdict: must-fix. Severity: medium.\n\nFAILURE SCENARIO\nRun `node scripts/prompt-census.mjs --write` with uncommitted changes in the tree. The baseline records the measurement of the WORKING TREE but stamps it with the SHA of HEAD, so the published artifact attributes its numbers to a commit that does not contain the code they were measured from. Every later `--compare` then reports deltas against the wrong starting point.\n\nThis already happened. The checked-in baseline records:\n  docs/analysis/prompt-token-baseline.json  ->  \"commit\": \"3dda8b5b3cc1\"\n  docs/analysis/prompt-token-baseline.md:14 ->  \"**Commit** — `3dda8b5b3cc1`\"\n\nBut its entry for buildSingleZoneLaterPassEnvelope lists\n  \"constants\": { \"ONLY_NEW_INSIGHTS\": 25, \"JSON_OBJECT_ONLY\": 16 }\n\nand JSON_OBJECT_ONLY does not exist at that commit:\n  $ git grep -c JSON_OBJECT_ONLY 3dda8b5b -- packages/sourcevision/src/analyzers/\n  (no output)\n  $ git grep -c JSON_OBJECT_ONLY 0b57e2eb -- packages/sourcevision/src/analyzers/\n  0b57e2eb:.../enrich-per-zone.ts:3\n  $ git merge-base --is-ancestor 3dda8b5b 0b57e2eb    # 3dda8b5b is the OLDER commit\n\nSo the recorded baseline measures content that first exists in 0b57e2eb, a descendant of the commit it names.\n\nMECHANISM\nscripts/prompt-census.mjs:1700-1712 stamps `commit: currentCommit()`. currentCommit() (:1594-1611) reads .git/HEAD and the ref file directly and has no notion of whether the working tree is dirty. The docstring explains why it avoids child_process (it would need an entry in the ALLOWED list in tests/e2e/architecture-policy.test.js) — that reasoning is sound, but the result is a provenance stamp that cannot detect the one condition that invalidates it.\n\nCONSEQUENCE\n0b57e2eb demonstrably changed the assembled text of that builder (\"Respond with ONLY a JSON object:\" -> \"...(no markdown, no explanation):\"), so a correct baseline at 3dda8b5b would show a delta for it. `--compare` instead reports \"(no surface changed)\" and a builder delta of 0. The token totals are not wrong; the attribution is. Since the whole point of a checked-in baseline is to say what a given commit cost, and the page is now published on the docs site (docs/.vitepress/config.ts), the artifact misleads.\n\nIMPORTANT: a numbers-based staleness check would NOT have caught this. The numbers matched. Only the stamp was wrong.\n\nWHY NO CHECK CAUGHT IT\n`--check` only verifies that every registry entry still resolves (it passes: \"36 surfaces resolve\"). tests/e2e/prompt-census.test.js asserts the baseline \"exists and is well formed\", never that it matches HEAD or that the tree was clean when it was recorded.\n\nSOLUTION OPTIONS\n(a) RECOMMENDED — stamp a content hash of the measured surfaces instead of (or alongside) a commit SHA. Provenance that cannot lie, needs no git access at all, and keeps the no-child_process property the script deliberately maintains.\n(b) Add scripts/prompt-census.mjs to ALLOWED in tests/e2e/architecture-policy.test.js and use `git status --porcelain` to refuse `--write` on a dirty tree. Exact and obvious, but costs a deliberate policy edit; note ALLOWED already lists three scripts/*.mjs entries, so this is a normal act rather than a violation.\n(c) Approximate a dirty check in pure JS by comparing each registered surface file's mtime against .git/index. No policy edit, but fragile.\n(d) Add an e2e assertion that the recorded stamp equals HEAD when the tree is clean, so a stale baseline fails CI. Complements any of the above rather than replacing them.\n\nRecommend (a) + (d).\n\nALSO REQUIRED: re-record the baseline at a clean HEAD, because the checked-in file is wrong today.\n\nFound by /ndx-adversarial-review on branch fix/coding-prompts-and-workflows (150ec2b3, baseline re-recorded later in the branch)."
