description: "Add the command that writes the v1 -> v2 migration plan. The pipeline is on main under packages/rex/src/migrations/: runPlanPipeline (pipeline.ts) over the registered migration v1ToV2 (registry.ts, v1-to-v2/index.ts, source v1TreeSource), seams from planSeams (v1-to-v2/seams.ts) with createTextPlacementModel (analyze/place-reason.ts) and createTextSpecModel (analyze/spec-draft-reason.ts), and writePlanFile / readPlanFile (plan-file.ts). There is no core/migration-plan.ts any more.\n\nShape: a new rex command, `rex migrate --plan [--out <path>] [--rules-only] [dir]`, in its own module under packages/rex/src/cli/commands/ with one dispatch line. It loads the v1 tree, gathers the outside facts the rules read (test and code files from the repository), runs the pipeline with planSeams, and writes the plan with writePlanFile. It prints a short summary: counts per kind, held changes, proposed areas. It writes nothing in the rex directory. `ndx migrate --plan` in packages/core spawns that rex command; orchestration scripts import no library code.\n\nDefault plan path: <project>/.ndx-migration/plan.json. The command creates .ndx-migration/ with its own .gitignore (\"*\") so the plan is never committed by accident. --out <path> overrides it; a path inside the rex directory is refused.\n\nRe-planning: when the output file already holds a v1-to-v2 plan, it is passed as context.previous so unchanged answers are reused, and its cutAt is kept unless --cut-at is given, so a re-run on an unchanged tree writes an identical file.\n\nDefaults (printed in the plan header): text placement and text spec drafting, one model for both (rex.placement.models = text for the migration); Jev review on only when a TypeSafe key (TYPESAFE_API_KEY) is available, otherwise skipped with the one warning planSeams emits; Jev placement off. --rules-only turns every model pass off. Under autoAccept \"agree\" a text-only placement is never auto-accepted: it is recorded as a suggestion and the change stays held for the Inbox. A pass recorded incomplete (header.passes[i].incomplete) is reported, naming the pass and its error, and the command exits non-zero after writing the plan, so the answers paid for are kept for the retry. Export isPlanComplete(plan) from plan-file.ts for this and for apply (48598986).\n\nA review-sourced epic (source \"ndx-adversarial-review\") proposes no area (#631 finding 1): treat it as a delivery container, the way a dissolved release epic is, and place or hold its children like other changes. (Criterion added overnight 2026-10-12 from the first-pass rules; confirm.)\n\nEvidence for the defaults, sampled live runs of 2026-10-09 (#616): the text model placed all 4 sampled held changes sensibly, while Jev placement picked wrongly on 3 and abstained on 1; Jev's confident criterion flags were useful. 16 spec redrafts took about 6.7 s each on claude-sonnet-5-5. A full-tree run of this repository (309 specs, 117 held) is roughly 430 text calls (about 45 min sequential) and 450 Jev calls.\n\nFirst pass (decided 2026-10-12; v2 migration path, decisions D1-D7):\n- Every v1 item lands in v2, checked by count and id. The migration drops or cancels nothing.\n- Changes the rules placed land on their capability. Changes the rules could not place (held) land in the Inbox with needsPlacement, in changes/inbox/. A text-model pick is recorded as a suggestion only.\n- Areas keep their v1 epic names, except a review-sourced epic (source \"ndx-adversarial-review\"), which proposes no area (#631 finding 1). Its children are placed or held like other changes.\n- Capability specs ship as drafted and stay flagged as unreviewed.\n- The cut is recorded as the first change, as 11c88bce describes.\n- Apply removes prd_tree/ and tree-meta.json in the same PRD transaction that writes the v2 tree, so the two layouts never exist side by side.\n- No decisions file and no area-renaming pass: those come after the cut.\n\nBoundary (stack C, roadmap PR 23):\n- Lane files: packages/rex/src/migrations/; one new rex CLI command for plan and apply, in its own module under packages/rex/src/cli/commands/ plus one dispatch line in packages/rex/src/cli/ (keep edits to the shared CLI files minimal: another stack is changing rex's store resolution and CLI error mapping in the same files, so a merge conflict is expected later); store/prd-model-writer.ts (c0dc9b3f); core/change-add.ts or the Inbox writer (2898acbe); packages/core for ndx migrate (spawn only, no library imports) and ndx init; tests.\n- Not hench, not web, not the v2 schema shape (schema/v2.ts), and not the MCP tools.\n- v1 trees keep working exactly as today, apart from the one-line deprecation notice in ad842166.\n- Each newly wired module that imports a v2 module is added to the v2 isolation allowlist in packages/rex/tests/unit/schema/v2.test.ts."
