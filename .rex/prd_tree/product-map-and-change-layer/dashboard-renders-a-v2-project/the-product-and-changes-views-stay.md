description: "Verdict: should-fix (adversarial review of 901a3775). Scenario: on a v2 project, open Plan with the Product and Changes sections mounted, then Quick Add a change (or let `ndx work` complete/apply one). The server broadcasts `rex:prd-changed` and the Tasks tree refreshes, but `ProductPage`/`ChangesPage` (packages/web/src/viewer/views/product-pages.ts, `useProductRead`) fetch once on mount and never refetch, so the new change is missing from Changes and capability status/overlays stay stale beside a Tasks tree that shows the new state. Reachable from the dashboard on every v2 write. Options: (a) refetch in `useProductRead` on `rex:prd-changed` through the existing `use-prd-websocket` hook / ws pipeline (small; recommended, matches how the Tasks view stays live); (b) poll with `usePolling` (simpler, but adds load and latency). Risk: refetch storms during bulk writes; the ws pipeline already coalesces frames."
