description: "Verdict: should-fix (adversarial review of the lazy-watch fix for aeac2c3a). In registerRexWatcher (packages/web/src/server/start.ts), watchPrdFolder records each folder in a `watched` set and never removes it. If prd_tree/, product/ or changes/ is deleted and recreated while the server runs (git checkout of a branch without it and back, or a tool removing the folder), the .rex/ watcher fires and schedules one refresh, but no new recursive watch is added. On Linux (inotify) and Windows the old watch died with the old directory, so later edits inside the recreated folder leave .rex/.cache/prd.json stale until restart. macOS FSEvents watches by path and is unaffected. Folders present at boot behaved the same way before this change (they were never re-watched), so the gap is not new, but the lazy path keeps it.\n\nReachable: any branch switch in a served worktree that removes and restores a PRD folder. Mitigated: the recreation itself triggers one refresh.\n\nOptions: (a, recommended) keep a Map from folder name to FSWatcher. On a .rex/ event for that name, if the directory exists and its inode differs from the watched one (or simply always), close the old watcher, splice it out of `into`, and add a new one. Cost: about 15 lines plus a test. Risk: re-watching on every event for that name churns watchers on macOS, where child writes can report the folder name, so compare inodes. (b) Attach an 'error'/'close' listener that clears the entry. Cheaper, but inotify does not always emit an error when the directory is deleted.\n\nOperator notes (2026-10-14, v2 hardening 4/5): packages/web only, except the criteria's tests.
