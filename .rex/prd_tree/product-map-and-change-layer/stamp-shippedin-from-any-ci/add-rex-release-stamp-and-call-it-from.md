description: "rex release stamp <version> stamps shippedIn on every change applied since the previous release tag and, under applyOn release, applies pending completed changes. n-dx's own release workflow calls it in the Version Packages PR. When no stamp exists, derive shippedIn from the first tag containing the apply commit.\n\nDesign boundary, written 2026-10-09 for the PR 22 run. Follow it exactly; anything it does not allow is stop-and-report.\n\n1. v1 is a no-op that cannot fail. Decide the layout before anything else: when <rexDir>/product/ does not exist (a v1 tree), or there is no .rex directory at all, print one line saying there is nothing to stamp and why (\"this project is on the v1 tree; shippedIn is stamped on v2 changes\"), and exit 0. On that path run no git command, take no lock, and do not parse the v1 tree, so a shallow CI checkout or a v1 parse warning cannot fail it. This repository's next release (0.9.0) runs the command on a v1 tree, so this path is the one that ships first.\n\n2. Host-neutral. The command reads git only: release tags, ancestry and N-DX-Item trailers, through the existing helpers in core/change-landing.ts (computeLandings, firstReleaseContaining) and core/change-commits.ts. Do not reimplement landing, the tag pattern or trailer parsing. The version is a required positional argument; accept X.Y.Z or vX.Y.Z and store X.Y.Z; refuse anything else (prerelease suffixes included) with a CLIError. Nothing GitHub-specific inside rex: no GitHub API, no GITHUB_* environment variables, no ::warning:: syntax.\n\n3. What gets stamped (v2 only). A change is stamped with the version when all hold: it is live (not cancelled, not retired/deleted), finished (completed or applied, as computeLandings judges), has no shippedIn yet, has landed on main (computeLandings says landed: true), and its landing commit is contained in no release tag yet (firstReleaseContaining returns undefined). A change already stamped is never re-stamped, whatever version is passed, so a second run with the same or a different version changes nothing: that is the idempotence criterion. A finished change that has not landed is not stamped; list it in the output with the landing reason. A change whose landing is already in an older tag is left unstamped (the tag fallback in resolveShippedIn covers it). Do not stamp tasks or product nodes.\n\n4. applyOn release. Read rex.applyOn with loadApplyOn. Only when it is \"release\", apply every change from changesAwaitingApply(tree) through applyOnTrigger(tree, id, \"release\", { applyOn, ... }) before stamping, so an applied change is then stamped by rule 3. Under \"complete\" or \"review\" apply nothing. A refused apply (ApplyAmendmentsError) fails the command with the change named; do not catch it into a partial write.\n\n5. One locked write. The v2 path loads, applies, stamps and writes inside the PRD lock for rexDir (the same withLock(prdLockPath(rexDir)) + loadPrdModel + writePrdModel pattern as importBundleIntoV2 in store/prd-bundle-v2.ts). Write nothing when nothing changed. --dry-run computes and prints the same report and writes nothing. --format=json prints the report as JSON (version, applied ids, stamped ids, skipped ids with reasons).\n\n6. Shape. Pure planning in a new module packages/rex/src/core/release-stamp.ts: a function that takes the V2Tree, the version, applyOn, the landing for each change and the set of landing commits already in a release, and returns the new tree plus the report. It must not touch disk, git, config or the lock. A small async wrapper in the same module may gather the git inputs through change-landing.ts. The CLI handler is packages/rex/src/cli/commands/release.ts, dispatched as `rex release stamp <version> [dir]` from cli/index.ts (positional subcommand like `rex claim`); an unknown release subcommand is a usage error. Add the command to rex's help (follow whatever registry or help test the other commands use). Add core/release-stamp.ts and cli/commands/release.ts to the v2 module set in packages/rex/tests/unit/schema/v2.test.ts (\"no runtime module imports the v2 modules yet\") and to its comment, as cli/commands/codeowners.ts was. Do not edit schema/v2.ts (shippedIn already exists), store/, MCP tools, packages/web or packages/hench.\n\n7. The workflow call. changesets/action@v2 runs version-script through @actions/exec, not a shell, so shell operators there do not work. Change the root package.json \"version-packages\" script to run `changeset version` and then the stamp, fail-open, and point .github/workflows/release.yml's version-script at `pnpm run version-packages`. The script must (a) still fail when `changeset version` fails, and (b) only print a warning line and succeed when the stamp fails. Use exactly this shape: changeset version && { node packages/rex/dist/cli/index.js release stamp \"$(node -p \"require('./packages/core/package.json').version\")\" . || echo 'warning: rex release stamp failed; versioning continues'; }  Do not change any other release.yml step, the checkout's fetch depth, the publish script, or any existing changeset. Update the comment above the changesets step to say why the version script stamps and that it never blocks a release.\n\n8. Tests. (a) v1 fixture: exits 0, prints nothing to stamp, writes no file, and works in a directory that is not a git repository. (b) Idempotence: on a v2 fixture repo with a landed, untagged, completed change, a first run stamps it, a second run (same version, then a different version) changes no file. (c) Tag-derivation parity: in a fixture git repo, stamp version X, then create tag X on main; for the same change with shippedIn removed, resolveShippedIn returns X, equal to the stamp. (d) A change landed before an existing release tag is not stamped; an unlanded finished change is reported as skipped. (e) applyOn release applies a completed unapplied change and stamps it; under complete it is not applied. (f) The workflow: a test reads release.yml and package.json and asserts the version-script is `pnpm run version-packages` and the script runs `changeset version` before `release stamp` with the fail-open group. Fixture git repos need full history and real tags; follow packages/rex/tests/integration/change-landing.test.ts.\n\n9. Add a patch changeset for @n-dx/rex only. Say \"product layer\", never \"map\"."
