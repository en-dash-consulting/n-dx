description: "Two defects in the slug-rule write guard shipped by this feature, both reproduced against a throwaway project during the pre-PR review.\n\n**1 — The guard refuses the writer's own rename.** On a tree with no `slugRule` marker, `assertSlugRuleWritable` (packages/rex/src/store/slug-rule-guard.ts, the absent-marker branch around line 154) falls back to `findNonConformingSlugs(items, treeRoot)`. It passes `doc.items` — the document *about to be written*, already carrying the mutation — and compares the slugs that document implies against the paths currently on disk. Any write that changes a slug therefore looks exactly like a foreign build's re-slug. Reproduced: on an unmarked tree, `rex update <epic-id> --title=\"Beta epic\"` is refused with \"it carries no slug-rule marker and 1 path does not match slug rule 2 … ./alpha-epic should be beta-epic (Beta epic). Run 'rex migrate-slugs'.\" The rename is blocked, and the message blames a foreign build for a mismatch the caller itself introduced. Every tree written before this release is unmarked, so this hits real repositories on upgrade — on whichever slug-changing write happens to come first (a title edit, a move, a merge, or an add that forces a colliding sibling to gain an id suffix). A non-slug-changing write stamps the marker and permanently unblocks, which is why it was not caught: it bites exactly once per repository.\n\n**2 — migrate-slugs downgrades a newer tree and reports a no-op.** `adoptSlugRule` bypasses the guard unconditionally rather than only in the adopt-older direction, so following the refusal's own advice migrates a tree *down*. Reproduced: with `{\"slugRule\":3}` in tree-meta.json, every write is refused with \"Run 'rex migrate-slugs' … to bring the tree onto rule 2\"; running it rewrites the marker 3 → 2 while printing \"PRD tree already uses the current slug rule — nothing to rename\" — claiming a no-op while having overwritten a newer build's marker. The rule-3 build is then refused, given the same advice, and migrates it back: repeated whole-tree renames ping-ponging between builds, reached by following the guard's own instructions. Not reachable today since 2 is the maximum version, but a field whose whole purpose is forward compatibility guarantees a rule 3.\n\n**Why the tests did not catch either.** `packages/rex/tests/helpers/rex-dir-test-support.ts` now stamps `slugRule: SLUG_RULE_VERSION` into every fixture, so every test takes the cheap marker-equals early return at slug-rule-guard.ts:141 and no fixture exercises the absent-marker branch that real upgrades take.\n\nImplementation notes: For (1), the absent-marker branch must judge the tree as it *is*, not as the pending document implies it should be — scan against the document loaded from disk (the pre-mutation items the store already holds) rather than the mutated one, or restrict the mismatch set to items whose on-disk path disagrees with what the *loaded* document implied. Keep the refusal for a genuinely foreign unmarked tree; the distinguishing fact is whether the expected slug changed because of this write or because the tree was written by another rule. For (2), add a direction check to `adoptSlugRule` in both `packages/rex/src/store/folder-tree-store.ts:294` and `packages/rex/src/store/file-adapter.ts:555` — refuse when the on-disk marker exceeds `SLUG_RULE_VERSION` — and make the refusal messages in `slug-rule-guard.ts` (both `assertSlugRuleWritable` and `checkTreeConformance`) branch on direction. Fix `migrate-slugs.ts:138` so the no-op message is not printed on a run that wrote the marker. For coverage, give the test helper a way to omit the marker and add a store-level test for the rename case. Also fix `samplePaths` at slug-rule-guard.ts:60, which concatenates `parentDir` (built with path.join) to a hardcoded forward slash. Changeset: @n-dx/rex patch. Constraints that apply to every n-dx change: cross-package imports go only through the package's gateway module (hench: src/prd/rex-gateway.ts and src/prd/llm-gateway.ts; web: src/server/rex-gateway.ts and src/server/domain-gateway.ts) and tests/e2e/architecture-policy.test.js enforces an export ceiling on those gateways; orchestration scripts in packages/core spawn CLIs and never import packages; every user-facing change carries a changeset using the scoped package name with a patch bump; run pnpm preflight before opening the PR."
