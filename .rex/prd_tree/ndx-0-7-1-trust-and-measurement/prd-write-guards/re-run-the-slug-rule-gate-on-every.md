description: "The slug-rule guard runs once per invocation, before the first task, and assertSlugRuleWritable returns early on a matching marker without scanning paths. A long --loop or --epic-by-epic run that outlives a change to the tree (another worktree's write, a pull) is therefore unguarded after its first iteration, and a later iteration's completion write re-slugs whatever drifted. Run the gate at the start of every iteration, ahead of the claim.\n\nLOCATIONS CORRECTED 2026-09-22. An earlier version of this description sent the work to packages/hench/src/agent/lifecycle. That directory exists but contains neither function. Line numbers below are as of commit a2b7e0c7; verify by symbol name rather than trusting the number.\n\n- assertPrdTreeConformant is defined in packages/hench/src/cli/commands/run.ts at line 389, and calls checkTreeConformance at 398. Line 398 is inside that helper, not a call site of it.\n- The single call today is `await assertPrdTreeConformant(rexDir)` in cmdRun (defined at 1214), at line 1439, before cmdRun dispatches to one of the two loops at 1764 and 1766.\n- runIterations is a private function in the same file at 1824. runLoop is at 1931. Neither is exported and neither lives under src/agent/.\n\nTHE HAZARD IN THE SHAPE OF THE FIX. Every execution path funnels through runOne, defined at line 967, and runOne has three call sites: 1872 inside runIterations, and 2036 and 2358 inside runLoop. Taking \"run the gate at the start of every iteration\" literally means finding all three, and a fix that covers runIterations plus one of runLoop's two paths leaves a loop mode unguarded while still passing a test written against the other. That is exactly how WM2094 went green while the store that actually runs was untouched — see .rex/execution-log.jsonl under item 078cd2b1. Gating at the top of runOne covers all three by construction; if you gate at the loop bodies instead, cover both of runLoop's call sites and say in the PR why that placement was preferred.\n\nSINGLE-TASK RUNS. A single-task run reaches runOne through runIterations with iterations = 1, not through a separate path — cmdRun always dispatches to runLoop or runIterations. So a gate inside runOne must be paired with removing the cmdRun call at 1439, or a single-task run pays for two full tree parses where it used to pay for one. Acceptance criterion 2 means one gate per iteration, and exactly one for a single-task run.\n\nImplementation notes: call the same pre-run gate (assertPrdTreeConformant, or checkTreeConformance directly through the rex gateway at packages/hench/src/prd/rex-gateway.ts) at the top of each iteration, ahead of TaskClaims and the --allow-dirty check, so a refusal happens before anything is claimed or written. Add an integration test in packages/hench/tests/integration that makes the tree non-conformant between iterations — rename one PRD directory, or rewrite .rex/tree-meta.json's slugRule — and asserts the next iteration refuses before claiming, with a message naming rex migrate-slugs. Exercise the --loop path, not only --iterations, since they are separate functions with separate runOne call sites. Note that WM2092 changed what non-conformance means: an absent marker on a non-empty tree is now itself a refusal, so a test may make the tree non-conformant by deleting the marker as well as by renaming a path. Changeset: @n-dx/hench patch.\n\nConstraints that apply to every n-dx change: cross-package imports go only through the package's gateway module (hench: src/prd/rex-gateway.ts and src/prd/llm-gateway.ts; web: src/server/rex-gateway.ts and src/server/domain-gateway.ts) and tests/e2e/architecture-policy.test.js enforces an export ceiling on those gateways; orchestration scripts in packages/core spawn CLIs and never import packages; every user-facing change carries a changeset using the scoped package name with a patch bump; run pnpm preflight before opening the PR.\n\nNOTE (0.7.1 close-out, 2026-09-25): criterion 3 is deliberately not met. A single-task run gates twice, not once: cmdRun's unconditional pre-flight (readTreeConformanceRefusal, which is also where the interactive migrate-slugs offer lives) still runs, and createPerTaskTreeGate is built without consuming it, so runOne re-checks before task one. The pre-flight has to stay because --reset-deferred and the commit gate write or block before the first task; the first task cannot rely on it because the commit gate waits on an operator prompt for unbounded time. Cost: one extra loadDocument per run (~0.33s on a 405-item tree). See the comment above createPerTaskTreeGate's call in packages/hench/src/cli/commands/run.ts."
