description: "A tree whose marker names another rule, or whose paths do not match the running rule, dead-ends a run with a refusal and an instruction to go run rex migrate-slugs by hand. Close that loop at the gate — but stop after migrating rather than continuing into the task.\n\nWHY NOT SILENT AUTO-RUN-AND-CONTINUE, WHICH IS WHAT WAS ORIGINALLY ASKED FOR. On a non-conformant tree migrate-slugs is not a no-op: it rewrites every path that does not match the running rule, which can be the whole tree. The command's own header says why it exists — it performs the rename \"deliberately, in one reviewable commit, instead of letting the next ordinary save produce a surprise mass diff\". Running it inside a task run and continuing turns it back into exactly that surprise diff: the rename lands in whatever commit the task makes next, under a message about something else. That is the 2026-09-17 incident (a pull request merging 1,570 re-slugged files through green CI) with the human step removed. Stopping after the migration keeps the rename in its own commit, which is the property the command was built to provide, and still removes the manual step.\n\nWHERE IT CAN LIVE. Not in the store guard. assertSlugRuleWritable throws from inside writeFolderTree, which runs while holding the PRD lock, and migrate-slugs needs that same lock — recovering there deadlocks. The gates are the place: hench's per-task gateTree (packages/hench/src/cli/commands/run.ts, called as the first statement of runOne) and the dashboard's Execute gate (packages/web/src/server/routes-hench.ts), both of which run before the claim and outside the lock, where the refusal's own copy already promises that nothing has been claimed or written. The store guard stays a hard error as the backstop.\n\nAUTONOMOUS RUNS MUST NOT DO THIS AT ALL. An unattended run has nobody to see the diff before it is committed, which is the whole safeguard. Refuse exactly as today when the run is autonomous, non-TTY, or in CI, and say so in the message rather than silently behaving differently.\n\nNote that direction is already bounded: assertSlugRuleAdoptable permits adopting an older rule only, so a tree marked with a newer rule is refused and no prompt should be offered for it — migrating there would be a downgrade wearing a migration's name.\n\nImplementation notes: in the hench gate, catch the refusal, and on an interactive TTY print what migrate-slugs would do and prompt. On yes, spawn it the way orchestration spawns any CLI rather than importing rex outside the gateway, then exit with a message naming the changed paths and telling the operator to review and commit before re-running. On no, or when not interactive, rethrow unchanged. migrate-slugs already snapshots first (ensureSnapshot in packages/rex/src/cli/commands/migrate-slugs.ts, around line 99), so rex restore can undo a bad migration; say so in the prompt. Mirror the same offer in the dashboard Execute gate, where \"interactive\" means a real operator on the other end of the request. Changeset: @n-dx/hench patch, @n-dx/web patch. Constraints that apply to every n-dx change: cross-package imports go only through the package's gateway module (hench: src/prd/rex-gateway.ts and src/prd/llm-gateway.ts; web: src/server/rex-gateway.ts and src/server/domain-gateway.ts) and tests/e2e/architecture-policy.test.js enforces an export ceiling on those gateways; orchestration scripts in packages/core spawn CLIs and never import packages; every user-facing change carries a changeset using the scoped package name with a patch bump; run pnpm preflight before opening the PR."
