description: "Found by /ndx-adversarial-review on the missing-review gate change, 2026-09-12. Severity: medium. Verdict: out-of-scope (pre-existing; the review gate merely adds one more route into the same state).\n\nFAILURE SCENARIO\nOn the commit-prompt path (autoCommit=false) the agent stages its work and writes a proposed message to .hench-commit-msg.txt. performCommitPromptIfNeeded returns early on 'run.status !== \"completed\"' (packages/hench/src/agent/lifecycle/shared.ts:1776), so any path that flips a completed run to failed after the agent wrote that file leaves the sentinel on disk with content. Reachable today from at least three: the test-gate max-attempts failure (shared.ts ~2450), the uncommitted-work refusal (shared.ts ~2500), and now the missing-review refusal.\n\nThe next run then starts startCommitMsgWatcher, which arms on *detection* of the file rather than on a write during this run (packages/hench/src/agent/lifecycle/commit-msg-watcher.ts:78-140). After hench.commitMsgTimeoutMs it runs 'git commit -F .hench-commit-msg.txt' over whatever is staged. Result: task B's work committed under task A's commit message, including task A's N-DX-Status trailer, so the audit trail names the wrong item.\n\nREACHABILITY\nReal, on the default non-autoCommit path. Requires two runs in sequence, which is exactly what --loop and --auto do.\n\nSOLUTION OPTIONS\n1. Delete the sentinel whenever a run ends non-completed and the commit prompt was skipped. Cheap, one place (finalizeRun). Risk: discards a message the operator might have wanted to reuse after fixing the cause; mitigate by logging the path before unlinking, or renaming to .hench-commit-msg.rejected.txt.\n2. Have startCommitMsgWatcher ignore a sentinel whose mtime predates the run's startedAt. Narrower, no data discarded. Risk: clock skew, and it leaves the stale file to accumulate.\n3. Stamp the run id into the sentinel and refuse to commit one written by a different run. Most precise, most code, and changes a file format the agent prompt documents.\n\nRECOMMENDED: option 1, with the rename rather than the unlink, so nothing is destroyed and the next watcher cannot see it.\n\nACCEPTANCE CRITERIA (fails today, passes once fixed)\n- A run that ends non-completed with a non-empty .hench-commit-msg.txt does not leave a file the next run's watcher will act on.\n- The proposed message is still recoverable by the operator after such a run.\n- A unit test drives finalizeRun to a non-completed status with a populated sentinel and asserts a following startCommitMsgWatcher does not auto-commit.\n- Existing commit-prompt and timer-expiry behaviour on the completed path is unchanged.\n\nTAGS (CLI cannot set these; apply via MCP add_item/edit_item when convenient): ndx-adversarial-review, severity:medium. SOURCE: ndx-adversarial-review."
