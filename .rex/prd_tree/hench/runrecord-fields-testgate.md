description: "Found by /ndx-adversarial-review on the missing-review gate change, 2026-09-12. Severity: medium. Verdict: out-of-scope (pre-existing; sibling of the 'review' stripping that WAS fixed in that change).\n\nFAILURE SCENARIO\nloadRun returns the zod-parsed record, not the raw JSON (packages/hench/src/store/runs.ts:56-60), and zod strips keys the schema does not declare. RunRecordSchema (packages/hench/src/schema/validate.ts) declares no testGate, dependencyAudit or cleanupTransformations, though finalizeRun writes all three (shared.ts:2292, 2387) and saveRun persists them. So .hench/runs/<id>.json holds the data on disk and every reader that goes through loadRun or listRuns sees undefined.\n\nNothing reads them back today, which is the only reason this is not already a visible bug — the existing assertions are all in-memory (tests/integration/self-heal-codex-batch.test.ts:232 and similar operate on the returned run object, never a reloaded one). It is a loaded trap: the next consumer added for any of these three gets undefined with no error, exactly as happened for 'review', where a documented stuck-task exemption and a 'hench show' line were both dead on arrival.\n\nREACHABILITY\nNo current wrong behaviour. The defect is silent data loss across the persistence boundary plus the trap it sets.\n\nSOLUTION OPTIONS\n1. Declare the three fields on RunRecordSchema, passthrough and fully optional, as was done for 'review'. Cheap, consistent, cannot reject a legacy record. Risk: none material.\n2. Declare them precisely, mirroring the TS types. Better validation. Risk: a run written before any field existed fails safeParse, loadRun throws, and listRuns swallows it — dropping the whole run from usage rollups. Rejected for 'review' for this reason.\n3. Add a drift test that fails when a RunRecord key has no RunRecordSchema entry, so the class of defect cannot recur. Most durable; pairs with option 1 rather than replacing it.\n\nRECOMMENDED: option 1 plus option 3. The drift test is the part that stops a fourth field going the same way.\n\nACCEPTANCE CRITERIA (fails today, passes once fixed)\n- A run saved with testGate, dependencyAudit and cleanupTransformations reads back through loadRun with all three intact.\n- A run record written before the newest sub-field exists still loads rather than being dropped by listRuns.\n- A test fails if a field is added to the RunRecord type without a matching RunRecordSchema entry.\n\nTAGS (CLI cannot set these; apply via MCP add_item/edit_item when convenient): ndx-adversarial-review, severity:medium.
