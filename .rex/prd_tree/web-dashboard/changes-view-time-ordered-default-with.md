  - "The existing `CompletionTimeline` component and its `buildTimeline` data source are extended in place to cover all items rather than completions only; no second parallel timeline component is introduced, and the timeline no longer renders as a secondary panel below the tree."
  - "The Changes view renders a time-ordered layout by default, grouped into day buckets newest-first, with each item placed by its most recent meaningful timestamp using the precedence `completedAt` then `startedAt` then `lastModified` (first present wins), and the chosen field named in the item's row."
  - "A toggle switches between the timeline and tree layouts; the tree layout is unchanged from today, including search, status filter, bulk actions and merge preview."
  - "The layout choice persists across view switches and reloads using the same persistence mechanism the status filter already uses in `prd.ts`."
  - "The status filter and search apply identically in both layouts, with the same result set in each."
  - "Items are desaturated on a defined recency scale, with the most recent bucket at full saturation and progressively older buckets faded to a floor that remains legible in both light and dark themes."
  - "Desaturation is never the only recency signal: every item also carries an explicit relative date label, so the read survives low vision, colour blindness and greyscale rendering."
  - "Hench runs appear on the timeline as markers anchored to their `finishedAt`, so recent agent activity is distinguishable from ordinary item mutation."
  - "Items with no usable timestamp render in a clearly labelled undated group rather than being dropped or dated to the epoch."
  - "Hierarchy is not lost in the timeline: each row shows its parent chain, reusing the existing breadcrumb logic, and selecting a row opens the same detail panel the tree opens."
  - "Timeline rendering holds up on this repository's PRD (over 1,300 items) without a visible stall, with off-screen day buckets not rendered eagerly."
  - "The change of default layout is recorded in the release note, since it changes what existing users see on first load."
description: "**Re-scoped 2026-10-07 (agreed with Hal on #533, deferred until after 1.0.0):** the time-ordered layout becomes the default of the Changes view, because the change layer is the linear history; the Product page keeps its own layout. Placement drops `createdAt` (completedAt, then startedAt, then lastModified). After the cut a task's parent is its change, so the parent chain on each row is change, then task. The text below is the original capture.\n\nThe PRD view (`packages/web/src/viewer/views/prd.ts`) leads with hierarchy, which answers \"how is this structured\" but not \"what just happened.\" Make a time-ordered rendering the default, keep the tree one toggle away, and fade items by age so the result of the most recent run is visually obvious against months of completed work.\n\n**This extends existing code rather than starting fresh.** `CompletionTimeline` (`packages/web/src/viewer/components/prd-tree/completion-timeline.ts`, ~148 lines) already groups items by day with parent breadcrumbs and is already rendered inside the PRD view at `prd.ts:389` — but only as a secondary panel *below* the tree, and only for items carrying `completedAt`. The work is to promote it to a first-class layout and generalize it: all items rather than completions only, a toggle against the tree, recency desaturation, and hench run markers. Its `buildTimeline` data source and day-grouping render are the starting point; a second parallel timeline component would be a regression.\n\nThe data already exists — PRD items carry `createdAt` (required), `startedAt?`, `completedAt?` and `lastModified?`, and hench run records carry `startedAt`/`finishedAt` — so this is a rendering and view-state concern, not a schema one.\n\nWhat else it builds on: the status filter in `prd.ts` already persists across view switches, and the layout toggle follows that same persistence pattern. `activity.ts` is a flat execution-log table over `.rex/execution-log.jsonl`, a different surface that this does not replace.\n\nDesign notes: items bucket by day, newest first, placed by their most recent meaningful timestamp with an explicit precedence so placement is never ambiguous. Desaturation carries the recency read, but never alone — an explicit relative date label accompanies it so the signal survives low vision, colour blindness and greyscale. Hench runs overlay as markers, because \"what was just run\" means agent activity rather than mere item mutation.\n\nGoal: opening the PRD answers \"what moved recently\" before it answers \"how is this organised\", without losing the tree for anyone who wants it.\n\nPrior art: the completed feature \"Item completion timeline view\" (577c74cb) delivered the completions-only panel this supersedes."
