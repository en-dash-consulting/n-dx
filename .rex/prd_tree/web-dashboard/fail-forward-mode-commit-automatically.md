description: "A single settings toggle, \"fail-forward mode\", that makes n-dx save work automatically instead of leaving it uncommitted. When it is on, the end of every command, run and loop adds and commits whatever that work changed, using a simple constant message per kind of change. Settings changes commit the same way, including the ones made through the pre-run menu.\n\nThe name states the intent: never stall or lose work because something was left dirty — keep moving forward and let the history record each step.\n\nScope:\n- **End of a run or loop.** When an autonomous run finishes — `ndx work --auto`, `--loop`, `--iterations`, `--epic-by-epic` — commit what it changed. In a loop this is per iteration, not once at the end, so an interrupted loop still leaves each completed iteration committed.\n- **Settings changes.** Writing `.n-dx.json`, `.rex/config.json` or `.hench/config.json` commits with a constant message naming what changed.\n- **The pre-run menu.** Settings edited from the prepare-task modal (`packages/web/src/viewer/components/prepare-task-modal.ts`) commit on the same path, not a separate one.\n- **Constant messages.** A fixed message per kind (settings, PRD, scan output, run result) rather than generated prose — predictable history, nothing to review before it lands.\n\nThe toggle itself:\n- A boolean key in `FEATURE_REGISTRY` (`packages/web/src/server/routes-features.ts:43`), which renders generically in `views/feature-toggles.ts` on the Project settings page. Default off.\n- Enforced server-side with `isFeatureEnabled` so it fails closed, and readable by the CLI/hench paths too — those do not go through the web server, so the toggle must live in project config that both sides read, not in web-only state.\n- **The toggle needs an info icon** opening a short explanation of what fail-forward mode commits, when, and that it is off by default. The settings sections currently render label plus description text with no per-toggle help affordance, so this is a small addition to the toggle component rather than a copy change.\n\nRelationship to the one-click labelled commit feature: that one delivers dirty-path classification and pathspec-scoped staging, which this feature needs. Build on it rather than adding a second commit path — and in particular do not route this through `POST /api/git/commit` while it still runs `git add -A` (`packages/web/src/server/routes-git.ts:229`), or an automatic commit will sweep in unrelated work.\n\nInteractions worth settling in design, because they are where this can do damage:\n- Hench's pre-run gate refuses to start against a dirty tree (`performPreRunCommitGateIfNeeded`, `packages/hench/src/agent/lifecycle/shared.ts`) and there is already an \"Allow dirty tree\" escape in the prepare-task modal. Fail-forward changes what that gate sees; the two must not fight.\n- An automatic commit must not stage a user's unrelated in-progress work. Scope every commit to the paths the step actually touched.\n- Attribution: these commits should carry the `N-DX:` trailer block like other n-dx-generated commits, and name an `N-DX-Item` where the work belongs to one.\n- Nothing should be pushed automatically. Committing is the whole promise."
