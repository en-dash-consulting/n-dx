description: "Where: packages/rex/src/cli/mcp.ts. createRexMcpServer(dir) builds rexDir, store (resolveStore) and claims (openClaimsStore(dir), resolveClaimHolder(dir).worktreeRoot) eagerly, and every server.tool / server.resource closure captures them. Roots are only available after the client's `notifications/initialized`, so the per-workspace state has to be rebindable.\n\n1. Resolution helper, in @n-dx/llm-client next to getWorktreeRoot / getGitCommonDir (packages/llm-client/src/exec.ts), exported from its public entry, because sourcevision reuses it (two consumers). The helper is pure apart from fs/git reads. Signature: resolveWorkspaceFromRoots({ roots: {uri: string}[], startupDir, marker }) → { dir, source: 'roots' | 'startup', refused?: string }.\n   For each root in order: skip non-file: URIs; path = realpath(fileURLToPath(uri)); candidate = getWorktreeRoot(path) ?? path.\n   The first candidate that differs from realpath(startupDir) and contains `marker` (\".rex\" for rex) wins → source 'roots'.\n   If the candidate is a worktree of the SAME repository as startupDir (getGitCommonDir equal) but lacks the marker → return startupDir with `refused` set to a message naming both paths.\n   A root in an unrelated repository without the marker is ignored → 'startup'.\n\n2. Rebindable workspace in mcp.ts. Hold { dir, rexDir, store, claims } in one object that every handler reads at call time, not at registration. Do not thread new parameters through the handler signatures in mcp-tools.ts; pass the current values at the call site. Add an optional createRexMcpServer option (e.g. { resolveWorkspaceFromClientRoots: true }) that only startMcpServer (stdio) sets, so the web HTTP factory keeps its fixed dir.\n   With the option on, and only when dir === process.cwd() (the implicit `.` from .mcp.json):\n   - On server.server.oninitialized: if getClientCapabilities()?.roots, call server.server.listRoots(), resolve, and rebind (new resolveStore(rexDir), openClaimsStore, resolveClaimHolder) when the dir changes.\n   - setNotificationHandler(RootsListChangedNotificationSchema) → re-resolve.\n   - Tool calls that arrive before the first resolution settles await it. Bound the wait (about 2 s); on timeout use the startup dir and log one stderr line.\n   - When `refused` is set: write tools (add_item, edit_item, update_task_status, move_item, merge_items, append_log, claim_task, release_task, sync_with_remote, reorganize when it applies changes) return isError with the message. Read tools still answer from the startup dir and carry a `warning`.\n   Run ensureLegacyPrdMigrated for the rebound dir too.\n\n3. Diagnostics. On rebind, write one stderr line: `rex mcp: serving <dir> (client root; started in <startupDir>)`. stdout is the protocol, so nothing else goes there. handleGetCapabilities gains the workspace block.\n\n4. Tests.\n   Unit (packages/llm-client): worktree root, a subdirectory root → its worktree toplevel, a non-file URI ignored, a root without the marker ignored, a same-repo worktree without the marker → refused, root === startup → 'startup'.\n   Integration (packages/rex/tests/integration): build a tmp git repo with `rex init` and a committed .rex/prd_tree, then `git worktree add` a second worktree. Spawn `node <rex dist>/cli/index.js mcp .` with cwd = the main checkout. Connect @modelcontextprotocol/sdk Client with capabilities { roots: { listChanged: true } } and setRequestHandler(ListRootsRequestSchema) returning the worktree.\n   Integration cases: add_item lands in the worktree only; a client without roots writes the main checkout as today; `sendRootsListChanged()` after switching the root moves later writes; `rex mcp <abs main path>` with cwd elsewhere ignores roots.\n\n5. Changesets: @n-dx/rex and @n-dx/llm-client, patch."
