Five in one session, on branches whose subject was test determinism, is evidence about the harness rather than about five tests. Sighting 5 is a Windows file handle still held at teardown — a different mechanism that may have a different cause. Do not assume a single root cause. None of those explains a worker exiting with every test passing, or an EPERM at cleanup.\n\n**Options.** (a) Recommended: treat the five as one investigation. Run pnpm validate in a loop capturing each worker's stderr — vitest reports an exit code but not what the process printed before dying — and record heap usage and open handles per suite. Decide from evidence whether this is memory pressure, vitest worker supervision, or cross-suite interference. Cost: machine time. Risk: it may not reproduce, in which case record what was ruled out and close. (b) Attribute each separately.
