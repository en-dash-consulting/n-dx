description: "Task b19513b5 scaled the six fixed-timeout `vi.waitFor` watcher waits in the two web worktree integration tests by BUDGET_MULTIPLIER. Two more waits in the same file were left on vitest's 1-second default, and both files still tear their git fixtures down without retries.\n\n1. `packages/web/tests/integration/workspace-two-worktrees.test.ts`, around lines 96 and 104: `await vi.waitFor(() => expect(cachedTitle(repo)).toBe(\"A\"))` and `await vi.waitFor(() => expect(cachedTitle(linked)).toBe(\"B\"))` pass no options, so they get vitest's 1s default. They wait for the first cache fill after `registry.refresh()` / `registry.get()` rather than a watcher event, but 1s is the same fixed, idle-machine budget the feature exists to remove. Give them `{ timeout: WATCHER_EVENT_TIMEOUT_MS, interval: 50 }` (the constant already defined at the top of the file), and give each `it()` an explicit timeout of `WATCHER_EVENT_TIMEOUT_MS + TEST_TIMEOUT_BUFFER` so vitest's own 30s testTimeout cannot fire before the wait does (TESTING.md Family 3).\n\n2. Fixture teardown: `workspace-two-worktrees.test.ts` (afterAll, about line 87) and `worktrees-route.test.ts` (about line 114) call `rmSync(root, { recursive: true, force: true })` on a directory holding git repositories and a linked worktree. The repository rule is that git fixtures tear down with retries. Web tests cannot import hench's `RM_RETRY`/`cleanupProjectDir`; the web-local equivalent is `removeTempDir` in `packages/web/tests/helpers/temp-dir.ts` (async `fs.rm` with maxRetries 10 / retryDelay 100, warns instead of failing only on win32). Switch both teardowns to `await removeTempDir(...)` and make the hooks async. Leave the `rmSync` calls around lines 262 and 402 of worktrees-route.test.ts alone: they delete a single run file as part of the test, and that removal is under test.\n\nTest-only change: no production code and no changeset."
