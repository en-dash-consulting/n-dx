description: "Found by running the #370 follow-up queue on 2026-09-12. Severity: medium — a slow resource leak on any machine that runs the suite repeatedly, and it degrades the autonomous runs themselves.\n\nFAILURE SCENARIO\nA sweep of this machine found 31 orphaned node processes holding 431 MB, every one of them tests/fixtures/ci-child-cleanup/ci-child-double.mjs validate --quiet, reparented to PID 1. They were spread across seven worktrees (fix-autonomous-run-reliability, pr-02-run-branch-gate, pr-03-mcp-json, pr-04-ask-cwd, pr-06-task-claims, cool-wing-6cea48), with the oldest alive for over 11 hours. Two of them had been created by the task runs earlier in this same session, since each run's test gate executes the full suite.\n\nAll 31 ignored SIGTERM and required SIGKILL. That part is by design: the fixture's header says it 'blocks indefinitely (ignores SIGTERM so the parent must escalate to SIGKILL)', and tests/e2e/cli-ci-child-cleanup.test.js exists to prove the escalation happens. The leak is that the survivors are never reaped — either the assertion path leaves them running after it has made its point, or a timeout/early-return path skips the escalation entirely.\n\nThis matters beyond tidiness: the run records from this session show 'system: 3.9 / 16.0 GB available', and hench's own memory monitor reads system headroom to decide whether to throttle. A slow leak from the test gate pushes later autonomous runs toward throttling.\n\nSOLUTION\n- Give tests/e2e/cli-ci-child-cleanup.test.js an afterEach/afterAll that SIGKILLs any fixture child it spawned, whatever the assertion outcome, so a failing or timing-out case cannot leave one behind. Track spawned PIDs explicitly rather than relying on process-group semantics.\n- Establish whether the escalation path under test actually runs to completion in every case, or whether some cases assert and return before it does. If the production cleanup code has a gap, fix that too and say so in the changeset — a fixture surviving 11 hours is exactly what the code under test is supposed to prevent.\n- Consider a suite-level guard that fails loudly if fixture children outlive the test file, so a future regression is caught rather than accumulating silently.\n\nACCEPTANCE CRITERIA\n- After a full pnpm test run from a clean process table, no ci-child-double.mjs processes remain (assert by scanning for the fixture path).\n- The existing escalation assertions still pass.\n- If a production gap is found, it is fixed and covered; if not, the changeset says the leak was test-side only.\n- Changeset for the affected package (patch)."
