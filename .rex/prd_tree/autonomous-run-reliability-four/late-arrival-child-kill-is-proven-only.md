description: "Found by /ndx-adversarial-review on commit 623ae90b (task 099a0f2d). Severity: medium. Verdict: should-fix. Introduced by that change.\n\nFAILURE SCENARIO\n623ae90b made createChildProcessTracker.register() SIGKILL any child registered after cleanup() has started, which is what stopped ndx ci orphaning a sourcevision-validate child on Ctrl-C. Two things verify it, and neither is both real and deterministic:\n\n1. tests/unit/child-lifecycle.test.js drives the path with FakeChildProcess, an EventEmitter whose kill() only appends to an array. It proves the SIGNAL IS CHOSEN. It cannot prove an OS process dies, and it would still pass if child.kill(\"SIGKILL\") were replaced with a no-op that recorded the signal.\n\n2. tests/e2e/cli-ci-child-cleanup.test.js teardown scans every recorded fixture PID and fails on a survivor. That is real, but it only fires if runCI actually advances to the next step before the parent exits -- a race. Measured on an idle machine 2026-09-12: the vitest path lost that race 3/3 (only the analyze child was ever recorded, no late child spawned at all), while a standalone harness driving the same CLI won it 3/3. So on an idle machine the guard passes vacuously; it was real load that produced the 31 orphans in the original report.\n\nNet effect: revert the four-line latch in register() and the unit tests go red (verified), but nothing proves the real kill works, and on a quiet machine the e2e guard says nothing either. The file header at tests/e2e/cli-ci-child-cleanup.test.js:11-20 currently claims the file 'used to leak one hang-mode double per SIGINT run', which is true under load but not on an idle machine -- a reader who runs it once locally, sees no leak, and concludes the guard is dead code could delete it.\n\nREACHABILITY\nEntry point is pnpm test / node scripts/run-all-tests.mjs. The gap is in what the suite proves, not in a user-facing path.\n\nSOLUTION OPTIONS\nA (recommended). Add an integration test that spawns a REAL child: create a tracker, await cleanup(), then register(spawn(node, ['-e','setInterval(()=>{},1000)'], treeKillSpawnOptions())) and poll kill(pid,0) until it is gone, with a bounded deadline. Deterministic -- no race, because cleanup() has already latched before the spawn. ~25 lines, no production change, and it closes the FakeChildProcess gap for the one path that matters most. Also covers the POSIX group-kill branch by spawning a child that itself spawns a grandchild.\nB. Make the e2e race deterministic by giving the fixture a mode where the first double exits promptly on SIGTERM, so runCI reliably advances to step 2 while the parent is still shutting down. Closer to the real failure, but it is still timing-coupled and it complicates a fixture three test files share.\nC. Do nothing and rely on load. Rejected: that is what let 31 orphans accumulate across seven worktrees unnoticed.\n\nRecommend A, and while there, correct the header claim in tests/e2e/cli-ci-child-cleanup.test.js to say the leak is load-dependent rather than per-run."
