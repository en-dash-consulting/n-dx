description: "Follow-up to PR #370 review (findings 4, 5). Severity: critical — one path lets #363 through unchanged, the other loses the executor's committed-ready work.\n\nFAILURE SCENARIO A — staged work with no commit message passes the gate uncommitted. In finalizeRun (packages/hench/src/agent/lifecycle/shared.ts ~line 2279) the gate passes stagedCommitFollows: !autoCommit and so discounts fully-staged paths. But the commit that is supposed to follow only happens when .hench-commit-msg.txt exists with content: performCommitPromptIfNeeded returns early at 'if (!existsSync(msgPath)) return' (~line 1656). An agent that ran git add -A but never wrote the message file has every line as 'A  path' → isFullyStaged → discounted → clean. updateCompletedTaskStatus marks the PRD completed, no commit lands, the work sits in the index — the exact #363 symptom.\n\nFAILURE SCENARIO B — --review without autoCommit fails the gate on reviewer repairs. pendingRepairs (~line 2275) is computed as autoCommit && review && review.failed === undefined ? review.repairedFiles : []. --review runs regardless of autoCommit (it only requires the CLI provider). With hench.autoCommit=false (the default) the reviewer's unstaged repairs (adversarial-review.ts tells it not to commit; 'fixes are picked up by that commit') are ' M', not fully staged, not discounted → leaked.clean=false → run failed, withdrawCompletionClaim resets the task to pending, performCommitPromptIfNeeded returns early because status !== completed, so the executor's staged work never lands and .hench-commit-msg.txt is left behind. Pre-PR the run completed with the repairs leaked; now the executor's work is lost too.\n\nSOLUTION\n- stagedCommitFollows must be true only when a commit will actually follow: !autoCommit AND a non-empty .hench-commit-msg.txt exists (PENDING_COMMIT_FILE). Add a small helper (pendingCommitMessageExists) next to performCommitPromptIfNeeded and use it in the gate; a commitWatcher that already auto-committed does not make leftover staged paths safe, so do not treat didAutoCommit() as 'a commit follows'.\n- Discount review.repairedFiles whenever the review report is usable (review.failed === undefined), on both paths — and make the non-autoCommit path honour the reviewer prompt's promise by git add-ing review.repairedFiles inside performCommitPromptIfNeeded before git commit -F (~line 1856), the same file list commitReviewRepairsIfNeeded commits on the autoCommit path.\n- Update the comment block above the gate so it states exactly what a later step commits on each path.\n\nACCEPTANCE CRITERIA\n- Integration test (autoCommit=false): staged files with no .hench-commit-msg.txt → completion refused, paths named, nothing reverted.\n- Integration test (autoCommit=false): staged files plus a non-empty message file → completes and the commit lands.\n- Integration test (autoCommit=false, run.review with repairedFiles): reviewer repairs are discounted by the gate, staged by the commit prompt, and land in the same commit as the executor's work.\n- Existing uncommitted-work-completion suite still passes; changeset for @n-dx/hench (patch).\n\nDepends on: the guard-calibration task (shared PRD_COMMIT_PATHS / tree-meta changes) — run that first so both edits to finalizeRun do not collide."
