description: "#539 item 2. Task 3 of 7. It depends on task 1 (`run-all-tests.mjs <label,…>` and the `test-gate: failed-suites=` line) and task 2 (the `hench.testGate` config group).\n\n**The problem.** In an unattended run, one failing test in one suite fails the gate and the run. The next attempt then starts from scratch. Run 5b8fc246 lost ~45 minutes to `tests/integration/scheduler-startup.test.js`, which passes 3/3 when run alone.\n\n**Today.**\n- `finalizeRun` (`packages/hench/src/agent/lifecycle/shared.ts:3485`) runs `runTestGate` (shared.ts:3636) in a loop of up to 5 attempts (:3632).\n- On failure it calls `promptTestGateFailure` (shared.ts:945). That returns \"abort\" at once when `!isTTY || yes || autonomous` (:951). So an unattended run never re-runs anything.\n- Abort sets `run.status = \"failed\"` and `run.error = \"Test gate failed [command: …]: …\"` (:3751-3764), then calls `settleAfterTestGateFailure` (:3803).\n- `run.testGate` is overwritten per attempt (:3643). Diagnostics `testGateOutputTail` / `testGateFailureDigest` are at :3657 and :3666.\n\n**Add `hench.testGate.rerunCommand`** (string, optional, no default). It is a template where `{suites}` is replaced by the failed suite labels, comma-joined. This repo will use `node scripts/run-all-tests.mjs {suites}`.\n\n**Behaviour.** When the gate fails and all of these hold:\n- the failure would auto-abort (the same `!isTTY || yes || autonomous` condition; leave the interactive rerun/abort/skip prompt as it is);\n- `rerunCommand` is set;\n- the gate's full stdout has a `test-gate: failed-suites=<list>` line with at least one label. Validate each label against `/^[A-Za-z0-9@/._-]+$/`; on any invalid label, skip the re-run;\n- the failure was not a timeout or a not-launched result;\n\nthen re-run once with `{suites}` substituted. Use the same timeout, `execShellCmd` and process-tree kill as the gate. Then:\n- **Re-run passes.** The gate passes. Record `testGate.flakyRerun: [{suite, firstFailure}]`, one entry per re-run suite. `firstFailure` is a one-line description of what failed the first time: the first failing test name from that suite's part of the output or the failure digest, capped at ~200 chars. Keep the first attempt's command, duration and failed suites as `testGate.firstAttempt`. Print a visible warning naming each flaky suite and its first failure, and append a rex log entry (event `test_gate_flaky_rerun`) so flakes stay visible. The run continues exactly as after a first-time pass: held resolution applied, commits, and so on.\n- **Re-run fails.** The gate fails as today. Record `testGate.rerun: {suites, passed: false, totalDurationMs}` and say in `run.error` that the failed suites failed again on a re-run. The diagnostics output tail and digest come from the re-run.\n- At most one re-run per gate. It must not compound with the existing 5-attempt loop, so put the re-run inside a single attempt.\n\n**Config registries.** Same set as task 2: the zod `HenchConfigSchema` testGate object, the `HenchConfig` type, `CONFIG_FIELDS`, `CONFIG_FIELD_META`, the `packages/core/config.js` HELP_TEXT test-gate block, and the `realistic` map in `tests/e2e/hench-config-gate-contract.test.js`. Add the TestGateResult type fields (`flakyRerun`, `firstAttempt`, `rerun`) in `src/schema/v1.ts`. `testGate` is an opaque passthrough in the zod run-record schema, so no zod change is needed for those.\n\nDo not change this repo's config files; the last task opts the repo in.\n\n**Tests** (integration, in `packages/hench/tests/integration/`, following `test-gate.test.ts`; use a fake gate command that keeps state in a temp file so it fails on the first call and passes on the second). Cover:\n1. Pass on re-run: the run completes and `flakyRerun` is recorded.\n2. Fail on re-run: the run fails and `rerun.passed` is false.\n3. No rerunCommand: unchanged.\n4. Interactive TTY path: unchanged, with no automatic re-run.\n5. Timeout: no re-run.\n6. No failed-suites line: no re-run.\n7. The re-run command receives exactly the failed labels.\n\n**Validation.**\n- `pnpm --filter @n-dx/hench exec vitest run <files>` plus `tests/integration/gate-holds-completion.test.ts` (the held resolution must still apply after a flaky pass) and `node_modules/.bin/vitest run tests/e2e/hench-config-gate-contract.test.js`.\n- Build hench and web.\n- Do not run the full suite."
