description: "Found by the closing soak (task 45bb2888) at commit c12a1f98. Run 1 of `pnpm test` under concurrent build load failed: `@n-dx/rex` red, 2 of 5401 tests, both in `packages/rex/tests/integration/prd-tree-atomic-writes.test.ts` — \"updateItem writes only the updated item and its parent\" (line 352) and \"no full-tree re-serialization on single-item add\" (line 375). Both died as `Test timed out in 30000ms`, not as assertion failures.\n\nThe assertions themselves are clean. The prior task in this feature replaced this file's raw 500ms latency budgets with file-set and file-count comparisons, and those are load-immune — a count of written files does not care how busy the machine is. What is load-sensitive is the fixture cost that surrounds them: each of these tests calls `saveDocument` on `createHierarchy(10, 10, 10)`, which writes roughly 1110 files to a real temp directory before the assertion is reached.\n\nMeasured on the soak machine (Intel Core Ultra 5 225F, 10 logical CPUs, 31.5 GB, Windows 11 26200, Node 24.16.0):\n\n| test | idle | under 2-worker tsc load |\n|---|---|---|\n| a single add writes the same files on a 1000-item tree as on a 6-item one | 2867ms | passed |\n| updateItem writes only the updated item and its parent | 4134ms | >30000ms (timeout) |\n| no full-tree re-serialization on single-item add | 2783ms | >30000ms (timeout) |\n\nThe whole file is 10.2s idle and was 79s under load.\n\nSo the headroom against rex's 30s `testTimeout` is about 7x at the worst test. TESTING.md's own tolerance for load is `BUDGET_MULTIPLIER = Number(process.env[\"NDX_TEST_TIME_MULTIPLIER\"] ?? 20)` — 20x. These tests are budgeted, implicitly and by accident, at roughly a third of the margin the repo documents for everything else, because nobody chose 30s with this fixture in mind; it is the package-wide default in `packages/rex/vitest.config.ts`.\n\nImplementation notes: the fix is the fixture size or the timeout, not the assertions — do not touch the file-set expectations, they are the point of the previous task. Two candidate directions, both needing measurement before either is committed:\n\n1. Shrink the hierarchy. `expect(fullTreeWrites).toBeGreaterThan(1000)` in the third test hard-codes the 1000-item scale, so that bound moves with the fixture. Check first whether a smaller tree still separates \"writes 2 files\" from \"re-serializes the tree\" — it almost certainly does, since the written-set assertions are exact and size-independent by construction.\n2. Give the three write-volume tests an explicit per-test timeout sized from the measured idle cost times the documented 20x, rather than inheriting the package default. TESTING.md permits a per-test timeout when a single test owns the risky path, and forbids raising one to turn an existing red green — this would be the former only if the measurement is recorded alongside it.\n\nReproduce with `node scripts/soak-under-build-load.mjs --runs=1`.\n\nConstraints that apply to every n-dx change: cross-package imports go only through the package's gateway module; orchestration scripts in packages/core spawn CLIs and never import packages; every user-facing change carries a changeset using the scoped package name with a patch bump; run pnpm preflight before opening the PR."
