Spawning goes through llm-client's exec helpers or an allowlisted entry in packages/core/child-process-allowlist.json.\n\nDeclaration: a checked-in `n-dx.graview.json` (`format: \"graview-document\"`, formatVersion 1; limits 40 kinds, 256 KB). Kinds: area, capability, constraint, change, task, release, zone, component, run, commit (file is a kind only when `--files` is passed). Fields carry status, priority, health, intent status (proposed/changing/met/revised/retired), tokens, timestamps. Edges (declared on the kind they leave, with `inverse` text): under (child to parent), dependsOn (capability), appliesTo (constraint), amends and touches (change to product node), blockedBy, discoveredFrom (change to item or run), shippedIn and plannedFor (change to release), ranFor (run to change or task), produced (run to commit), realizes (commit to capability, from N-DX-Item trailers), inZone (component or file to zone), crosses (zone to zone, from sourcevision crossings). Lenses: board (changes by status), plan (plannedRelease), timeline (runs by startedAt/finishedAt), blocks (blockedBy), coverage (capability rows x zone columns linked by realizes). Rules: start with two or three that mirror computed health only (an open fix change marks its targets defective; a met capability has at least one realizing commit); rex's v2-rules stay the schema of record, and a unit test fails when a rex v2 NodeType or ProductEdges key has no kind or edge in the document.\n\nProjection: `buildSnapshot(layout, {files?})` returns `{nodes: [{id, kind, ...fields}], edges: [{kind, from, to}]}` from `loadPrdModel` plus computeEdges/computeProductStatus/computeRealizedBy, zones.json/components.json/imports.json, and run records. Node ids are the rex ids, zone ids, run ids and commit shas as they are, so Graview's `search_graph` answers with n-dx's own identifiers. Output is sorted canonically (reuse the sourcevision canonical-sort approach) so two runs on an unchanged checkout are byte-identical. Default excludes file nodes; zones, components and entry points keep a repo this size inside Graview's comfortable scale.\n\nCLI (`packages/graview/src/cli.ts`, spawned by core as `ndx graview <sub> [dir]`): `emit` writes document.json and snapshot.json under the layout's graview dir (`.ndx/graview/` or `.graview/`; `ndx init` and `rex init` gitignore it); `check`, `describe`, `serve` and `mcp` run emit then spawn `graview <sub> document.json --seed snapshot.json` (mcp with `--read-only`), resolving the binary from `graview.bin` in config, then PATH, then `npx -y graview@0.1.19`.
