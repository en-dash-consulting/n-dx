description: "Make the Graview face of n-dx really good: very customized, still unmistakably Graview. The reference is ../bee-bot (a coworker's product on Graview, @graview/* pinned from npm). Its lesson: the scene views are all framework defaults; the feel comes from a declaration written as data (glance on every kind, a home written as blocks, record pages written as blocks, a brand derived from one accent, titled lenses that become places) plus a React pages face laid over the derived pages (own shell with a rail in the domain's words, custom home, a few hand-made record and list pages, read models in TypeScript where the rule language stops, generic list/record for everything else). Read bee-bot's docs/STYLE-GUIDE.md, docs/LIVING-UI.md and docs/UPSTREAM.md, and graview's docs/site/docs/skills/graview-pages.md (the ladder from derived pages to a product design), graview-lens.md and graview-worker-view.md before designing.\n\nTwo halves, two homes.\n\nHalf one, in n-dx, upgrades the adapter's `n-dx.graview.json` (the document format carries all of this as data; no React): glance and `page: {groups}` on every kind; `computed` expressions where they fit (open changes per capability, cohesion as percent, tokens per change); `brand` from one accent with a hue per kind, the n-dx mark, typography and radius; `views.home` as blocks (a headline sentence of counts: capabilities met of total, changes open, Inbox size; figures for spend and runs this week; areas as cards; recent runs and Inbox items as rows); per-kind `card`, `row` and `page` blocks for capability, change, zone and run; `pages: {order, hide, first}` so bookkeeping kinds (commit, component) are reachable but not in the way; and the lens set as titled places: a `columns` status board of changes, a `timeline` of runs, a `coverage` of capabilities x zones through the realizes path, a `coverage` of constraints x capabilities through appliesTo, a `calendar` of shipped changes by shippedIn date, and `blocks` places for \"Needs attention\" (violations, Inbox, defective capabilities) and \"Spend\". Copy voice is plain and in n-dx's words (capability, change, zone, run), never \"node\" or \"record\"; every empty state names the n-dx command that fills it, since acts are read-only until the SyncEngine task.\n\nHalf two, a sibling product repo `n-dx-graview` (beside bee-bot; `@graview/*` pinned from npm with the link:../graview switch bee-bot's scripts/graview.mjs provides; Vite; pages face as the front door, the scene at /scene): the app is built with `appFromOrCompile` from the document and snapshot that `ndx graview emit` writes, so the declaration has one source of truth in n-dx and the repo only adds React. It lays custom pages over the derived ones through `createPageRegistry`: a shell whose rail speaks n-dx (Product: areas, capabilities, constraints; Work: changes, Inbox, tasks, releases; Code: zones, components, crossings; Runs: runs, commits, spend; Needs attention with a count; Pictures from placesOf(app)); a custom home; record pages for capability (statement, criteria, status and health, changes grouped open/applied, realized-by commits and zones, binding constraints), change (intent, amendments with deltas, tasks, runs with tokens, PRs, shippedIn), zone (cohesion and coupling meters, members, crossings, capabilities realized here) and run (turns, files changed, tokens, commits); a changes list with status filter, search kept in ?q= and a current/past toggle; the generic list and record for every other kind. TypeScript read models (spend rollups, coverage of capabilities by zone, cohesion trend) live beside the pages, not in the declaration. Keep an UPSTREAM.md of framework workarounds as bee-bot does, and capture each as an item in ../graview's PRD.\n\nWiring: `ndx graview serve .` prefers the product app when `graview.app` in config names its checkout or build, and falls back to bare `graview serve` on the document otherwise. The PR in the n-dx stack carries half one and this wiring; the repo is created as part of the task. Scope guard: no custom scene views in this task (bee-bot shipped none and the defaults carry it); worker-script views only if a derived page cannot say something the data can."
