description: "Severity: high (a published package that fails at import). Verdict: must-fix — the fix is one line in an existing changeset.\n\n## The defect\n\nThe prompt-envelope work adds new public API to `@n-dx/llm-client`:\n\n- `packages/llm-client/src/prompt-diagnostics.ts` — new, 150 lines: `extractPromptSectionDiagnostics`, `promptSectionCosts`, `dominantPromptSections`, `formatPromptSectionCosts`\n- `assemblePromptText` in `packages/llm-client/src/runtime-contract.ts`\n- the matching re-exports in `packages/llm-client/src/public.ts`\n\nrex, sourcevision and hench all import that API. But no changeset added by this branch bumps `@n-dx/llm-client`. `.changeset/prompt-envelope-rex-sourcevision.md` — the changeset that describes this very work — bumps `@n-dx/rex`, `@n-dx/sourcevision`, `@n-dx/hench` and `@n-dx/core`, and omits the package the API was added to.\n\nOnly two changesets in `.changeset/` bump `@n-dx/llm-client`, and **both are already on main**: `harden-execshellcmd-windows-shell.md` and `sourcevision-ask-endpoint.md`.\n\n## Why the green check missed it\n\n`pnpm exec changeset status --since=origin/main` lists `@n-dx/llm-client` among the packages to be bumped, and CI passes. That is misleading: the bump comes from those two unreleased on-main changesets, not from anything this branch declares. The coupling is accidental.\n\n## Failure scenario\n\n`packages/rex/package.json` declares `\"@n-dx/llm-client\": \"workspace:*\"`, which the publish step rewrites to the **exact** version — not a range. So:\n\n- Today: llm-client is bumped 0.5.2 -> 0.5.3 by the unrelated on-main changesets, published with the new API, and rex@new pins 0.5.3. Safe, by coincidence.\n- If either of those changesets is dropped, reverted, or released in a separate cycle: llm-client stays at 0.5.2, and published `@n-dx/rex` pins `@n-dx/llm-client@0.5.2` exactly — a version with no `assemblePromptText` and no `prompt-diagnostics`. A fresh `npm i -g @n-dx/rex` then fails at import with `SyntaxError: The requested module '@n-dx/llm-client' does not provide an export named 'assemblePromptText'`, and `rex analyze` is dead on arrival. Same for `@n-dx/sourcevision` (also `workspace:*`) and `@n-dx/hench`.\n\nThe blast radius is every prompt-building path in three published CLIs, and the trigger is an ordinary release-management action on an unrelated changeset.\n\n## Reachability (Pass 2)\n\nReachable by release sequencing, not by code. Not detectable by any current check: `changeset status` is satisfied by the accidental coupling, and no test asserts that a package whose `src/` changed is named in a changeset.\n\n## Solution options\n\n1. **Add `\"@n-dx/llm-client\": patch` to `.changeset/prompt-envelope-rex-sourcevision.md` (recommended).** One line, in the changeset that already describes this work, so the declaration sits with the change that created the dependency. Per CLAUDE.md's Changeset Versioning rules: patch, scoped name.\n\n2. **Add a separate changeset for llm-client.** Equivalent effect; worse locality — a future reader of the envelope changeset still would not see that llm-client is part of it.\n\n3. **Additionally, guard the class.** A CI check that every package with changes under `packages/<pkg>/src/` on the branch is named in some changeset would have caught this and will catch the next one. Larger than this fix and should be its own task; noted here so the option is not lost.\n\nRecommendation: option 1 now. Option 3 is worth capturing separately if the team wants the class closed.\n"
