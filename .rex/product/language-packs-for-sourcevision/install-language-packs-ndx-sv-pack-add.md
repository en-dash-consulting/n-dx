Decision 7 (LS9), second half: new languages are opt-in, "installed with a sourcevision command or from an offline tarball, and the project's .n-dx.json can list the packs it wants". 12a built the per-user pack directory (`<resolveNdxHome()>/packs/<sourcevision version>/`, `defaultPackDir()` and `packInstallCommand()` in packages/sourcevision/src/language/pack-loader.ts) and the loader that reads it; 12b gives users the commands. Brief: workshop analysis/language-scaling/pr12-runtime-and-packs-brief.md, section 12b.

Known packs: java, go, sql, terraform (`@n-dx/lang-<id>`, version always equal to sourcevision's). Analysis loads only Java and Go today (KNOWN_PACKS in pack-loader.ts); `pack add` accepts all four.

Rules for every task:
- No core change: `ndx sv <args>` already passes through to sourcevision's CLI (packages/sourcevision/src/cli/index.ts).
- Every new child process (npm, tar) goes through @n-dx/llm-client's spawn helpers and is registered where tests/e2e/shell-spawn-inventory-policy.test.js expects; tests inject the runner and never touch the network or the user's real ndx home.
- No dependency added to any package.json (agents cannot run `pnpm install`); if one seems needed, stop and say so.
- Analysis output stays byte-identical when no project pack list is set (the default).
- Do not touch rex, hench, core or web source.

Gates after every task (rebuild first): sourcevision and every lang-* suite; the root policy suites (architecture-policy, domain-isolation, instruction-alignment, layout-literal-policy, agents-md-size-budget, vitest-hidden-spawn-policy, prd-line-endings, ci-merge-queue-trigger, iso-skill-drift, shell-spawn-inventory-policy, wall-clock-inventory-policy, obfuscated-code-policy). The root AGENTS.md chain has about 119 bytes of headroom (agents-md-size-budget): document the commands in packages/sourcevision/AGENTS.md and docs, not in the root guidance.

Side stack, PR 12b, cut from 12a's tip 3e5e37544.
