Decided with Sterling H on 2026-10-12 (all nine decisions): sourcevision becomes a language-neutral engine, and languages and frameworks arrive as packs on top of a new foundation-tier package, @n-dx/lang-kit. This feature creates the package with no dependencies beyond Node, moves sourcevision's pure language facts into it, defines the facts-out pack contract there, and makes sourcevision use it. Analysis output must stay byte-identical.

This supersedes the epic's earlier rule "no new package, the pack interface stays inside sourcevision": the new package is @n-dx/lang-kit, and the architecture policy tests change to admit it as foundation tier. The epic's other rules still apply.

Out of scope (later PRs): the parser runtime package, per-language pack packages, `ndx sv pack add` and opt-in installs (PR 12). Resolvers (java-resolver.ts, go-resolver.ts), runner.ts, pack.ts's loader, the *-pack.ts files, queries, grammars and the SQL modules stay in sourcevision. The Terraform model (PR 13). rex, hench, core and web adoption of lang-kit, including 9b692c8a (one go.mod parser), happens later off main: do not touch rex, hench, core or web source. No language SDK or toolchain may be required at run time (LS16).

The bar for every task: analysis output byte-identical (every language-pack golden and analysis fixture), and the Java and Go corpus reports give PR 10's numbers (Java 99.93% clean parse; Go on gitea 98.69% clean, import parity 3130 of 3131).

Gates after every task (rebuild first with `pnpm build`):
- `cd packages/lang-kit && npx vitest run`
- `cd packages/sourcevision && SV_REQUIRE_GRAMMARS=1 npx vitest run`
- `npx vitest run --config vitest.config.js tests/e2e/{architecture-policy,domain-isolation,instruction-alignment,layout-literal-policy,agents-md-size-budget,prd-line-endings,ci-merge-queue-trigger,iso-skill-drift}.test.js`
- The epic's static policy tests: shell-spawn-inventory-policy, wall-clock-inventory-policy, obfuscated-code-policy.
