Roadmap PR 35, stack B (v2 Migration Path, card B1), based on roadmap PR 34 (feature b86f9199). On a v2 tree, ndx work cannot select, brief or complete a task: hench selects with the v1 findNextTask, briefs from the v1 item chain, writes status and completion through the v1 store, and its completion gate reads product/ and changes/ writes as leaked work. This feature makes hench select with rex's findNextWork, brief from buildChangeBrief, write status, completion and claims through rex's v2 transaction, and treat the v2 folders as PRD bookkeeping, all through packages/hench/src/prd/rex-gateway.ts.

Overlap: this overlaps Hal's feature 20d12416 ("Agent brief from the product layer") and its task 6daf36b5 ("Let agents read capabilities and place follow-ups; run task-less changes"). Ryan owns this work by decision D7 of the v2 Migration Path (2026-10-12).

Design boundary (roadmap PR 35, stack B; every change is checked against it):
- Lane files: packages/hench (src and tests), plus the two root tests tests/e2e/architecture-policy.test.js (gateway export ceiling, with a "Raised from X to Y for …" description entry) and tests/integration/cross-package-contracts.test.js.
- Not rex and not web. hench consumes rex only through its public API (packages/rex/src/public.ts, as exported by roadmap PR 34 task T6), and only through packages/hench/src/prd/rex-gateway.ts (re-export only, no logic; type imports through the gateway too). If something hench needs is not exported by rex, stop and report it rather than editing rex.
- v1 trees keep today's behaviour exactly: this repository's own PRD is v1 and hench works on it every day; existing v1 tests pass unedited.
- On a v2 tree (rex's prdLayout reports "v2") hench never writes through a v1 FileStore and never writes prd_tree/.
- Fixtures: packages/rex/tests/fixtures/v2-tree (copy it to a temp dir before any test that writes).
- Add a patch changeset for @n-dx/hench. Never major.

Decisions (assumed overnight 2026-10-12, Ryan to confirm): stack A's Q1–Q4 hold (resolveStore dispatches on layout; v1 field names kept with optional v2 fields; #648 not merged, so rex exports only what hench and web need). `--epic-by-epic` refuses on v2 rather than mapping epics to changes (the epic level does not exist on v2; mapping is a later decision).
