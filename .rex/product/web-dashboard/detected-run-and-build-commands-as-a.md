When the project has a discoverable run command — `npm run dev`, `python3 file.py`, `cargo run`, `go run .` — surface a "found run command" button next to Live, with a dropdown to change or edit the command and to pick build commands too. Running one shows a spinner, then reports success or failure. If the command serves on localhost, give the user a link to open it.

Requested as an idea rather than a defect, so the shape is open.

Detection — extend what exists rather than writing a second detector. `packages/core/readme-generator.js` already reads manifests across ecosystems and derives commands from them: `readManifest` handles `package.json` scripts, Python, Go and Rust (see the manifest branches around `:90-181`), and the deriver at roughly `:208-245` returns `installCommand`, `testCommand` and `packageManager`. It does not yet derive a run/dev command or a build command — that is the gap to fill.

Note the tier boundary rather than deciding it here: `readme-generator.js` is orchestration-tier core, and the dashboard is the web package, which under the repo's rules reaches other packages through a gateway or by spawning. Whether the detector moves, is spawned, or is reimplemented behind `packages/web/src/server/domain-gateway.ts` is an architecture call for the implementer.

Execution — the infrastructure to follow already exists for analysis runs in `packages/web/src/server/routes-commands.ts`: `handleSvAnalyze` spawns a binary under a write lock, returns 202 for async work, and is paired with `/status` and `/stop` endpoints, with the job surfaced through `hooks/use-active-operations.ts` and progress through `routes-live-analyze.ts`. A long-running dev server is not the same shape as a one-shot analyze — it does not finish — so lifecycle needs thought: a build command completes and reports, a dev server stays up and needs a stop control and a way to not leak a process when the tab closes.

Localhost link: detect the bound port from the child's stdout rather than assuming one, since the port is frequently chosen at runtime or shifted when busy.

Safety note worth settling early: this runs project-defined shell commands from a web UI. The dashboard is already token-authenticated (`X-Ndx-Token`), and the command set should come from detected manifest entries rather than free-form input, or the edit box becomes arbitrary command execution over HTTP.
