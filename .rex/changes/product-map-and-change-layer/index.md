- Hotfix · Skip CI on draft pull requests (d94e33aa-d512-41c7-88fb-20d7557d2d5b)
  We are running out of GitHub Actions build minutes. Every push to a draft PR runs the full CI matrix (ubuntu + macOS + Windows; macOS bills at 10x Linux), plus CodeQL and Dependency Review. Drafts cannot merge, so those runs buy nothing.

  Fix: gate each PR-triggered job on the PR not being a draft, and add the `ready_for_review` trigger type so the full run fires the moment a PR is marked ready.

  Workflows that run on pull_request today:
  - .github/workflows/ci.yml: jobs `build` (matrix: "Build & Validate", "CLI Smoke (macOS)", "CLI Smoke (Windows)") and `smoke-parity` ("CLI Smoke Parity", needs build). Also triggers on push to main and merge_group.
  - .github/workflows/codeql.yml: job `analyze`. Also push to main and a weekly schedule.
  - .github/workflows/dependency-review.yml: job `dependency-review`. pull_request only.
  docs.yml and release.yml do not run on PRs and are out of scope.

  THE TRAP (read before editing): `if: github.event.pull_request.draft == false` alone is wrong for ci.yml and codeql.yml. On push, merge_group and schedule events `github.event.pull_request` is null, `null == false` is false, and the job would be SKIPPED on main and in the merge queue. The merge queue would then wait forever on its required checks. Use:
    if: github.event_name != 'pull_request' || github.event.pull_request.draft == false

  Trigger types: replace the bare `pull_request:` with
    pull_request:
      types: [opened, synchronize, reopened, ready_for_review, converted_to_draft]
  The first three are GitHub's default set, so nothing that runs today stops running. `converted_to_draft` starts a run whose jobs all skip; in ci.yml the existing `concurrency: ci-${{ github.ref }}` with cancel-in-progress then cancels the in-flight full run, which saves the rest of its minutes.

  Billing: a job whose job-level `if:` is false never gets a runner and is not billed. The workflow run still appears in the Actions tab with skipped jobs; that is expected.

  Required checks: for a draft PR the matrix job is skipped before expansion, so the required checks ("Build & Validate", the two smoke legs, "CLI Smoke Parity") show as Expected/pending instead of passing. That is fine (a draft cannot merge) and they report once the PR is marked ready. Do not rename any job or check name; tests/e2e/ci-merge-queue-trigger.test.js pins them.

  Conventions (every task in this epic):
  - Branch: hotfix/draft-pr-ci-gate (this worktree), cut from main. One PR for the epic.
  - Workflow and test edits only. No package source changes, so no changeset (ci.yml's "Require changeset" step skips PRs that touch no packages/ source). Do not add an empty changeset.
  - Read workflows as text in tests, no YAML dependency, matching tests/e2e/ci-merge-queue-trigger.test.js.
  - Keep the existing comment style in the workflow files: a short comment above the new `if:` and `types:` saying why.
  - Before declaring done run `pnpm vitest run tests/e2e/ci-merge-queue-trigger.test.js tests/e2e/ci-draft-pr-gate.test.js` and the required tests tests/e2e/cli-dev.test.js and tests/integration/scheduler-startup.test.js.
