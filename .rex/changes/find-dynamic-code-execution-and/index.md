intent: "PR 10 of the PHP language-pack stack, stacked on PR 9 (#1078). It comes from the 2026-11-16 client call. The client's estate is a custom PHP app that uses WordPress-like patterns: some application routing lives in the database rather than in files, and whole parts of sites are stored as PHP code in database rows. Static analysis can't read the rows, but it can find every place the code runs strings as code or picks what to run from data. When that data comes from a query, it can name the tables and columns. A private dump scanner and a runtime trace, both outside this repository, then check those rows.\n\nTwo parts:\n1. **Dynamic execution and dispatch sites.** eval, string assert, preg_replace /e, create_function, variable includes, call_user_func(_array), variable functions, `new $class`, `$obj->$method()` and `$class::$method()`.\n2. **Database-driven dispatch.** A database query result that reaches one of those sites, in the same function or top-level scope or through repository functions that return query results, with the query's tables and columns when its SQL is literal.\n\nLane rules (PHP pack; decisions made 2026-11-12):\n- Facts record locations, names, tables and columns only, never row data or string contents beyond the expression as written.\n- Per-site details reuse the pack's notice mechanism with locations, as `php-include-notices.ts` does for dynamic includes. Per-repository counts go beside `versionFloors` and `legacyConstructs` in the PHP ecosystem section of sdlc-profile (`packages/sourcevision/src/analyzers/pack-ecosystem.ts`), as optional fields. Hal reviews the field names.\n- Analyze output stays byte-identical for every repository without PHP files, and for PHP repositories without the pack.\n- Do not change sourcevision MCP tool names, required parameters or response shapes.\n- Agents cannot use the network, run `pnpm install`, read `~/.cache`, or write under `.claude/`. The operator does those steps.\n- Corpus analyze runs use `--fast`, and the operator resets the corpus checkout afterwards.\n- Record measurements with append_log on the task.\n- Patch changesets with scoped package names, at the current fixed-group version.\n- Before finishing, run the six static root policy tests: tests/e2e/architecture-policy.test.js, domain-isolation.test.js, shell-spawn-inventory-policy.test.js, wall-clock-inventory-policy.test.js, layout-literal-policy.test.js, obfuscated-code-policy.test.js."
