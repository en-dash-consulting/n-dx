description: "Builds on the previous task's sites and PR 6's database facts (`php-outbound.ts` database calls, `php-sql.ts` table names from literal SQL).\n\n**Sources.** A value is database-derived when it comes from any of these:\n- a fetch on a query result: `mysql_fetch_*`, `mysql_result`, `mysqli_fetch_*`, `mysqli_result::fetch_*`, `PDOStatement::fetch*`, `pg_fetch_*`, `oci_fetch_*`;\n- a direct result accessor on a known database client (`->fetchColumn`, `->fetchAll`, `->get_var` / `->get_row` / `->get_results` / `->get_col` on a variable that holds a database client);\n- a call to a repository function or method whose return value is database-derived. Compute these summaries across the repository by resolved name, iterating to a fixed point with a bound. Precedent for cross-file resolution: `php-resolver.ts`.\n\n**Flow.** Within one function, method or top-level scope:\n- assignment, array access (`$row['handler']`), `foreach` over a result, `list()` / `[...]` destructuring, string concatenation and interpolation;\n- parameters of the enclosing function are not sources.\nKeep it a simple forward pass. When a variable can't be decided, prefer missing a flow over guessing one.\n\n**Output.** Each execution or dispatch site fed by a database-derived value is reported as database-driven:\n- a notice code such as `php-db-dispatch` / `php-db-exec`;\n- the source position;\n- the tables and, when the SELECT list is literal, the columns. `SELECT handler FROM pages` gives `pages.handler`; `SELECT *` gives the table only.\n\nAdd database-driven counts to the per-repository `dynamicCode` field.\n\nFixtures, modelled on a custom app with WordPress-like patterns:\n- a `pages` table whose `handler` column is dispatched with `call_user_func`;\n- a `blocks.body` column passed to `eval`;\n- a router that loads a row in one function (`get_route($path)`) and dispatches it in another;\n- a parameter-fed eval, which must not be marked database-driven.\n\n**Operator note:** after the run, analyze the Drupal 7 corpus app with the worktree CLI and `--fast`, then reset its checkout (`git checkout -- .gitignore`, and clean `.sourcevision/`). Confirm and log with append_log:\n- `menu_execute_active_handler`'s `call_user_func_array` on the router item from `menu_get_item` (`menu_router`) is reported as database-driven;\n- `php_eval` is reported as an execution site.\nAlso log the database-driven and total site counts for osCommerce 2, WordPress and CodeIgniter 3.\n\n**Operator note (the Drupal 7 shape the check needs, read by the operator 2026-11-16):** in `includes/menu.inc`:\n- `menu_get_item($path = NULL, $router_item = NULL)` loads the row with `$router_item = db_query_range('SELECT * FROM {menu_router} WHERE path IN (:ancestors) ORDER BY fit DESC', 0, 1, array(...))->fetchAssoc();`. That is a `fetch*` method called directly on the result of a query call (Drupal's `db_query` / `db_query_range` are already in `PHP_SQL_FUNCTIONS`, and `php-sql.ts` drops the `{table}` braces).\n- It then caches the row in a static array and returns the element: `$router_items = &drupal_static(__FUNCTION__);` at the top, later `$router_items[$path] = $router_item;`, and finally `return $router_items[$path];` (other paths `return FALSE`). The parameter `$router_item` is also written into `$router_items[$path]` on one branch; that write is parameter-fed, not database-derived.\n- So: assigning a database-derived value to an element (`$a[$k] = $row`) makes the array database-derived, and a reference assignment from an unrelated call before it (`$a = &drupal_static(...)`) must not clear that. A function counts as returning database-derived values when any of its `return` expressions is database-derived.\n- `menu_execute_active_handler($path = NULL, ...)` receives the row through an assignment inside an `if` condition, `if ($router_item = menu_get_item($path)) {`, and dispatches `call_user_func_array($router_item['page_callback'], $router_item['page_arguments']);` inside nested `if` blocks. Assignments in conditions count.\n- Expected result: that call is database-driven with table `menu_router` and no columns (`SELECT *`).\nAdd a hand-written fixture of this shape (static cache array, assignment in an `if` condition, `fetchAssoc` on a `db_query_range` result) beside the WordPress-like ones. `php_eval` in `modules/php/php.module` is a plain `eval` on its parameter: an execution site, not database-driven."
