summary: "Drupal keeps most of its PHP in .module and .install files, which n-dx lists as PHP but never reads, so their eval calls, classes and includes are missing from the report."
description: "Operator finding from the PR 10 Drupal 7 corpus check (2026-11-16, `sv analyze --fast` with the worktree CLI). `php_eval` in `modules/php/php.module` (`print eval('?>' . $code);`) and `locale.module`'s `@eval(...)` are not reported. The cause is `phpConfig.parseableExtensions` in `packages/lang-kit/src/php.ts`: it leaves out `.module` and `.install`, so the pack never parses Drupal module files, and every pack rule (symbols, imports, includes, entry points, outbound, config, compat, dynamic code) misses them. A scratch probe confirmed that `print eval(...)` and `@eval(...)` are reported in a `.php` file.\n\n**Change:** add `.module` and `.install` to `phpConfig.parseableExtensions`.\n- They are already in `phpConfig.extensions` and count as PHP only in a repository detected as PHP (`PHP_REPOSITORY_ONLY_EXTENSIONS`). Keep that, and keep detection from counting them.\n- Do not add `.theme`, `.profile`, `.engine` or `.test`; they are not inventoried today.\n- PR 2's corpus report showed `.module` and `.install` files parse 186/186 clean.\n- Check everything else that reads the parseable list: sourcevision's parse selection, lang-runtime's pack file filter, tests that enumerate PHP parseable extensions, and docs that list them (lang-kit and lang-php AGENTS.md, sourcevision docs). Update the doc comment in php.ts.\n\n**Tests:** a lang-php integration fixture with a Drupal-style `.module` file holding an `eval` on a parameter and a class declaration referenced from a `.php` file.\n- The exec site is reported.\n- The class resolves to the `.module` file, not a `php:` external (the FieldException case from the parent Inbox change f852a948).\n- A `.module` file in a non-PHP repository stays unparsed and not PHP.\n- Update goldens through `test:update-goldens` if they move.\n\nNon-PHP repositories and PHP repositories without the pack stay byte-identical.\n\nLane rules from change ec248078 apply: no network, no `pnpm install`, no `~/.cache`, no writes under `.claude/`; a patch changeset with scoped names at the fixed-group version 0.10.4; run the six static root policy tests (tests/e2e/architecture-policy.test.js, domain-isolation.test.js, shell-spawn-inventory-policy.test.js, wall-clock-inventory-policy.test.js, layout-literal-policy.test.js, obfuscated-code-policy.test.js) before finishing.\n\n**Operator note:** after the run, the operator re-analyzes Drupal 7 with `--fast` and confirms `php_eval` is an exec site."
