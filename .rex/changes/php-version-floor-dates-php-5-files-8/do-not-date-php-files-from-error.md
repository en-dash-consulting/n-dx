description: "Found by the operator's corpus check of PR 8 (2026-11-16), probing `pack.analyzeProject({ kinds: [\"versionFloor\"] })` from @n-dx/lang-php over the PHP 5 corpus apps. Two rule families in packages/lang-php/src/php-compat.ts / queries/php-compat/compat.scm give PHP 5 files a PHP 8.0 floor:\n\n1. Parser error recovery dates code. In files that use curly-brace string offsets (`$var{$c}`, which tree-sitter-php cannot parse), error recovery yields nodes the `named-arguments` rule matches although the source has no named argument:\n   - wordpress wp-includes/class-json.php: floor 8.0 named-arguments at line 254 col 4 (the file has 30 `$var{$c}` offsets, e.g. line 319 `ord($var{$c})`);\n   - wordpress wp-includes/ID3/getid3.php: floor 8.0 named-arguments at line 464 col 11 (`} catch (Exception $e) {`).\n   Fix: a syntax hit whose node lies inside, or has as ancestor or immediate sibling, an ERROR or MISSING node does not date the file. Check every rule that could match recovered nodes this way, not only named-arguments. A rule hit in a clean part of the same file still counts.\n\n2. One-line attributes are comments before PHP 8.0. `#[...]` written on its own line, with nothing after the closing `]` but whitespace or a comment, is a `#` line comment to PHP < 8.0, so the file still runs there. Drupal 7 adds `#[\\ReturnTypeWillChange]` and `#[AllowDynamicProperties]` this way on purpose to stay PHP 5 compatible, and five of its files get floor 8.0 (`attributes`): includes/bootstrap.inc:362, includes/database/database.inc:2265, includes/database/prefetch.inc:271, includes/database/query.inc:1738, includes/filetransfer/filetransfer.inc:12. Fix: the `attributes` rule dates only an attribute group that would not be a whole-line comment before 8.0: one that spans lines, or one followed on its line by code (e.g. `#[Attr] public function f() {}`). Cite the attributes section of https://www.php.net/manual/en/migration80.new-features.php as today; describe the one-line exception in the rule's comment and in docs/packages/sourcevision.md#php-pack-rules.\n\nFixtures under tests/fixtures/php-compat/ (a new subfolder, so the one-fixture-per-rule check is unaffected): a PHP 5 file using `$s{0}` with the class-json.php shape (a `function encode($var) {` after the offsets) that must get no floor; a file with `#[\\ReturnTypeWillChange]` alone on a line above a method (no floor); a file with `#[Attr] function f() {}` on one line (8.0); a file with a multi-line attribute group (8.0).\n\nOperator note: the agent cannot read ~/.cache; the line references above come from the operator's probe. Keep every rule's version boundary and source as they are."
