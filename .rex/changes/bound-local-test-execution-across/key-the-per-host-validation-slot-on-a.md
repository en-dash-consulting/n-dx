summary: "The shared test-run slot is now named after the computer's network name, which macOS changes when the network changes. Two test runs on one machine could then run at once. This names the slot after a machine identifier that never changes, and keeps nested runs pointed at their parent's slot."
description: "Fixes change a3e16b11 (\"A hostname change mid-run splits the host validation slot\"), found by the review of task 24e3c609. Read that change's intent and acceptance criteria; this task carries them out inside PR 2 (#1034), because the regression comes from 24e3c609's per-host directory.\n\nProblem: `resolveValidationSlotDir` in `packages/hench/src/process/validation-slot-dir.ts` keys the slot on `os.hostname()`. On macOS without a fixed HostName, that follows DHCP or reverse DNS and changes with the network (`ryans-mbp.local` → `ryans-mbp.lan`). A run started after the change uses a different directory and runs beside the current holder. A nested acquire whose resolved directory differs from its parent's would miss the parent's token too.\n\nFix:\n1. **Stable host identity.** Resolve once per process and cache the result:\n   - Linux: `/etc/machine-id`, else `/var/lib/dbus/machine-id`;\n   - macOS: `IOPlatformUUID` from `ioreg -rd1 -c IOPlatformExpertDevice`, run with `execFileSync`, no shell, with a short timeout;\n   - Windows: `MachineGuid` from `reg query HKLM\\SOFTWARE\\Microsoft\\Cryptography /v MachineGuid`, with a short timeout;\n   - otherwise, or on any failure: `os.hostname()`.\n\n   Use a short hash of the id as the directory name, e.g. the first 16 hex chars of sha256, prefixed `m-` (or `h-` for a hostname fallback), so no raw machine id lands on disk. Keep an injectable identity for tests. Keep `validationSlotHostDirname` only if still needed.\n2. **Nested runs use their parent's directory.** When hench holds a slot it already exports `NDX_VALIDATION_SLOT` (the token) to the command. Also pass the absolute slot directory in a new variable, e.g. `NDX_VALIDATION_SLOT_DIR`, set and cleared beside the token everywhere the token is. A nested acquire uses that directory when present, before resolving its own. Check `guard` env stripping and the sandbox env pass-through so the new variable reaches the runner exactly where the token does.\n3. Update the protocol header in `validation-slot.ts` (the spec PR 3's `scripts/lib/validation-slot.mjs` mirrors) and the docs that name the slot path (TESTING.md, docs/guide/configuration.md, docs/packages/hench.md) to describe the machine-id directory and the nested-dir variable.\n\nTests:\n- two resolves with different injected hostnames but the same machine id give the same directory;\n- the fallback to hostname when no machine id is readable;\n- the directory name never contains the raw id;\n- a nested acquire with `NDX_VALIDATION_SLOT_DIR` set nests even if its own resolution would differ.\n\nAfter the work, close change a3e16b11 as done by this task (the resolution names this task's commit).\n\nOperator notes: you are on macOS; the Linux and Windows branches are reasoned, so unit-test them through the injected readers. Run the slot and slot-dir tests, `tests/integration/test-gate.test.ts`, the sandbox profile tests if touched, and the static root policy tests. Add a patch changeset for `@n-dx/hench`. Do not edit `scripts/lib/validation-slot.mjs`: it does not exist on this branch, and PR 3 mirrors the change. No `process.env.NDX_*` writes in tests."
