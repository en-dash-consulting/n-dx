description: "Story 50b (contract half, part 2 of 3; security-bearing; Sidecar design §17.2). The frame key belongs to the proxy (XT2). New hub route POST /api/hub/extensions/:name/frame?project=<id> (also reached as /p/<id>/api/hub/extensions/:name/frame, the same rewrite the links fetch uses), behind the hub token and request-guard and the loopback-Origin rule for mutating requests, answering { apiVersion, url, expiresAt } where url is /x/<name>/~f/<key>/<resolved sidecarTab path>. The hub sends the finished URL: no gateway export, no ceiling raise. Keys: at least 32 random bytes, base64url, held only in the hub's memory; bound to the extension (the project is recorded and used to fill the URL); expire after the extension's idleStopMinutes without use (sliding) with a hard cap; dropped on disable, remove, revoked approval or hub restart (XT3). The proxy accepts /x/<name>/~f/<key>/... in place of the hub token only when the key is live and bound to <name>; it strips ~f/<key> before forwarding, sets X-Ndx-Base-Path: /x/<name>/~f/<key>/, still strips every hub credential, and adds Content-Security-Policy: sandbox allow-scripts allow-forms allow-popups allow-downloads and Referrer-Policy: no-referrer to every keyed response, so the page has an opaque origin even when opened full-window. WebSocket upgrades follow the same rules. src/hub/ imports nothing from src/server/ or src/viewer/; exec only through hub/exec-gateway.ts. src/hub/AGENTS.md gets at most one pointer line; the reasoning goes to docs/extensions/hub-api.md (or docs/architecture/extensions.md, whose open question about embedding is answered for the drawer only). Do not add to packages/web/AGENTS.md or packages/web/src/server/AGENTS.md (at the Codex size budget)."
