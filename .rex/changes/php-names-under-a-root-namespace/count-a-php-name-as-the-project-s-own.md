summary: "When a project and an outside library share the same top-level namespace (MediaWiki and the wikimedia packages, or a company's apps and its shared private package), n-dx counts the library's classes as missing project classes. Deciding by the whole namespace puts them back among the outside packages."
description: "Fix found by the operator's hand-check of the php-resolve-report sample (run 9d846e7f, logged on task 461493c0). In packages/lang-php/src/php-resolver.ts, resolveReference returns unresolved internal-not-found whenever Index.isOwn(qualified) is true, and isOwn compares only the first namespace segment (headOf) with the project's declared namespaces, classes and autoload prefixes. On mediawiki the project declares Wikimedia\\Rdbms, Wikimedia\\Stats and plain Wikimedia, so Wikimedia\\Assert\\Assert, Wikimedia\\Timestamp\\ConvertibleTimestamp and Wikimedia\\Parsoid\\Parsoid (Composer packages wikimedia/assert, wikimedia/timestamp, wikimedia/parsoid; no lock, no vendor) count as 5436 internal-not-found references: no edge and no php:Wikimedia external. A client repository that uses a shared private package under the company's root namespace (Acme\\Shared beside its own Acme\\Billing) loses those references the same way.\n\nChange the rule: a namespaced name is the project's own only when its namespace (the qualified name without its last segment) equals a namespace the project declares, or a project PSR-4/PSR-0 autoload prefix covers the name. An un-namespaced name is the project's own when it is declared, or its PSR-0 prefix is a project prefix (zf1's Zend_ must stay internal-not-found for Zend_Gdata_YouTube). Everything else that does not resolve is an external named per D5 (php:<first segment>, module from composer.lock as today). Update the module doc comment in php-resolver.ts, the sourcevision AGENTS.md lines that describe the rule, and add a patch changeset for @n-dx/lang-php.\n\nTests: a fixture where the project declares Acme\\Billing\\Invoice and references Acme\\Shared\\Money (not in the project): it becomes the external php:Acme; a reference to a missing Acme\\Billing\\Missing stays internal-not-found; a project autoload prefix still marks names under it as internal.\n\n**Operator note, 2026-11-14:** you cannot read ~/.cache; the operator re-runs php-resolve-report.mjs on the corpus after the run. Expect mediawiki's internal total to drop by most of the 5436 Wikimedia references and php:Wikimedia to appear among its externals; zf1, cakephp2, koel and symfony-demo rates should not move. Run `npx vitest run` inside packages/lang-php, plus packages/sourcevision/tests/integration/php-pack-imports.test.ts. Never commit anything under any package's build/."
