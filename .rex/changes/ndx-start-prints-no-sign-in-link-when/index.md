intent: "Found on 2026-11-05 registering a fresh project (terrarium_site) with a running hub on Windows, from a source-linked install (the global `ndx` shim execs `packages/core/cli.js` in the n-dx checkout).\n\n## Symptom\n\n`ndx start .` registers the project and reports it healthy, but prints:\n\n    (could not get a sign-in link from the server; run 'ndx start' again, or restart the server if it predates this ndx)\n\nso the printed URL carries no `ndx_nonce=` and the browser cannot sign in. The per-user token (`<ndx home>/auth.token`) exists and is fine — the token is per user, not per project; what fails is minting the one-time landing nonce.\n\n## Cause: CLI/hub version skew in a source-linked install\n\n- `packages/core/web.js` is plain JS run from source, so it is always at HEAD. Since `2b16b07f0` (2026-11-02, \"contain agent execution and protect dashboard credentials\") it mints the landing nonce with `POST /api/auth/nonce` to the hub root (`mintLandingNonce` via `credentialedHubRequest`).\n- The hub and project servers are spawned from `packages/web/dist`, which was last fully built 2026-10-29 — before that commit. The built hub has no `/api/auth/nonce` route at all (no `AUTH_ROUTES` / `api/auth/nonce` anywhere in `packages/web/dist`).\n- With several projects registered (25 here) the stale hub routes the root request through its project proxy and answers `409 \"Several projects are registered; address one as /p/<id>/…\"`; `/p/<id>/api/auth/nonce` answers `404`. With one project it would be proxied to an equally stale project server. Either way `mintLandingNonce` gets null and `NO_NONCE_NOTE` is printed.\n- `isBuildCurrent()` from `scripts/lib/stale-dist.mjs` reports web, core, rex, sourcevision and hench all stale in that checkout.\n\n## Why nothing caught it\n\n- Build-stamp freshness (`dist/.build-stamp.json`, `scripts/lib/stale-dist.mjs`) is consulted only by the test harness (`tests/e2e/verify-build.js`, `scripts/run-all-tests.mjs`), never at run time by `ndx start`.\n- `/api/hub/health` returns `{ok, pid, port, startedAt, registryPath, projects}` — no version or build identity — so `ndx start` cannot tell it is talking to an older hub.\n- `NO_NONCE_NOTE`'s advice (\"run 'ndx start' again, or restart the server\") cannot work: a restart respawns the same stale `dist/`. Only rebuilding `packages/web` fixes it.\n\n## Secondary: misleading status before registration\n\nBefore the project was registered with the current hub, `ndx start status .` printed \"No background server recorded.\" and \"Note: Port 3117 is in use by another process.\" — although the occupant was this user's own hub on its default port. It should say the hub is running and this project is not registered with it.\n\n## Repro\n\n1. Link `ndx` to an n-dx checkout whose `packages/web/dist` predates `2b16b07f0` (or is otherwise stale against `packages/web/src`), with `packages/core/web.js` at or after that commit.\n2. Have the hub running with two or more projects registered.\n3. `ndx start .` in another project → registered/healthy, no `ndx_nonce=` in the URL, `NO_NONCE_NOTE` printed.\n4. `curl -X POST -H \"X-Ndx-Token: <token>\" http://127.0.0.1:3117/api/auth/nonce` → 409; `.../p/<id>/api/auth/nonce` → 404.\n\nWorkaround: rebuild (`pnpm build` in the checkout), then `ndx hub stop` and `ndx start .`."
