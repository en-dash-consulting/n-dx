intent: "Verdict: should-fix (severity low). Found by the adversarial review of task 99e2bdb7 (run 0ec3cfdc).\n\nThe Sidecar transcript decides a card-less call failed from `toolResultIsError(output)` (packages/web/src/viewer/components/sidecar-tool-names.ts), which tests for the \"[error] \" prefix. Only llm-client's Claude stream-json content-block parser writes that prefix (packages/llm-client/src/vendor-session-driver.ts:304, from `is_error`). RuntimeEvent.toolResult (runtime-contract.ts:212) has no error field.\n\nFailure scenarios:\n1. A Codex Sidecar session's call fails, or the broker refuses it. The Codex parse paths (`function_call_output`, the command_execution item) never set the prefix, so the pill reads Done.\n2. A Claude Bash call exits 0 and its output starts with \"[error] \". The pill reads Failed.\n\nReachability: the Sidecar drawer transcript, for any Codex lens session (1) or any agent command whose stdout starts with that text (2).\n\nOptions:\n- A (recommended): add an optional `isError?: boolean` to RuntimeEvent.toolResult. Set it in the Claude parser from `is_error`, and in the Codex parser where the item carries a failed status or non-zero exit code. Carry it through hench's persisted frames (schema v1 + validate.ts) and the viewer's SidecarRuntimeEvent, and read it in the drawer. Keep the prefix in `output` for hench's existing consumers. Cost: a contract field across llm-client, hench and web, plus a test at each layer. Risk: low, because the field is additive.\n- B: keep the prefix and add it on the Codex paths too. This is cheaper, but it keeps the false positive in (2).\n\nOperator note (PR 2 of the Sidecar follow-up lane, 2026-11-06). Option A is chosen. Settled before the run:\n- The field is additive and optional: `isError?: boolean`. No schema version bump. Persisted frames without it must still validate. Hench run records and Sidecar transcripts are not declared surfaces in docs/architecture/public-surface.md, so the 0.9.0 soft freeze needs no release-note entry beyond the patch changesets.\n- Layers to touch:\n  - llm-client: `RuntimeEvent.toolResult` in packages/llm-client/src/runtime-contract.ts.\n  - Claude parsers in packages/llm-client/src/vendor-session-driver.ts: the content-block `tool_result` (around line 304, from `b.is_error === true`) and the top-level `tool_result` case (around line 428, from `event.is_error === true` when present).\n  - Codex parser, same file: the `item.completed` `command_execution` branch sets `isError: true` when `item.status === \"failed\"` or `item.exit_code` is a non-zero number. Leave `isError` off (not `false`) when the stream says nothing, so \"unknown\" stays distinguishable. `function_call_output` carries no status, so leave it unset. MCP tool-call items are not parsed yet (that is the Codex broker, change 31307b89, PR 3): do not add them here.\n  - hench: `PersistedRuntimeEvent.toolResult` in packages/hench/src/schema/v1.ts, the zod `toolResult` object in packages/hench/src/schema/validate.ts (`isError: z.boolean().optional()`), and `toPersistedEvent` in packages/hench/src/agent/lifecycle/cli-loop.ts, which copies toolResult field by field and must copy `isError` when defined.\n  - web: the Sidecar server stores the RuntimeEvent untouched (packages/web/src/server/sidecar/session-registry.ts), so only the viewer changes. Add `isError?: boolean` to `SidecarRuntimeEvent.toolResult` in packages/web/src/viewer/hooks/use-sidecar.ts. In packages/web/src/viewer/components/sidecar-drawer.ts (around line 189), decide failure from the flag.\n- Older-frame fallback: when `isError` is undefined, the drawer still reads the `[error] ` prefix through `toolResultIsError(output)`, so transcripts recorded before this change keep their status. When `isError` is defined it wins over the prefix. Put this decision in one helper in packages/web/src/viewer/components/sidecar-tool-names.ts, e.g. `toolResultFailed(result)`, and update the `toolResultIsError` doc comment.\n- Keep the `[error] ` prefix in `output` on the Claude path. hench's existing consumers read it.\n- Gateways: hench reaches `RuntimeEvent` through packages/hench/src/prd/llm-gateway.ts already, and the new field rides on that type. Add no gateway export. If an export cap fails, design the export away; never raise a cap.\n- Codex fixture: no checked-in fixture shows a failed item, and the Codex CLI is not installed on this machine. The real fixture packages/hench/tests/fixtures/codex-file-change-real.jsonl shows the shape: `{\"type\":\"item.completed\",\"item\":{\"type\":\"command_execution\",\"command\":…,\"aggregated_output\":…,\"exit_code\":0,\"status\":\"completed\"}}`. Write a failed variant in the llm-client parser test (`exit_code` 1, `status` \"failed\") and add a comment there saying it is modelled on that fixture, not captured from a live CLI.\n- Tests per layer: an llm-client parser test (Codex failed and successful items; Claude `is_error` true and false), a hench test (toPersistedEvent copies `isError`, and validate accepts frames with and without it), and a viewer test for the drawer pill (the three criteria plus the fallback).\n- Changesets: one scoped `patch` changeset each for `@n-dx/llm-client`, `@n-dx/hench` and `@n-dx/web`."
