The ndx-sidecar broker becomes an MCP client to servers the operator adds (streamable HTTP or stdio; auth none, a stored bearer token, or an MCP OAuth sign-in) and re-exposes their tools to the session under the server's namespace, each with a read/write class and a run/ask/never policy, external writes deciding on a form card built from the tool's input schema. Decided 2026-11-04: connections come from .n-dx.local.json until the Settings page (C2, story 47); the gateway lives in the project server and the hub reaches it over HTTP (C2); web reads the credential store directly through one module, no gateway; the gateway is vendor-neutral behind the broker, so Codex is covered by the broker's MCP surface and verified without the CLI; OAuth redirects land on a dashboard page that finishes the sign-in through an authenticated route (no new public route); CN5 (a Rex ID property in CAOS) stays out of scope.\n\nShared rules for every C1 task (Sidecar design §14, decided CN1-CN6; C1 decisions 2026-11-04):\n- Connections are declared only in the untracked .n-dx.local.json under `connections` (id -> { transport: \"http\" | \"stdio\", url | command+args+env, auth: \"none\" | \"token\" | \"oauth\", label? }). A `connections` block in the tracked .n-dx.json is ignored with one warning: a cloned repository must never choose a command to spawn or the URL a stored token is sent to. Ids match ^[a-z][a-z0-9-]{0,30}$. Config never holds a secret.\n- Tokens live only in the per-user credential store (@n-dx/llm-client: resolveCredential/storedCredential/setCredential/unsetCredential/credentialStatus/credentialFingerprint, already in its public API) under the reserved entry name `connection:<id>`. Every store read and write in the web package sits in one module, packages/web/src/server/connections/connection-credentials.ts. No gateway, no new llm-client export, no ceiling change in tests/integration/cross-package-contracts.test.js or tests/e2e/architecture-policy.test.js.\n- token and oauth auth are HTTP-only (MCP authorization is HTTP-only). A stdio server gets auth none, and its env is the sanitized child environment (sanitizeChildEnv / the SDK's default environment), plus only the literal env its config names, never process.env and never a token. Spawn it through the SDK's StdioClientTransport, as packages/web/src/server/mcp-subprocess-proxy.ts does; web has no node:child_process.\n- Nothing in the gateway is tracker-specific: no CAOS name, tool or status appears in packages/web/src/server/connections/ or the broker.\n- Tests use a temp ndx home (NDX_HOME / homeDir), an in-process fake MCP server (read and write tools, one annotated readOnlyHint, one destructiveHint, one unannotated) and, for OAuth, a fake authorization server. Never the real ~/.ndx, never CAOS or any network host.\n- Never print, log or persist a credential value outside the store; logs and API responses carry credentialFingerprint at most.\n- Do not edit packages/web/AGENTS.md or packages/web/src/server/AGENTS.md (Codex size budget); put reasoning in docs/architecture/sidecar-connections.md.\n- Use resolveNdxHome / resolveLayout; no hand-spelled .ndx/.rex/.hench paths. Viewer code opens sockets through openWebSocket() and reaches messaging only through src/viewer/external.ts and src/viewer/api.ts. Nothing turns on web.sidecar."
