description: "Two defects in packages/lang-php/src/php-outbound.ts, found by `sv analyze` on the oscommerce2/catalog corpus app (operator check after task 5f583e76).\n\n1. getenv skips the request-key filter. `envKey()` applies `isRequestKey` only to `$_SERVER`, so `getenv('HTTPS')`, `getenv('REQUEST_URI')`, `getenv('PATH_INFO')`, `getenv('HTTP_USER_AGENT')` are reported as env calls. Under CGI and Apache, getenv returns these request meta-variables. The PHP manual's own getenv example is `getenv('REMOTE_ADDR')` (https://www.php.net/manual/en/function.getenv.php). Apply `isRequestKey` to getenv keys too. Also treat mod_ssl's per-request `SSL_*` variables (e.g. SSL_SESSION_ID; https://httpd.apache.org/docs/2.4/mod/mod_ssl.html#envvars) as request keys, for both $_SERVER and getenv. $_ENV keeps every key.\n\n2. A partial literal target. oscommerce2 `includes/functions/database.php`: `function tep_db_connect($server = DB_SERVER, …) { if (USE_PCONNECT == 'true') { $server = 'p:' . $server; } $$link = mysqli_connect($server, …); }` reports mysqli target \"p:\" with targetSource literal. A concatenation whose operands are not all computable must not be `literal` with its computable part; it is `unknown` (or, when the non-computable part is an env read or config key, what the HTTP task's grading gives). Separately, mysqli's persistent-connection prefix `p:` on a host (https://www.php.net/manual/en/mysqli.persistconns.php) is stripped from a computable target: `mysqli_connect('p:db.internal')` and `new mysqli('p:db.internal')` give `db.internal`.\n\nFixtures: add cases to tests/fixtures/php-outbound/ (getenv request keys including SSL_SESSION_ID, and a getenv of a real env var still reported) and tests/fixtures/php-data-access/ (the tep_db_connect shape with a parameter default and the p: prefix, plus a literal 'p:host').\n\nOperator note: touch only packages/lang-php (src, tests, fixtures; update AGENTS.md's Outbound calls line if the rules change) plus a patch changeset for @n-dx/lang-php. Non-PHP output stays byte-identical. Before finishing, run the six static root policy tests: tests/e2e/architecture-policy.test.js, domain-isolation.test.js, shell-spawn-inventory-policy.test.js, wall-clock-inventory-policy.test.js, layout-literal-policy.test.js, obfuscated-code-policy.test.js."
