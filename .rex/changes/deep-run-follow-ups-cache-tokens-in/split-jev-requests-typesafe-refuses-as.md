title: "Split Jev requests TypeSafe refuses as too large into smaller requests"

summary: "On a large repository some judgment requests exceed what the judging service accepts, and every finding in them loses its judgment. Send such a request again as several smaller ones so everything still gets judged."
description: "TypeSafe answers an oversized request with a non-retryable 400 whose body carries `{\"detail\":{\"error_type\":\"max_tokens_exceeded\"}}`. llm-client's `askJev` throws it as `ClaudeClientError(reason \"unknown\", retryable false)`, with the body in the message. Batch sizes are counts (TYPED_PER_REQUEST 20 findings in `typed-findings.ts`, LLM_BATCH_SIZE 30 files in `classify.ts`), so on a large estate one request outgrows the limit. Retrying it unchanged fails again. What goes in for one item is already capped (zone evidence: 40 files, 2,500 header characters, 40 declarations, 30 symbols; 12 edges per finding), so splitting by item is enough. Do not split one item's evidence across requests.\n\nDesign:\n- New `packages/sourcevision/src/analyzers/jev-split.ts`, with two consumers (classify.ts, typed-findings.ts), which satisfies the two-consumer rule:\n  - `isJevTooLarge(err)`: a `ClaudeClientError` whose message includes `max_tokens_exceeded`. Keep this in sourcevision, not llm-client: adding an `ErrorReason` would change llm-client's public surface during the soft freeze.\n  - `askSplittingWhenTooLarge<T>(items, ask: (slice, offset) => Promise<void>): Promise<T[]>`. It works through a queue of [start, end) ranges. When `ask` throws too-large, it halves the range (`mid = start + ceil(len/2)`) and puts both halves at the front in order. A lone item still too large goes into the returned list. Any other error propagates.\n- `typed-findings.ts` `judgeTypedFindings`: move the per-slice request and answer handling into an `askSlice(slice, start)` closure, and call it through the helper for each TYPED_PER_REQUEST chunk. Any other `ClaudeClientError` keeps today's behaviour: warn \"typed-finding judgment failed … keeping derived severities\" and stop. Warn once with the count of findings too large alone. Count `judged` (findings with a noul answer) and make the summary line say `typed findings: ${judged}${judged === typed.length ? \"\" : ` of ${typed.length}`} judged in N request(s)` and `outside/judged`.\n- `classify.ts` `classifyBatchWithJev`: move the request-and-parse body into `askJevForFiles(files, archetypes, projectLanguages, tokenUsage)`, which throws what askJev throws. Run it through the helper and merge results and escalations across slices. On another error, return what the earlier slices produced (null if none), with the same auth handling and warnings as today. Warn when files were too large alone and leave them unclassified.\n\nTests (invented data, askJev mocked):\n- typed-findings: 5 findings, where the mock refuses any request of more than 2 findings and any request containing one named finding. Expect 3 calls, 4 judged, the named finding keeps its derived severity, the too-large warning, and the log line \"typed findings: 4 of 5 judged in 3 request(s)\". Also: any other 400 stops after one call with nothing judged.\n- classify: a batch the mock refuses above N files gets every file answered across the split requests.\n- jev-split unit tests: ordering and offsets, a lone item left over, and another error propagating.\n\nChangeset: patch `@n-dx/sourcevision`."
