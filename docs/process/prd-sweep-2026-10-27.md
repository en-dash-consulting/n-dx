# PRD sweep, 2026-10-27 — record and continuation plan

This page is two things: the record of a sweep that picked up Codex's
`ndx work` run and worked the open PRD, and the plan for an autonomous run on
another machine to finish what is left. The run follows the plan on its own;
nothing here needs a person except the items marked **person**.

Every sweep branch is pushed to `origin` with **no pull request opened**. Each
is one task, named `work/<id8>-<slug>`, based on `origin/main` at `1c4c217dc`,
and its commit carries `N-DX-Item: <id>` (plus `N-DX-Status` when it completes
the task) and the task's completed status in its `state.yaml`.

Status keys: **done** (code, tests and PRD status on its branch), **merged**,
**covered** (another branch already does it), **verify** (code done; a check
the sweep's sandbox could not run is outstanding), **shipped?** (looks
shipped on main with a stale PRD record — confirm, then record), **blocked**,
**person** (needs a human), **open** (not started).

## How the continuation run works

Per item, in the order of the plan below:

1. **Check before building.** If the item is already met on `main`, record it
   instead of redoing it: `rex update <id> --status=completed .` on a
   reconcile branch, with the shipping commit in the commit body and the
   `N-DX-Item` / `N-DX-Status` trailers. Several Inbox items are in this state.
2. **Place Inbox changes first.** `ndx work` refuses an Inbox task
   (`not-actionable: … is in the Inbox and needs placement`). Place the
   change with `rex change place <change-id> --target=<capability-id>
   --relation=<amends|realizes|…>` (MCP `place_change`; the `/ndx-reshape`
   skill helps choose the capability), then run its tasks.
3. **Run the task:** `ndx work --task=<task-id> --review .` (one branch per
   task, `work/<id8>-<slug>`, off current `main`). `--review` runs the
   adversarial pass after the task validates and fixes must-fix findings
   in-session.
4. **After each big item or group** (the CodeQL follow-ups, a language pack's
   batch, the rex migration items, the docs rewrite): run the
   `/ndx-adversarial-review` skill on the group's branches, fix every
   **must-fix and should-fix** finding on the same branches, capture the rest
   to the PRD, then move on.
5. Keep this page current: change the item's status and branch as you go.

Before running anything: `pnpm install && pnpm build`, a configured vendor
(`ndx config llm.vendor …`), and a clean tree (autonomous runs refuse a dirty
one). `tests/e2e/cli-dev.test.js` and `tests/integration/scheduler-startup.test.js`
are required on every change (TESTING.md); changesets are `patch` with scoped
names.
