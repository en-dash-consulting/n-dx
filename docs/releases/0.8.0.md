# n-dx 0.8.0 — Find your way

All six packages move `0.7.2 → 0.8.0`.

**Status:** the release lane is complete; three gate items remain — see
[Release gate](#release-gate).

## What changed

### One container for project state

State lived in three root dot-directories (`.rex/`, `.hench/`, `.sourcevision/`)
and five loose `.n-dx*` files. 0.8.0 introduces a single `.ndx/` container and
one resolver, `resolveLayout` in `@n-dx/llm-client`, that decides which layout a
project is on: a `.ndx/` directory selects the new one, its absence the legacy
one. An un-migrated project is not misconfigured and nothing warns.

- `ndx init` writes the `.ndx/` layout for new projects.
- `ndx migrate-layout` moves an existing project when the operator chooses:
  snapshot, `git mv` the tracked paths so history follows, move the untracked
  state, rewrite the `.gitignore`/`.gitattributes` blocks, verify — or restore.
- The per-user directory becomes `~/.ndx/` with `NDX_HOME` as the override;
  `~/.n-dx/` and `N_DX_HOME` are still read as fallbacks.
- `.mcp.json` stays at the repository root (the vendor CLIs read it there) and
  task claims stay in the git common directory.

### One navigation model, three settings pages

Dashboard views are now stages, with tabbed Terrain and Architecture sections
and a next-step panel on Home. Scattered settings views were consolidated onto a
shared frame with an explicit Save, an unsaved-changes indicator and a leave
prompt:

| Page | Replaces |
|---|---|
| **Robot Wrangler** (`/robot-wrangler`) | LLM Provider |
| **Workflow** (`/workflow`) | work settings, CLI timeouts, templates |
| **Project** (`/project`) | analyze/plan settings, feature flags, Notion, integrations |

Robot Wrangler reports what `ndx work` will actually run — vendor, provider,
model, and which setting supplied it — and says why when that combination would
be refused. Model fields are dropdowns over a live catalog read from the
vendor's models API when a key resolves, with a built-in fallback otherwise; the
page names the source and the installed CLI version.

The breadcrumb links back to the hub and, with two or more projects registered,
switches between them. The hub chooser has a stable address at `/hub`.

### Per-vendor agent models

`hench.model` is deprecated and ignored. `ndx work` resolves its model from
`--model`, then `hench.models.<vendor>`, then the `llm.*` fields.

### Claude settings resolve per field

The legacy top-level `claude.*` keys now resolve against `llm.claude.*` one
field at a time, through a single implementation shared by the CLI, the
dashboard and the footer. The fallback used to be block-level, so a modern
`llm.claude` block holding one field discarded every legacy field beside it — a
project that set `claude.api_key` once and later pinned `llm.claude.model`
silently lost the key. Writes go to `llm.claude.*` only; existing `claude.*`
values stay where they are and are still read until 1.0.0.

### Command transparency

Interactive `analyze`, `plan` and `recommend` print a preflight banner saying
what the command will read, write and spend before it starts — with a pause the
operator can shorten (`NDX_PREFLIGHT_PAUSE_MS`) or skip (`--yes`) — and a run
summary afterwards: files written, calls, tokens, cost. Cost appears only when
it is known; an unpriced model or a provider that reported no usage shows "not
recorded" rather than `$0.00`.

### PRD storage

`rex tree-diff --json` diffs two PRD trees; `rex ready` marks items ready when
they have an automated or metric requirement and no open blocker; items carry an
assignee and `ndx work --mine` respects it. Whole-tree PRD rewrites are refused
off the default branch without `--allow-on-branch`.

## New configuration keys

Four keys are new — absent from the 0.7.2 schema, not merely unlisted:

| Key | What it does |
|---|---|
| `hench.models.<vendor>` | Agent-only model for `claude`, `codex`, `google` or `local`. Set in `.n-dx.json` (`.ndx/config.json` on the new layout) or from Robot Wrangler, not through `hench config`. |
| `hench.batchMaxAgeHours` | How old a batch session may get before it is retired. |
| `hench.batchMaxIdleHours` | How long a batch session may sit idle before it is retired. |
| `hench.guard.memoryMonitor.spawnThreshold` | Memory headroom below which the guard stops spawning. |

`hench.model` still parses, so existing configs keep loading, but it is ignored.

A further 32 keys became *visible* without becoming new: `hench config` listed
21 at 0.7.2 and lists 56 now. The schema already accepted them — they worked if
you hand-edited the config file, and were invisible if you did not.

## Redirects

Every path merged into a stage stays a registered view and redirects to it. The
table lives in `packages/web/src/shared/view-routing.ts` as `VIEW_ALIASES`.

| Old path | Redirects to |
|---|---|
| `overview` | `analyze` |
| `rex-dashboard` | `work` |
| `llm-provider` | `robot-wrangler` |
| `hench-config`, `cli-timeouts`, `hench-templates` | `workflow` |
| `project-settings`, `feature-toggles`, `notion-config`, `integrations` | `project` |

An alias fires only when its target is valid for that viewer: a rex-scoped
standalone viewer has no `work` stage, so `rex-dashboard` keeps rendering as its
own page there rather than redirecting nowhere.
