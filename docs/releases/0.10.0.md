# n-dx 0.10.0

The PRD separates what the product does from the work that changes it. The **product layer** holds areas, capabilities and constraints; the **change layer** holds changes, tasks and subtasks. Capability criteria describe standing requirements. Acceptance criteria describe when a change or task is done.

New projects created with `ndx init` use v2. Existing v1 projects keep working until you migrate them. Run `ndx migrate` in your project to review the migration plan, resolve the choices it flags, and apply the approved conversion. Keep the resulting product and change files under version control. See [PRD storage](../guide/prd-storage) and [Changes and apply](../guide/concepts/changes-and-apply) for the layout and lifecycle.

The dashboard's **Product** page shows capabilities, their status and health. **Changes** shows work grouped by release and stage. **Inbox** holds changes awaiting placement; place a change against the capability it affects before starting work. V1 projects continue to show their existing PRD tree until migration.

This release continues the soft freeze introduced in 0.9.0. The [public surface contract](../architecture/public-surface) names the CLI, MCP, configuration and schema surfaces covered by it. Experimental surfaces remain changeable; 0.10.0 does not announce the 1.0.0 freeze.
