### Claude-specific guidance files

Claude Code loads a package's own `CLAUDE.md` when work happens under that directory — `packages/web/CLAUDE.md`, `packages/rex/CLAUDE.md`, `packages/hench/CLAUDE.md`, `packages/core/CLAUDE.md`, `packages/llm-client/CLAUDE.md`. Each is a one-line `@AGENTS.md` import; the guidance itself is in the sibling `AGENTS.md`, so edit it there.

`.claude/rules/` narrows a package's guidance to the directory you are editing (`packages/core/**`, `packages/web/src/server/**`, `packages/web/src/viewer/**`). Only Claude Code reads it, so it is for pointers, not content: do not add a registry or a policy table here, because it would be invisible to every other assistant. Each of its files is frontmatter plus a short pointer naming the `packages/<pkg>/AGENTS.md` section that holds the real content, which the package's `CLAUDE.md` already imports. `tests/e2e/instruction-alignment.test.js` fails any file in that directory — whatever its name — that carries a table row, names no `AGENTS.md`, points at a section that does not exist, or tells authors to add another rule file.
