## lang-python

`@n-dx/lang-python` is the Python pack: the pinned tree-sitter-python grammar, `queries/python`, the pack definition and its symbol rules, the Python resolver and the Python goldens. It is opt-in (`ndx sv pack add python`): without it, Python files get inventory only.

### Rules

- **Imports only `@n-dx/lang-kit` and `@n-dx/lang-runtime` from n-dx.** No pack imports another pack.
- **Loaded, never imported.** sourcevision finds this package at run time (`src/language/pack-loader.ts`: the per-user pack directory, then module resolution) and imports it dynamically; nothing in a package's `src` imports it statically. Its version must equal sourcevision's, or sourcevision refuses it.
- **Returns facts.** `pack` (`src/pack.ts`) is a lang-kit `LanguagePackEntry` built with lang-runtime's `createPackEntry`, and it is the only export sourcevision reads; no tree-sitter type crosses into sourcevision. Other exports serve the corpus scripts in `packages/sourcevision/scripts` and tests in the workspace.
- **Finds its assets from its own root** (`src/package-paths.ts`): the grammar in `build/grammars`, queries in `queries/python`, each framework's query in `queries/<framework>`.
- **No language SDK at run time.** Grammars ship prebuilt as WASM; nothing here may require a Python interpreter or toolchain on the user's machine. Build files (`pyproject.toml`, `setup.cfg`, requirements) are read as text, and `setup.py` is never executed.
- **One public entry**, `.` (`src/index.ts`). There is no `./dist/*` escape hatch.

### What it reads

- **Imports** (`src/python-imports.ts`, `queries/python/imports.scm` and `guards.scm`): one lang-kit `WrittenImport` per imported module, in `FileReferences.written`: the specifier with its leading dots (`..pkg`), the names (`*` for a wildcard, none for `import a.b`), the specifier's position, and `guard` (`type-checking` under `if TYPE_CHECKING:` or `if typing.TYPE_CHECKING:`, `optional` in a `try:` body whose handler catches `ImportError` or `ModuleNotFoundError`; the innermost guard wins). `from __future__` is never listed.
- **Resolution** (`src/python-resolver.ts`): `pythonResolver.forProject(projectDir, files)` reads lang-kit's Python projects from the directories holding the pack's files; a file resolves against its own project's source roots, then its project directory, then the other projects' roots (the repository root when there is no project). A module is a package (`__init__.py`), a module (`.py`, else a lone `.pyi`) or a namespace directory, in that order; `from a import b` targets submodule `a/b` when it exists, otherwise `a` with symbol `b`. A relative import past its source root is unresolved with a notice; a missing module below a project namespace package is external. Externals are named `python:<top-level module>`, so they never merge with another pack's of the same name (npm `openai`, Go's `stdlib:os`): `python:stdlib:<name>` from the pinned Python 3.13 list (`src/python-stdlib.ts`), otherwise `python:<name>`, matched to a declared dependency by PEP 503 name only. A target reached only under `TYPE_CHECKING` is `typeOnly`. An import of a namespace package itself gives no edge. `preparePythonImports(...).outcomes(path)` says what each import resolved to, for `packages/sourcevision/scripts/python-resolve-report.mjs`; `.module(path, specifier)` is the file a module name (relative or absolute, as an import in that file would write it) resolves to, for the framework packs.
- **Symbols** (`src/python-symbols.ts`): `class`, `function` (sync and async), `method` (a function whose nearest enclosing class or function is a class), `variable` (a name assigned directly at module level; tuple targets are not). `decorators` holds each decorator as written without `@`, and the span then starts at the first one. `__all__` carries `exports` only when its value is a list or tuple of plain string literals.
- **Calls** (`queries/python/calls.scm`): callee and receiver as written, positional string literals (f-strings are not literals).
- **Notices** (`src/python-notices.ts`): `importlib.import_module(…)`, `import_module(…)` and `__import__(…)` are counted, with the first five locations, when imports are wanted; they never become import facts.
- **Routes** come from three framework packs (lang-runtime's `FrameworkPack`): `src/fastapi.ts`, `src/flask.ts`, `src/django.ts`, provenance per rule, each with its own query (`queries/<framework>/<framework>.scm`) that runs in the Python parse only when `routes` is asked for; none is in `pythonPack.queries`, so the Python golden and corpus reports do not see them. They read the Python queries' `calls`, `definitions` and `imports` captures beside their own, through `src/python-web.ts` (literals, the `${expression}` form, path joins, following a name into another file); FastAPI and Flask share `src/python-routers.ts`. A reference into another file is followed through the framework context (the prepared resolver's `module`): `include_router(items.router)`, `register_blueprint(bp)` imported from elsewhere, re-exports, Django's `include("app.urls")`. `from pkg import name` follows what `pkg/__init__.py` binds to `name` (so a re-export of `pkg/name.py`'s router is followed), and names the submodule `pkg/name.py` only when `__init__.py` binds nothing by that name; the same holds for the base of a dotted name (`endpoints.router` after `from app.api import endpoints`, where `app/api/__init__.py` has `from .v1 import routes as endpoints`) and a Django `include(module)`. An imported name bound again at module level after its import (an assignment `variables.scm` captures, a `def` or a `class`; one inside a function, or under a module-level `if` or `try`, is not seen) is not followed through the import.
  - Each framework's rules (decorators and constructors, prefixes, includes and mounts, Django's URLconf walk) are listed with their provenance in its module comment (`src/fastapi.ts`, `src/flask.ts`, `src/django.ts`); keep them there.
  - A route on a name no constructor binds is not one; a router no mount reaches keeps its own prefix; a mount whose receiver is unknown (a subclass, a factory's result) mounts at the root; a router mounted twice gets both paths. Prefix and path are joined with exactly one slash and keep a trailing slash (`src/python-web.ts` `joinWebPath`); the result starts with `/` unless it starts with `${` or `^`.
  - Notices: a path or prefix that is not a literal is kept as written in `${expression}` form (`${settings.API_V1_STR}/items/`, an f-string's fields too) and counted; a `methods` value that is not a literal is skipped and counted; a mount or `include()` the rules cannot follow is counted; Django REST framework `router.register(…)` calls (on a name bound to a `…Router(…)`, in the file or imported from another) are counted, not expanded. Out of scope: aiohttp and Starlette route tables, `add_url_rule`/`add_api_route`, class-level `url` attributes (Home Assistant views), GraphQL, websockets, Django's removed `url()`.

- **Outbound calls** come from the `python-clients` framework pack (`src/python-clients.ts`, query `queries/python-clients/python-clients.scm`, run only when `outboundCalls` is asked for), provenance per rule, read through `src/python-web.ts` like the route rules. http: `requests` and `httpx` module functions (`get/post/put/patch/delete/head/options`, `request(method, url)`) and the same methods on `requests.Session()`, `httpx.Client()`/`AsyncClient()` and `aiohttp.ClientSession()`; `urllib.request.urlopen(url)` and `Request(url)` (an `urlopen` of a `Request` is reported once, at the `Request`). grpc: `grpc.insecure_channel`/`secure_channel` and their `grpc.aio` forms. queue: confluent_kafka `Producer.produce(topic)` and `Consumer.subscribe([topics])`, kafka-python `KafkaProducer.send(topic)`, `KafkaConsumer(*topics)` and `.subscribe(topics)` (one call per topic), pika `basic_publish` (the routing key on the default exchange `""`, else the exchange) and `basic_consume(queue)` on a channel from `pika.BlockingConnection(…).channel()`, Celery `send_task(name)`. env: `os.environ["X"]`, `os.environ.get("X")`, `os.getenv("X")`; a write or `del` of `os.environ["X"]` is not a lookup.
  - Targets: a string literal is `literal`; an env lookup is `env` with its key; `settings.X` is `config` with key `X`; an f-string or `+` concatenation takes its first part's source and value (`f"https://h/{id}"` is literal `https://h/`); anything else, an empty literal included, is `unknown` with target `""`.
  - Confidence: `certain` when the callee is reached through an import of its module (aliases included) that the call's function does not rebind, or the receiver's name is bound only to one client constructor (an assignment or a `with … as` target) in the scope Python resolves it to (any binding, a parameter included, makes a name local; `global`, `nonlocal`, lambdas and comprehensions honoured); `likely` only for `basic_publish`, `basic_consume` and `send_task` on a receiver that is not known (`produce` and `send` are unshared but too common elsewhere to grade). A call with no argument is not reported. Callees are matched by name, so a function imported under another name (`from requests import get as fetch`) is not read. Out of scope: database and cache clients, boto3 and cloud SDKs, Home Assistant's `async_get_clientsession(hass)` sessions (their verbs are shared by every HTTP client).

tree-sitter-python 0.25.0 does not parse PEP 696 type parameter defaults (`class C[T = int]`); such files parse with ERROR nodes.

### Scripts

`build:grammars` builds the grammar into `build/grammars` (CI and release run every package's before tests and publish); the grammar tests skip without it unless `SV_REQUIRE_GRAMMARS=1`. `test:update-goldens` rewrites the fixture's capture golden (`golden.json`, with the resolver's written imports) and the pack entry's facts and notices (`facts.json`) under `tests/fixtures/language-packs/python`, each framework's routes and notices (`tests/fixtures/<framework>/facts.json`) and the outbound calls of `tests/fixtures/python-clients/facts.json`; review the diff. `packages/sourcevision/scripts/python-corpus-clone.mjs` clones the pinned corpus (`python-corpus.json`); the `python-*-report.mjs` beside it, which measure the pack, resolver and rules over it, are listed in sourcevision's AGENTS.md.
