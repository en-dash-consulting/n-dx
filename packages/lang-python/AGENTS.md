## lang-python

`@n-dx/lang-python` is the Python pack: the pinned tree-sitter-python grammar, `queries/python`, the pack definition and its symbol rules, the Python resolver and the Python goldens. It is opt-in (`ndx sv pack add python`): without it, Python files get inventory only.

### Rules

- **Imports only `@n-dx/lang-kit` and `@n-dx/lang-runtime` from n-dx.** No pack imports another pack.
- **Loaded, never imported.** sourcevision finds this package at run time (`src/language/pack-loader.ts`: the per-user pack directory, then module resolution) and imports it dynamically; nothing in a package's `src` imports it statically. Its version must equal sourcevision's, or sourcevision refuses it.
- **Returns facts.** `pack` (`src/pack.ts`) is a lang-kit `LanguagePackEntry` built with lang-runtime's `createPackEntry`, and it is the only export sourcevision reads; no tree-sitter type crosses into sourcevision. Other exports serve the corpus scripts in `packages/sourcevision/scripts` and tests in the workspace.
- **Finds its assets from its own root** (`src/package-paths.ts`): the grammar in `build/grammars`, queries in `queries/python`, each framework's query in `queries/<framework>`.
- **No language SDK at run time.** Grammars ship prebuilt as WASM; nothing here may require a Python interpreter or toolchain on the user's machine. Build files (`pyproject.toml`, `setup.cfg`, requirements) are read as text, and `setup.py` is never executed.
- **One public entry**, `.` (`src/index.ts`). There is no `./dist/*` escape hatch.

### What it reads

- **Imports** (`src/python-imports.ts`, `queries/python/imports.scm` and `guards.scm`): one lang-kit `WrittenImport` per imported module, in `FileReferences.written`: the specifier with its leading dots (`..pkg`), the names (`*` for a wildcard, none for `import a.b`), the specifier's position, and `guard` (`type-checking` under `if TYPE_CHECKING:` or `if typing.TYPE_CHECKING:`, `optional` in a `try:` body whose handler catches `ImportError` or `ModuleNotFoundError`; the innermost guard wins). `from __future__` is never listed.
- **Resolution** (`src/python-resolver.ts`): `pythonResolver.forProject(projectDir, files)` reads lang-kit's Python projects from the directories holding the pack's files; a file resolves against its own project's source roots, then its project directory, then the other projects' roots (the repository root when there is no project). A module is a package (`__init__.py`), a module (`.py`, else a lone `.pyi`) or a namespace directory, in that order; `from a import b` targets submodule `a/b` when it exists, otherwise `a` with symbol `b`. A relative import past its source root is unresolved with a notice; a missing module below a project namespace package is external. Externals are named by top-level module: `stdlib:<name>` from the pinned Python 3.13 list (`src/python-stdlib.ts`), otherwise matched to a declared dependency by PEP 503 name only. A target reached only under `TYPE_CHECKING` is `typeOnly`. An import of a namespace package itself gives no edge. `preparePythonImports(...).outcomes(path)` says what each import resolved to, for `packages/sourcevision/scripts/python-resolve-report.mjs`; `.module(path, specifier)` is the file a module name (relative or absolute, as an import in that file would write it) resolves to, for the framework packs.
- **Symbols** (`src/python-symbols.ts`): `class`, `function` (sync and async), `method` (a function whose nearest enclosing class or function is a class), `variable` (a name assigned directly at module level; tuple targets are not). `decorators` holds each decorator as written without `@`, and the span then starts at the first one. `__all__` carries `exports` only when its value is a list or tuple of plain string literals.
- **Calls** (`queries/python/calls.scm`): callee and receiver as written, positional string literals (f-strings are not literals).
- **Notices** (`src/python-notices.ts`): `importlib.import_module(…)`, `import_module(…)` and `__import__(…)` are counted, with the first five locations, when imports are wanted; they never become import facts.
- **Routes** come from three framework packs (lang-runtime's `FrameworkPack`): `src/fastapi.ts`, `src/flask.ts`, `src/django.ts`, provenance per rule, each with its own query (`queries/<framework>/<framework>.scm`) that runs in the Python parse only when `routes` is asked for; none is in `pythonPack.queries`, so the Python golden and corpus reports do not see them. They read the Python queries' `calls`, `definitions` and `imports` captures beside their own, through `src/python-web.ts` (literals, the `${expression}` form, path joins, following a name into another file); FastAPI and Flask share `src/python-routers.ts`. A reference into another file is followed through the framework context (the prepared resolver's `module`): `include_router(items.router)`, `register_blueprint(bp)` imported from elsewhere, re-exports, Django's `include("app.urls")`.
  - FastAPI: `@X.get/post/put/delete/patch/options/head(path)` and `@X.api_route(path, methods=[…])` (GET without) on a name bound to `FastAPI(…)` or `APIRouter(…)`; `APIRouter(prefix=…)`; `include_router(router, prefix=…)`, joined after the parent's prefixes and before the router's own; `mount(path, app)` of another `FastAPI(…)` app.
  - Flask: `@X.route(rule, methods=[…])` on `Flask(…)` or `Blueprint(…)`, GET without `methods` (Flask's default: the method is set, not absent), and `@X.get/post/put/delete/patch`; `Blueprint(…, url_prefix=…)`; `register_blueprint(bp, url_prefix=…)`, whose prefix replaces the blueprint's own; nested blueprints get the parent's prefixes first.
  - Django: `urlpatterns` (list, `+` of lists, `+=`) entries `path(route, view)` and `re_path(regex, view)`; `include(…)` of a dotted string, an imported module, a list or a `(patterns, app_name)` tuple, and a view `X.urls` (`admin.site.urls`), joined under the entry's route. Walking starts at the module a literal `ROOT_URLCONF` names, else at each module setting `urlpatterns` that no other includes. No method; the handler is the view's last name (`SiteListView` for `views.SiteListView.as_view()`), absent for other calls and lambdas. `re_path` regexes are kept as written.
  - A route on a name no constructor binds is not one; a router no mount reaches keeps its own prefix; a mount whose receiver is unknown (a subclass, a factory's result) mounts at the root; a router mounted twice gets both paths. Prefix and path are joined with exactly one slash and keep a trailing slash (`src/python-web.ts` `joinWebPath`); the result starts with `/` unless it starts with `${` or `^`.
  - Notices: a path or prefix that is not a literal is kept as written in `${expression}` form (`${settings.API_V1_STR}/items/`, an f-string's fields too) and counted; a `methods` value that is not a literal is skipped and counted; a mount or `include()` the rules cannot follow is counted; Django REST framework `router.register(…)` calls (on a name bound to a `…Router(…)`) are counted, not expanded. Out of scope: aiohttp and Starlette route tables, `add_url_rule`/`add_api_route`, class-level `url` attributes (Home Assistant views), GraphQL, websockets, Django's removed `url()`.

tree-sitter-python 0.25.0 does not parse PEP 696 type parameter defaults (`class C[T = int]`); such files parse with ERROR nodes.

### Scripts

`build:grammars` builds the grammar into `build/grammars` (CI and release run every package's before tests and publish); the grammar tests skip without it unless `SV_REQUIRE_GRAMMARS=1`. `test:update-goldens` rewrites the fixture's capture golden (`golden.json`, with the resolver's written imports) and the pack entry's facts and notices (`facts.json`) under `tests/fixtures/language-packs/python`, and each framework's routes and notices (`tests/fixtures/<framework>/facts.json`); review the diff. `packages/sourcevision/scripts/python-corpus-clone.mjs` and `python-corpus-report.mjs` clone and measure the pinned corpus (`python-corpus.json`); `python-resolve-report.mjs` measures resolution over it (internal and external rates, stdlib, unresolved by reason, a hand-check sample); `python-routes-report.mjs` the route rules (routes by framework and method, placeholder paths, notices, a seeded 15-route sample).
