## 0.10.0

### Patch Changes

- [#760](https://github.com/en-dash-consulting/n-dx/pull/760) [`24e4dba`](https://github.com/en-dash-consulting/n-dx/commit/24e4dba1b2278c4ed2d6309e7fa6a808c5f0ffb0) Thanks [@ryrykeith](https://github.com/ryrykeith)! - Add `@n-dx/lang-python`, the package for the opt-in Python language pack. It is empty for now; the grammar, structure queries and import resolver follow.

- [#760](https://github.com/en-dash-consulting/n-dx/pull/760) [`95acf33`](https://github.com/en-dash-consulting/n-dx/commit/95acf3361a0bd1d68cc73054c5d220a9e8d83dd6) Thanks [@ryrykeith](https://github.com/ryrykeith)! - The Python outbound-call rules follow Python's scoping when they decide a receiver is a client: a parameter or any other binding of a module-level client's name inside a function makes the call's receiver unknown rather than `certain`, `global` and `nonlocal` are honoured, lambdas and comprehensions are scopes, and a client bound in an enclosing function is now seen by the functions nested in it.

- [#760](https://github.com/en-dash-consulting/n-dx/pull/760) [`2db6705`](https://github.com/en-dash-consulting/n-dx/commit/2db670583b73e1c74c2e662df0d8c24d19bf36b3) Thanks [@ryrykeith](https://github.com/ryrykeith)! - The Python outbound-call and route rules no longer take quadratic time on a name followed by a long run of spaces in an env lookup, or on a route prefix with a long run of `/` followed by another character. Results are unchanged.

- [#760](https://github.com/en-dash-consulting/n-dx/pull/760) [`1bb77bf`](https://github.com/en-dash-consulting/n-dx/commit/1bb77bf3a8e6935295bcc59686fe79990f7a2a73) Thanks [@ryrykeith](https://github.com/ryrykeith)! - The Python pack resolves imports: absolute, from-import submodule or attribute, relative, src-layout and namespace-package imports become edges to project files across each project's source roots, so Python files join the import graph and zones, beside TypeScript in a mixed repository. Externals are named `python:<top-level module>`, so npm and PyPI packages of the same name stay apart; stdlib is `python:stdlib:<module>` from a pinned Python 3.13 list, and a third-party module is matched to a declared dependency by PEP 503 name only. A target imported only under `TYPE_CHECKING` is a `type` edge. Without the pack every artifact is unchanged.

- [#760](https://github.com/en-dash-consulting/n-dx/pull/760) [`22a8d63`](https://github.com/en-dash-consulting/n-dx/commit/22a8d632eb780c0ba39340970e990d84c934bc39) Thanks [@ryrykeith](https://github.com/ryrykeith)! - The Python pack produces `outboundCalls` through a python-clients framework pack, so a Python repository's outbound calls reach outbound.json: `requests`, `httpx` and `aiohttp` HTTP calls (module functions, sessions and clients, `async with` included), `urllib.request`, gRPC channels, confluent_kafka and kafka-python producers and consumers, pika `basic_publish`/`basic_consume`, Celery `send_task` and `os.environ`/`os.getenv` lookups. Targets are literal, env, `settings.X` config or unknown, and confidence is `certain` for an imported module or a bound client, `likely` only for `basic_publish`, `basic_consume` and `send_task` on an unknown receiver. Without the Python pack, or in a repository without Python, every artifact is unchanged.

- [#760](https://github.com/en-dash-consulting/n-dx/pull/760) [`bf141e2`](https://github.com/en-dash-consulting/n-dx/commit/bf141e29a91a42da1b2b6c184c291650f088ef92) Thanks [@ryrykeith](https://github.com/ryrykeith)! - The Python pack reads structure: the pinned tree-sitter-python 0.25.0 grammar, imports as written (relative dots kept, `TYPE_CHECKING` and `ImportError`-guarded imports marked, `from __future__` skipped), classes, functions, methods, decorators, module-level names and literal `__all__`, and calls; dynamic imports are counted in its notices. `ndx sv pack add python` installs it. Its imports are not resolved yet, so Python files still get no edges, and without the pack every artifact is unchanged.

- [#760](https://github.com/en-dash-consulting/n-dx/pull/760) [`049159f`](https://github.com/en-dash-consulting/n-dx/commit/049159f68262553326f892a4f72feb618caeca51) Thanks [@ryrykeith](https://github.com/ryrykeith)! - The FastAPI, Flask and Django rules now follow a module that a package's `__init__.py` re-exports under another name when it is the base of a dotted name or a Django `include(module)`. With `from .v1 import routes as endpoints` in `app/api/__init__.py`, `include_router(endpoints.router, prefix="/api")` gives `/api/x`, not `/x`. A name `__init__.py` binds to an object rather than a module is no longer taken as the submodule of the same name.

- [#760](https://github.com/en-dash-consulting/n-dx/pull/760) [`086e4b3`](https://github.com/en-dash-consulting/n-dx/commit/086e4b3cc789f0f3dfd20cb03c771980b4adf389) Thanks [@ryrykeith](https://github.com/ryrykeith)! - The FastAPI, Flask and Django rules now follow `from pkg import name` into what `pkg/__init__.py` binds to `name`, so a router or blueprint that `__init__.py` re-exports from `pkg/name.py` gets its mount prefix (`include_router(router, prefix="/api")` gives `/api/x`, not `/x`). The name is taken as the submodule only when `__init__.py` binds nothing by that name.

- [#760](https://github.com/en-dash-consulting/n-dx/pull/760) [`1ff9b98`](https://github.com/en-dash-consulting/n-dx/commit/1ff9b984f42eb62d46972f4d0d5d400b581627e5) Thanks [@ryrykeith](https://github.com/ryrykeith)! - The FastAPI, Flask and Django rules no longer follow an imported name that the file binds again at module level after the import (`from .routers import router` then `router = make_other()`): a mount through it is not followed, and a `router.register(…)` on it is not counted as a Django REST framework registration.

- [#760](https://github.com/en-dash-consulting/n-dx/pull/760) [`7e3cded`](https://github.com/en-dash-consulting/n-dx/commit/7e3cdedf02eb5ac2ef6daeaa11e02e20ef8c8725) Thanks [@ryrykeith](https://github.com/ryrykeith)! - The Python pack produces `routes` through FastAPI, Flask and Django framework packs, so a Python repository's routes reach components.json `serverRoutes`. FastAPI `include_router`, Flask `register_blueprint` and Django `include` are followed across files through the pack's resolver, which a framework now receives as an optional third argument to `FrameworkPack.read`. A prefix or path that is not a literal is kept as written in `${expression}` form and counted in a notice; Django REST framework router registrations are counted, not expanded. Without the Python pack, or in a repository without Python, every artifact is unchanged. Pairing call captures (lang-runtime's `callSites`, and the new `innermostEach`) is now n log n rather than quadratic in a file's size, so large files no longer take seconds per framework.
