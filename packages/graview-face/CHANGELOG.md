## 0.9.1

### Patch Changes

- [#647](https://github.com/en-dash-consulting/n-dx/pull/647) [`21b50b8`](https://github.com/en-dash-consulting/n-dx/commit/21b50b8cd794ad76f0df89533a2e97565cddda11) Thanks [@dnaniel](https://github.com/dnaniel)! - Graview 0.1.22 answered every ask the n-dx run filed, so both packages take it and drop the workarounds that stood in for it; the pins then move on to 0.1.26, which reads an MCP reply by its request's id (so the last workaround row closes), holds a deleted record against a remote edit as a conflict, and keeps a per-kind tally the face's counts read. The adapter writes the snapshot in Graview's line format (format 2: a header saying when it was made and what it holds, then a record a line), by its own writer held byte for byte to `@graview/core/snapshot`'s, and `emitProjection` takes `generatedAt`. The declaration names `$schema` for editor validation, declares `fieldRoles` on run and commit, a document-level fact `mapProposed` that the home reads with `fact()`, a `key` on every titled block the face claims, each kind's own wording of `under`, and sorts a change's tasks by `choices`. The hand-written document types give way to the format Graview publishes.
  
  The face pins `@graview/*` and `graview` at 0.1.26 and `pnpm doctor` holds them together. Its sync is `SyncEngine` from `@graview/core/sync` with `conflicts: "theirs"`, a `version` field on each synced resource and read-only resources with a `because` sentence, guarding the store; the hand pre-empt, the seeded links and the refusal table are gone. The dev door is `mcpDoor` over `mcpClient`, the page reaches it with `doorClient`, the remote is `mcpRemote`, and the snapshot is read with `fetchSnapshot` by byte range, two kinds at a time. Declared blocks resolve with `resolveFor` and are claimed by key; the store attributes acts to `rememberedPrincipal()`; the shell keeps the bar without its places; types are generated from the document with `graview types` and the models read through `typedReader`. `shots.mjs`, the fixture-drift test, the version-pin test and the fixture copy of the document are deleted in favour of `graview shots`, `graview doctor` and `compileDocumentFiles`.

- [#647](https://github.com/en-dash-consulting/n-dx/pull/647) [`e3ba73a`](https://github.com/en-dash-consulting/n-dx/commit/e3ba73af715f498b6dfc482647b18444e57ed7cb) Thanks [@dnaniel](https://github.com/dnaniel)! - New package `@n-dx/graview-face`: n-dx's face on Graview, a Vite + React product that compiles the document `ndx graview emit` writes, seeds a store from the snapshot, and lays a shell, home and record pages in n-dx's own words over the derived pages, with two-way sync to rex through a dev-server door. It is published on its own and no other `@n-dx/*` package depends on it, so installing n-dx never pulls Graview or React. `ndx graview serve .` finds it beside `@n-dx/graview` in the monorepo or in `node_modules` (or through `graview.app`) and runs its `bin/serve.js` on the fresh projection.

- [#647](https://github.com/en-dash-consulting/n-dx/pull/647) [`e6a3637`](https://github.com/en-dash-consulting/n-dx/commit/e6a363728757506a7454b05093802b56d465530a) Thanks [@dnaniel](https://github.com/dnaniel)! - The face's sync with rex holds to rex's answer. A write rex refuses is put back to rex's value and said once in the rail instead of being retried every run. Choosing `deleted` is refused rather than deleting the item and its children. A completion rex holds for a hench run is not logged as written. The dev-server door admits only the page it served, through a per-launch key, and skips the re-emit when nothing the projection reads has changed. `ndx graview info` and the serve hand-off name the port the running hub bound, which `ndx start --port` may have changed.

- [#647](https://github.com/en-dash-consulting/n-dx/pull/647) [`9667351`](https://github.com/en-dash-consulting/n-dx/commit/96673514addc91bf03a280b83bb895d9b0e4100b) Thanks [@dnaniel](https://github.com/dnaniel)! - `ndx graview emit` projects every source file by default (`--no-files` or `graview.includeFiles: false` leaves them out), and ties each one to the work: a commit to the files it changed (`changed`) and a capability to the files its realizing commits changed (`livesIn`), from the same commit-file read that already placed capabilities in zones. A capability's page lists the files it lives in, and a file's page lists its zone, the capabilities living there and the commits that changed it.

- [#647](https://github.com/en-dash-consulting/n-dx/pull/647) [`a4af06e`](https://github.com/en-dash-consulting/n-dx/commit/a4af06ec00bfd0fd8ed37bed21cf04885a99dc62) Thanks [@dnaniel](https://github.com/dnaniel)! - The v1-to-v2 migration plan marks a capability or constraint `met` when its v1 item completed, and the plan's data stage stamps `metAt` with the drafted spec's hash, as `appliedAt` already stamps a completed change: without it every migrated capability read proposed forever. `specHash` and `nodeSpec` join rex's public API. The Graview projection's proposed product layer stamps the same, so a completed feature's capability reads met, one with an open amending change reads changing, and the capability declaration drops its `metAt` datetime (rex's `metAt` is a spec hash, said through `intentStatus`).
  
  A run record's commits carry how each was tied to the run (`attribution`: `start-head` on the live path), and `hench backfill-commits [dir]` fills `commits` on every record written without `startHead`, from the main branch's history: a subject naming the run id, then an `N-DX-Item` trailer naming the run's task, then the run's time window when no other run's holds the commit (the window proper before the `--pad`, and never a window longer than `--max-window`, so a run an audit ended weeks later claims nothing). Merge and `chore(prd)` commits are never attributed; a record that has commits is left alone, so the command is idempotent; `--dry-run` reports without writing. On n-dx's own history it ties 638 commits to 569 of 673 runs.
  
  The projection reads that evidence: every commit a run record names is a `commit` node that `landedFor` the run's task, carrying the record's `attribution` (a trailer commit says `trailer`), with author and date from git. A capability is `realizedIn` the zones of the files changed by every commit that landed for a change placed on it, `amends` or `touches`, or for the work under that change, from trailers and run records alike; `loadCommitFiles` joins rex's public API for the file scan. The face's capability page, zone page and coverage picture fill in accordingly.
