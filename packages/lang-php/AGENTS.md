## lang-php

`@n-dx/lang-php` is the PHP pack: the pinned tree-sitter-php grammar and the pack definition. It is opt-in (`ndx sv pack add php`): without it, PHP files get inventory only and every analyze artifact is unchanged.

### Rules

- **Imports only `@n-dx/lang-kit` and `@n-dx/lang-runtime` from n-dx.** No pack imports another pack.
- **Loaded, never imported.** sourcevision finds this package at run time (`src/language/pack-loader.ts`: the per-user pack directory, then module resolution) and imports it dynamically; nothing in a package's `src` imports it statically. Its version must equal sourcevision's, or sourcevision refuses it.
- **Returns facts.** `pack` (`src/pack.ts`) is a lang-kit `LanguagePackEntry` built with lang-runtime's `createPackEntry`, and it is the only export sourcevision reads; no tree-sitter type crosses into sourcevision.
- **Finds its assets from its own root** (`src/package-paths.ts`): the grammar in `build/grammars`, queries in `queries/php`.
- **No PHP toolchain.** Grammars ship prebuilt as WASM; nothing here, in its tests or in its scripts may require a PHP interpreter, Composer or any PHP tool. PHP versions and syntax rules come from cited sources, never from memory.

### Grammar

`tree-sitter-php` 0.25.1, built from the release archive's `php/` grammar (PHP mixed with HTML, so `<?php … ?>` blocks between markup parse), not `php_only/`. The pin and its `subdir` live in `packages/lang-runtime/scripts/build-grammars.mjs`; `phpPack.grammar.version` must match it (`tests/unit/php-grammar-pin.test.ts`).

### What it reads

`produces` is `imports`, `symbols` and `calls`, from `queries/php/` (provenance per rule in `src/php-pack.ts`), `routes` from the `php-docroot` framework (`src/php-docroot.ts`, `queries/php-docroot/`), `entryPoints` from the `php-entry` framework (`src/php-entry-points.ts`, `queries/php-entry/`) and `outboundCalls` from the `php-outbound` framework (`src/php-outbound.ts`, `queries/php-outbound/`). Inline HTML is never captured.

- **Imports as written** (`src/php-imports.ts`): `FileReferences.written`, each with its `form` (the four include forms, `use`, `use function`, `use const`). An include's specifier is its path expression as written, quotes included (the parentheses of `require_once("x")` dropped); a `use` gives the qualified name (a group use's prefix joined to each entry) and any `alias`. An include inside a branch, `switch`, loop, function or method body, a short-circuit right operand, `?:` or `match` carries the `conditional` guard (`guards.scm`).
- **Includes** (`src/php-includes.ts`): a path built only from literals, `.`, `__DIR__`, `__FILE__`, `dirname(x[, n])`, `DIRECTORY_SEPARATOR` and constants the repository defines once (`define()`, file-level `const` outside a namespace; two different values is not computable) resolves to a pack file, symbol `*`; anything else gives no edge. Search: `__DIR__`/constant-anchored paths as named; `./` and `../` against the working directory; other relative paths under each include-path root, then the including file's directory. Working directory, tried in order: the including file's directory, its ancestors holding an `index.php` (entry scripts) nearest first, then the docroot (`src/php-docroots.ts`'s `primaryDocroot`: first `PHP_DOCROOT_DIRECTORIES` entry holding `index.php`, else the root). Roots: literal `set_include_path`/`ini_set('include_path', …)`, `.user.ini`/`.htaccess` (`php_value`) at or above the file nearest first, then any `php.ini`; default `.`; relative roots against the working directory; roots outside the repository are ignored with a notice. `preparePhpImports(...).includes(path)` gives each include's outcome. Fixture: `tests/fixtures/php-legacy-includes/`.
- **Dynamic includes** (a path not computable): no edge; counted with `file:line` in a `[php-dynamic-include]` notice, or `[php-host-include]` when the path reads `$_SERVER['HTTP_HOST']`/`['SERVER_NAME']`, itself or through a variable whose last assignment before the include, in its scope (`@guard.function` bodies, else the file; `src/php-assignments.ts`), reads it (`src/php-include-notices.ts`; `ResolvedPhpInclude.host`). The computable leading and trailing `.` operands (and an interpolated string's literal ends) give a prefix and suffix; pack files matching both, the prefix looked up as an include would be, fill `WrittenImport.candidates`, sorted, at most `MAX_INCLUDE_CANDIDATES` (50; the outcome keeps `total`). No prefix needs a suffix holding `/`; a leading `/` also matches at the repository root (`'/includes/x.inc'` → `includes/x.inc`). Candidates are never edges (`packages/sourcevision/tests/integration/php-pack-imports.test.ts`). Fixture: `tests/fixtures/php-dynamic-includes/`.
- **Resolution** (`src/php-resolver.ts`, class names from `queries/php/references.scm`): `use` imports and class references (`extends`, `implements`, trait `use`, `new`, `X::`, parameter/return/property/`catch` types, `instanceof`) are qualified as PHP does (per-namespace-block `use` aliases; `use function`/`use const` kept apart; `self`/`static`/`parent` dropped) and resolved through every Composer project's `autoload` and `autoload-dev` (lang-kit's `readComposerProjects`, read by `phpResolver.forProject`): PSR-4 longest prefix first, PSR-0, classmap (less `exclude-from-classmap`), then legacy loading, then a class declared in exactly one repository file (two or more and no pattern: `ambiguous`). Legacy loading (`src/php-autoloaders.ts`): the file an `__autoload` function or an `spl_autoload_register` closure, function or method callback would include, when an include in its body is computable from the class name (the parameter, body variables, `str_replace`/`strtr`/`strtolower`/`ltrim`…), then the PSR-0 path (`A_B_C` → `A/B/C.php`) under the referring file's include-path roots or the repository root; the file must declare the class, or be unparsed while nothing declares it. Any other autoloader or registration is a notice with its line. Fixture: `tests/fixtures/php-legacy-autoload/`. Unresolved, per D5: PHP's own and common PECL extensions' classes (`src/php-builtins.ts`, by manual book or PECL page), scalar type keywords in any case, and global functions and constants are nothing; a name a `composer.lock` package's autoload prefix covers is external with that package as `module`; a name that is the project's is unresolved — a namespaced name whose namespace (all but its last segment) the project declares or that a project PSR-4/PSR-0 prefix covers, an un-namespaced one whose PSR-0 prefix is the project's (`Zend_`), never a library merely sharing the root namespace (`Acme\Shared` beside `Acme\Billing`); any other is `php:<first namespace segment>` (`php:Zend` for `Zend_Db_Table`). Symbols are qualified names. `preparePhpImports(...).outcomes(path)` says what each reference resolved to, for `packages/sourcevision/scripts/php-resolve-report.mjs`. Fixture: `tests/fixtures/php-composer/`.
- **Symbols** (`src/php-symbols.ts`): class, interface, trait, enum, function, method, namespace (not a container) and constant (`const` elements, class constants, `define()` with a literal name). `__construct`, and a method named as its class in a class outside any namespace with no `__construct`, are constructors; functions and `define()` constants are never members.
- **Routes** (`src/php-docroot.ts`): docroots are `phpDocroots` (`src/php-docroots.ts`: each `PHP_DOCROOT_DIRECTORIES` directory holding `index.php`, any depth, not nested; else a root `index.php`). Each `.php`/`.phtml` file under one is a `GET` and `POST` route at its docroot-relative URL, `source` `docroot <dir>`, except `*.inc.php`, declaration-only fragments (top-level statements from `docroot.scm`) and files `.htaccess` denies (`src/php-htaccess.ts`: nearest `Deny from all`/`Require all denied` vs grant per directory, `<Files>`/`<FilesMatch>` denials, `RedirectMatch 403`). A `RewriteRule` to a literal `.php` target (not `R`/`F`/`G`/`P`; relative under `RewriteBase`) or `FallbackResource` is a catch-all route on its target, the pattern as written (`<dir URL>*` for `FallbackResource`), `source` `<.htaccess>:<line>`; a missing target is a notice. `.htaccess` text reaches the framework as the resolver's `configFiles`. Fixtures: `tests/fixtures/php-docroot-{flat,drupal7,public}/`.
- **Entry points** (`src/php-entry-points.ts`): `cli` for a `#!…php` shebang anywhere, or, under a `bin/`, `cli/`, `cron/`, `scripts/` or `jobs/` directory, a `PHP_SAPI`/`php_sapi_name()` comparison with `'cli'` or a `$argv`/`$_SERVER['argv']` read (`source` `shebang`, `PHP_SAPI check`, `$argv`). `cron` for each script a crontab-like file runs (`src/php-cron.ts`: `crontab`, `*.cron`, `cron.d/*`, found beside the PHP files and up to two directories below the root, a `cron.d/` one more; `php` options skipped, `-f` honoured; the script is the longest trailing part of its path that is a pack file), `source` `<crontab>:<line>`, `schedule` as written; a script that is no pack file is a notice. Crontab text joins `.htaccess` in the resolver's `configFiles`. Fixture: `tests/fixtures/php-entry-points/`.
- **Outbound calls** (`src/php-outbound.ts`, rules in its module comment), all `certain`: `http` from curl, `file_get_contents`/`fopen`/`file`/`get_headers` on an `http(s)://` value, `fsockopen`, `SoapClient` and Guzzle (methods only on a receiver bound to a client in its scope); `env` from `getenv`, `$_ENV` and `$_SERVER` less its request keys (`isRequestKey`), writes excluded. Targets computable as an include path are `literal`, env reads `env`, `$config['a']` (`CONFIG_NAMES`) `config`. Fixture: `tests/fixtures/php-outbound/`.
- **Calls**: function, method, nullsafe and static calls with the receiver or scope as written, and `new` (`construct: true`, the class as callee), with or without an argument list.

Goldens: `tests/fixtures/language-packs/php/` (`php52/`, `php53/`, `php8/`), updated with `test:update-goldens`.

### Scripts

`build:grammars` builds the grammar into `build/grammars` (CI and release run it before tests and publish); the grammar tests skip without it unless `SV_REQUIRE_GRAMMARS=1`.
