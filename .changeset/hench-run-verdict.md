New `hench runs diagnose <run-id> [--format=json]` explains why a run did not complete, using fixed rules and no model call. It names the class (test-gate-new, test-gate-preexisting, completion-held, review-blocked, claim-lost, budget-timeout, vendor-transient, no-changes or unclassified), the evidence behind it, the ranked next actions, and the attempt number out of 2. A run counts as completion-held when its completion was not applied (a completion that was applied or bypassed is not a hold), when it was a gate-only retry, or when the completion gate refused on uncommitted work. That refusal outranks every rule but a lost claim, and its first action is to commit or discard the uncommitted paths, then verify. claim-lost covers only a claim taken by another worktree. A read-only refusal (the forked attempt made no edits and the task re-ran cold) never sets the class; it is one evidence line on the class the retry's own record gives. test-gate-preexisting means the gate failed only in files the run did not change: with no baseline run, it says the failure is in tests the run did not edit and was not checked on main, never that it predates the run, and its only action is to run the failing tests on main. An absolute path in the test gate's failure digest is read relative to the run's worktree, so it matches the file the run changed. A file the digest names both package-relative and repo-relative is listed once in the summary and evidence, by its repo-relative path. On the second failed attempt it no longer suggests a re-run. Runs that end in any status other than completed store this verdict as `diagnosis` on the run record. The verdict's one-line summary becomes the task's `failureReason` when it has none, or when its current one is an earlier run's verdict, so the next brief names the latest cause; a reason a person or the agent wrote is kept.

A new experimental toggle, `hench.runVerdict` (off by default), adds a verdict banner at the top of a task's detail panel, above the description, when its latest run did not complete. The banner shows the class as a readable label (for example "Failure in tests the run did not edit"), the summary, the first next action and the attempt number.
