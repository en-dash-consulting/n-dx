Local-model runs no longer die on a slow turn or a malformed reply. Node's fetch waits at most 300 s for response headers, and LM Studio sends none for a non-streamed completion until generation finishes, so a slow model's turn failed with `UND_ERR_HEADERS_TIMEOUT` whatever `llm.local.timeoutMs` said — and the connection retries then resent the same slow request. Local completions (the provider's blocking path, and hench's local tool loop, context summarizer and verifier) are now requested with `stream: true` and `stream_options.include_usage`, so the headers arrive at once, and the server-sent chunks are assembled back into the non-streamed response — content and reasoning concatenated, tool calls merged by index, the finish reason and the usage chunk — so tool-call parsing and token accounting read the same shape as before. `llm.local.timeoutMs` still bounds the whole request (0 = no limit), and a connection dropped mid-stream is retried like a refused one. No new dependency. A 400/500 from the local server saying the model produced malformed output (LM Studio: "The model produced output that does not match the expected … format", and similar) — or the same error arriving inside the stream as an error event — is now resent up to the new `llm.local.maxFormatRetries` times (default 3; 0 disables), one log line per resend; ordinary 400s such as a context-length error, streamed or not, are not resent. When the resends run out the error says what happened and names the setting. `parseLmStudioError` reads LM Studio's string-valued `error`. `ndx config` validates and documents `llm.local.maxFormatRetries`, and the dashboard's Local server settings gain a Retries row for it and the three connection-retry settings.
