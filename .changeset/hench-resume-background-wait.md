Autonomous Claude CLI runs now finish their session when the agent ends it waiting on a background command. This closes the gap left by `foreground-invariant-autonomous-runs.md`: that change told the agent to run validation in the foreground, but it was prompt text only, and nothing enforced it. Bash's `run_in_background` is a parameter of an allowed tool, so a run could still background the suite, call `ScheduleWakeup` or `Monitor`, and end its turn waiting for a notification that never reaches a non-interactive session. The work was then left uncommitted and the completion gate reset the task, even though the test gate had passed.

hench now spots a backgrounded Bash call, `ScheduleWakeup` or `Monitor` in the session's stream. If the session ends that way with its work uncommitted, hench resumes it once with a message telling it to rerun the command in the foreground and finish. If it ends the same way a second time, the run fails with a message naming the cause, and hench does not spawn it again. The run record's new `backgroundResume` field names the call that triggered the resume. The adversarial reviewer gets the same treatment: a reviewer that ends waiting without writing its report, including one that inherited the wait from the work session it resumed, is resumed once to write the report from what it has. Both resumes apply to Claude CLI runs only. Detection and the permission to resume belong to the vendor adapter, and Codex runs are unchanged: `codex exec` has no known background tool, and a shell command backgrounded with `&` is not detected.

On attended runs, offered review findings now reach `hench review pending`. The reviewer is a headless session and could never receive the operator's selection, so its findings used to end `offered` and appear only in the run log. The reviewer is no longer told to wait for a selection. It reports `should-fix` and `out-of-scope` findings without capturing them, and the run queues them for the operator. Autonomous capture is unchanged.
